# UI40 原生改动与验证

本次从源码重编的只有 `padd` 与 `mediad`。UI39 的 `robotd`、模型、标定、总线、IMU 与推理参数应在最终安装包内逐字节保留；本目录的 `native-build.json` 给出了原始 robotd 的 SHA256，供打包时核对。

## 改动范围

- `padd`：在实际 HAT 语言音频播放期间，按一个短租约暂停其 `robot.mouth` 写入。租约不存在、关闭或过期时恢复官方每个手柄周期都发送嘴部状态的行为。没有增加 AI 嘴部角度生成、文字分字或 PCM 包络动画。
- 速度、转向、连续输入、UI39 的零速度心跳策略、其他按键和机器人主循环没有修改。特别是没有恢复旧版 100 ms 零速度心跳，也没有宣称解决物理 R3 的其他兼容问题。
- `mediad`：仅将拍摄版自动曝光目标亮度从 105 恢复到 90。720p15 是否启用由电脑端独立选项管理；曝光目标与帧率配置是两件事。

## 嘴部暂停协议

使用现有 `padd.service` 的可写运行目录 `/run/padd/ai-mouth`，不修改服务用户或 systemd 沙箱。目录由 `padd` 持有；root AI 工作进程也可创建该子目录并设置相同所有权。

每次播放使用一个独立的 32 位小写十六进制 token。`<token>.lease` 是 ASCII 格式的 Linux CLOCK_MONOTONIC 到期毫秒数，随后一个换行。AI 工作进程使用 750 ms 租期，播放期间每 200 ms 续约。`padd` 拒绝已经过期或超过未来 1500 ms 的请求；它只在开始暂停自身嘴部写入时，将同一个到期值写入 `<token>.ack`。

工作进程应在运行中的 padd 确认该租约后，才向 HAT 写入首段语言 PCM；没有 padd 进程时仍可播放。正常结束必须先排空音频，再释放本次租约。关闭、取消和异常路径均应清理自己的文件；进程意外退出后租约会自行到期。`padd` 在没有连接手柄的分支之前也检查租约，但沿用原本 500 ms 空闲轮询，没有新增轮询线程。

## 来源与复现

冻结源码为 `Microduck-Source-R17-V186-control57-compiled.tar.gz`，归档 SHA256 及所有补丁/修改文件哈希见 `native-build.json`。

实际复现链是：在冻结源码上先应用归档保留的 UI37 `native-input.patch` 和 UI38 `camera-source.patch`，形成 UI39 相应的原生源码，再应用本目录的 `native-mouth-camera.patch`。UI40 补丁是相对这一 UI39 原生源码生成的，因此不会把 UI37 的心跳改动表示成 UI40 新改动。共享协议源码沿用这两个历史原生构建的 API 40，不额外应用 UI22 的 robotd/共享协议更新，也不重编或替换 robotd。

编译使用 Rust 1.99.0、cargo-zigbuild 0.23.4、Zig 0.14.1，目标为 `aarch64-unknown-linux-gnu.2.31`。本次使用全新目标目录，没有复用其他固件的编译缓存。两个 ELF 均为 ARM64，自身所需 GLIBC 符号最高为 2.30；没有对 ELF 进行手工字节修改。
