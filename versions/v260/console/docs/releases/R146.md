# Microduck R17 v1.0.146 / 官方 0.15.1

本版用用户提供的 9600 轮行走＋倒地联合模型替换唯一的 Walk，删除旧 14000 轮行走模型。根据本次测试选择，新联合模型全程使用基础动作缩放 0.9、头部滤波 0.5、腿部滤波 0.7。原有 11000 轮 LB 独立起身老师及 v145 的倒地／卸力按 LB 入口继续保留。

## 安装与版本核对

关闭旧中控，完整解压 `Microduck-Console-R17-v1.0.146.zip`，Windows 运行 `start.cmd`，macOS 运行 `start.command`。连接 Zero 后，在原有“系统维护”中升级本版随包固件。安装完成后核对：

| 项目 | 本版标识 |
|---|---|
| 中控版本 | `1.0.146` |
| 运行固件 build | `1fa8438-feetech-ft6-control.29` |
| 配套 robotd、robotctl、padd | API40 |
| 唯一 Walk | 行走＋倒地联合 9600 轮，ID `1cbf8730eadd75a5704332c9f3c10f60` |
| LB 独立起身老师 | 11000 轮，ID `a481d9f211f31d9476ab1a319fe362a2` |

中控包已包含固件。独立 `Microduck-Firmware-R17-v1.0.146.zip` 是相同固件的单独打包，不需要重复安装。请安装配套固件，单独更新网页不能让旧 robotd 获得新的联合模型运行配置。

首次升级将 Walk 绑定到新联合模型，并安装它的独立运行配置；之前已手动导入同一联合模型的设备也会收到该配置。旧行走模型 `9e3ff8bde021be28a728c02dbd8e7aaf` 从随包模型、中控模型列表和升级后的模型目录移除。固件共带五个模型：新联合、LB 起身老师、起坐、捡取、前滚翻。自动 `Stand` 槽保持 `none`，LB 仍绑定 `stand_test`。

**无需恢复默认设置。** 已保存的全局动作系数、本机标定、其他动作绑定、LB 执行时长、音频设置，以及临时舵机测试 P／D／48 号转矩限制继续保留。重复安装同一版保留用户之后的有效模型选择和已保存参数。

## 本次联合模型的运行参数

| 联合模型正在执行的动作 | 基础动作缩放 | 头部低通系数 | 腿部低通系数 |
|---|---:|---:|---:|
| 行走 | 0.90 | 0.50 | 0.70 |
| 零速度保持 | 0.90 | 0.50 | 0.70 |
| 倒地恢复 | 0.90 | 0.50 | 0.70 |

同一张联合网络始终使用上述三个常量。没有新增姿态分档、倾角门限或恢复计时，也没有第二张 Walk 网络或第二次推理。表中“倒地恢复”指联合 Walk 策略正在运行时的模型动作；它不会让已卸力的机器人自行上力。

这些值采用本次查到的官方固件默认输出参数，并按用户选择用于这份自训练联合模型的实机试验。上传模型的原始训练设置实际为 1／1／1；其 ONNX、manifest、部署合同和训练记录保持原始内容，运行调整单独放在 `deployment-execution.json`。该文件绑定完整 ONNX SHA256，只接受支持的联合 Walk 任务、严格字段和有效参数。原件继续如实记录训练方式，不把本次运行调整伪装成训练设置。

基础动作缩放作用于模型输出相对 HOME 的动作偏移。头部低通 0.5 表示本轮目标和上一轮目标各占一半；腿部低通 0.7 表示本轮目标占 70%、上一轮目标占 30%。滤波系数不是将最终关节角度再乘一次。

**电压补偿沿用本机设置。** 实际动作倍率是基础 0.9 再乘原有电压补偿倍率，因此实际倍率可能高于或低于 0.9。当前模型的固定基础值与已保存的全局动作系数分别显示，实际应用值以 robotd 回读为准。全局原有 0.7 或其他值仍保存，供原有参数路径使用；本次无需再把它手动改为 0.9。

下一帧观测中的 `previous_action` 继续使用原始网络动作输出。运行时仍采用原 50Hz 控制循环和现有滤波算法，没有增加后台采集、网络轮询或额外传感器读取。原生执行机制见 [robotd 控制设计](docs/design/robotd-design.md)。

## LB、卸力与手柄

LB 继续调用独立的 11000 轮起身老师，使用原来的基础 1.0、头腿直通及电压补偿规则。它没有占用第二个 Walk。

倒地时，HOME、保持、行走和卸力状态都可以按 LB。卸力时由原流程确认上力后，从当前反馈姿态开始，不先执行 HOME 回位。从 HOME／卸力等未启用策略状态开始，本轮结束后回 HOME；从已启用的保持／行走策略开始，本轮结束后回新的联合 Walk。默认约 6 秒及用户保存的 LB 时长继续使用；执行窗口结束不代表已检测到起身成功。

起身期间按 Start 取消并回 HOME；短按并松开 Select 卸力，Select 长按关机保持原行为。开机仍然卸力。网页和真实手柄继续走原 padd → robotd 路径，真实手柄连接后优先接管。连接和输入机制见 [R17 连接设计](docs/design/r17-connection-design.md)。

## 测试时先核对这些结果

1. 升级后确认中控 `1.0.146`、运行 build `control.29`，Walk 指向新联合模型，模型列表没有旧行走模型。
2. 按原流程 HOME 后启用策略，观察零速度保持和短距离行走；当前模型配置应为基础 0.90、头 0.50、腿 0.70，另看含电压补偿的实际倍率。
3. 测试联合模型的倒地恢复时，保持联合 Walk 策略启用；上述三个值应保持不变。
4. 卸力后按 LB 是另一次独立起身老师测试。两者的结果请分别记录，便于判断联合模型表现。记录仍用原中控导出功能。

本次运行设置不同于该模型原始的 1／1／1 训练条件，步态和起身表现需要实机对照。观察到动作不合适时沿用原 Start 回 HOME 或 Select 卸力入口。

## 验证范围与源码

本版配套 robotd、robotctl 和 padd 使用 API40，原始遥测协议仍为 `r17.raw.v1`。构建、真实 ONNX 合成输入、模拟硬件控制循环、模型导入、前端事件和实际安装载荷检查的结果，见源码 `verification/` 和随包验证说明。

本轮未在用户 Zero 上完成步态、起身、真实手柄／systemd／uinput 或板温测试，也未运行 Chromium 渲染。离线测试通过不能替代实机结果。

系统全局 `/usr/local/bin/robotctl` 仍由官方安装管理。本版配套状态命令：

```bash
sudo /opt/robot/feetech-ft5-r5/robotctl health
```

仍为旧 API 的官方 updaterd 与配套 API40 工具可能显示版本差异提示；当前 R17 固件版本以中控／总线回读中的 build 标识为准。

源码中的 `policies/walk` 只存放新联合模型。旧行走模型仅作为 `test-data/walk-teacher14000` 数值回归样本保留于源码，测试样本不进入固件、模型目录或中控模型列表。参数、导入及升级保存规则见 [R17 设置设计](docs/design/r17-settings-design.md)。
