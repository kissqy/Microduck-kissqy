Отчёт о проверке R1.5.17
Дата: 2026-10-06

1. Регрессионные тесты Python (системный Python 3.12.14, без зависимостей обучения)
Команда: `python3 -m unittest tests.test_recovery_api tests.test_eval_push_dependencies tests.test_recovery_evaluation.RecoveryResultsTests tests.test_viewer_lifecycle tests.test_training_api tests.test_remote_training tests.test_durable_training -v`
Результат: 57 тестов, 54 пройдены, 3 пропущены; 8.505 секунды.
Все пропуски относятся к существующим тестам владения долговременными процессами: пространство имён PID в среде выполнения не соответствует /proc.
Охват: привязка происхождения выбранной модели, специальные запросы PT/ONNX, запрет неверной роли и входа через обучение, невозможность выдать сброс за успех, зависимости курса толчков, жизненный цикл замены симуляции, API обучения и передача данных, версия и комплект удалённого развёртывания, мониторинг долговременных процессов.
Исходный вывод: R1.5.17-portable-tests.txt

2. Интеграция закреплённых официальных исходников с CPU / Viser
Официальный коммит: 8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec
Зависимости: Python 3.12.14, Torch 2.9.1+cu128 (фактически device=cpu), MuJoCo 3.10.0, mjlab 1.3.0, Viser 1.0.30, ONNX Runtime 1.24.4, BAM 1.0.1.
Команда: `MICRODUCK_OFFICIAL_SOURCE=/path/to/frozen/source <eval-python> -m unittest tests.test_recovery_evaluation.RecoveryUpstreamTests -v`
Результат: все 8 тестов итогового модуля пройдены (3 переносимых уже учтены в группе 1, ещё 5 используют реальные официальные исходники/CPU/Viser); 26.067 секунды.
Охват: сохранение обычного рельефа Rough; неизменность конфигурации при train/preflight/preview/export/describe; одинаковая конфигурация PT/ONNX; итоговая смесь в реальном EventManager; восстановление разных counter больше не изменяет курс оценки; направление гравитации для спины/левого бока/правого бока/живота; нулевые скорости и команды; нижняя точка коллизионного тела на 1mm над землёй; сброс действий и истории фильтра; запуск реального сервиса Viser, переключение поз, состояние и закрытие.
Исходный вывод: R1.5.17-cpu-tests.txt

3. Регрессия изоляции штатного GUI скорости
Независимая перепроверка обнаружила, что штатный Twist GUI может переопределять нулевые диапазоны в конце command.compute. Для специального режима добавлен hook обнуления после исходного вычисления, затем повторно выполнен целевой тест с реальным Viser.
Результат: 1 тест пройден; 18.625 секунды. Штатный joystick действительно включён; после задания ненулевой скорости последние 13 командных слотов наблюдения actor остаются нулевыми.
Это дополнительный повтор проверки указанной выше логики Viser; число независимых пройденных тестов не увеличивается.
Исходный вывод: R1.5.17-viser-tests.txt

4. Поведение клиентских скриптов
Команда: `node tests/test_recovery_ui.cjs`
Результат: код выхода 0. Использованы реальные tasks.js + training.js и тестовая среда DOM/HTTP.
Охват: 4 официальных варианта stand × PT/ONNX; определение роли по resolved_task/request.task выбранной модели; текущее действие обучения не меняет допустимость; разделение обычных и специальных запросов; принудительное отключение толчков в специальном режиме; блокировки при отсутствии соединения, ожидании viewer и повторной отправке; инициализация и выбор модели не вызывают автоматический POST или запуск обучения.
Реальный браузер не использовался; отображение 4K/CSS/WebGL не проверялось.
Исходный вывод: R1.5.17-ui-tests.txt

5. Синтаксис и состав выпуска
Изменённые файлы Python прошли py_compile, training.js прошёл node --check.
В этой версии сохранены исходные рецепты обучения, закреплённый официальный коммит, данные оборудования, значения по умолчанию для действий/P/фильтра и существующие модели; новая логика выполняется только при оценке учителя подъёма из положения лёжа. Версии обоих концов SSH синхронно повышены до R1.5.17.
Обучение на GPU, продолжение обучения и реальный робот в этой проверке не запускались. Критерий прохождения для четырёх поз проверяет только удержание высоты и наклона туловища, без проверки контакта подошв. Инициализация с зазором 1mm — геометрическое размещение, а не библиотека физически установившихся состояний.

6. Два коротких воспроизведения исходного ONNX 11000 (новое ключевое свидетельство)
SHA256 модели: a481d9f211f31d9476ab1a319fe362a21ef0879d9fa59442a122845af598268c
Контракт робота/действий/наблюдений соответствует считанным параметрам обучения; исходные P5, scale1, без фильтрации. Специальный режим: ровная поверхность, нулевая начальная скорость, все 13 команд равны нулю; начальный геометрический зазор 1mm.
На спине: начальная гравитация [-1,0,0]; за 1.48 секунды достигнут и завершён непрерывный секундный контроль высоты стойки/наклона; конечная высота 115.60mm, наклон 0.983 градуса.
На животе: начальная гравитация приблизительно [1,0,0]; за 1.36 секунды завершён тот же контроль; конечная высота 116.08mm, наклон 0.387 градуса.
Для каждого класса выполнен только 1 выборочный эпизод, seed среды не фиксирован, рандомизация yaw/физики сохранена; это не оценка доли успехов. Контакт подошв не проверялся, видео и покадровые траектории суставов отсутствуют. Предварительная проверка интерфейса выполняет только один проход ONNX без состояния, без предварительного env.step; отсчёт начинается с первого шага после сброса viewer, до завершения эпизод не сбрасывался.
Вывод: нельзя утверждать, что эта модель никогда не встаёт из полностью лежачего положения на спине. Далее нужно записать и воспроизвести фактическое состояние пользователя с застрявшей ногой/шеей и дополнить обучение этим неудачным состоянием.
Структурированная запись: recovery-teacher11000-check.json

7. Запись позы в обычном и специальном режиме (уже включена в итоговую группу 2)
Ненулевые команды .23/- .11/.31 в обычном просмотре Rough сохраняются; qpos, qvel и число шагов эпизода до и после записи неизменны, реальный буфер контактов доступен для чтения, соответствие суставов адресам qpos корректно, JSON разбирается. Вход записи также проверен в специальном режиме.
До первого step флаги reset записываются как null; состояние после автоматического сброса явно помечается как возможно post-reset.
Запись содержит только позу/скорость/команды/диагностику контактов и отпечаток модели; возможность восстановления внутреннего гистерезиса исполнительных механизмов, решателя и генератора случайных чисел не заявляется.
