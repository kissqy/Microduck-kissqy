# Сервоприводы Feetech, upstream-конфигурация и проверка совместного обучения
<a id="飞特舵机官方配置与联合训练核对"></a>
<a id="feetech-servos-upstream-configuration-and-joint-training-review"></a>

**Архив технического исследования, 3 октября 2026 года:** здесь зафиксирована историческая проверка оборудования и исходников обучения, а не актуальная инструкция по эксплуатации. Функции и параметры описаны в [текущем руководстве пользователя](../USER-GUIDE.ru.md). Проверялась консоль R1.5.3 с целевым контрактом среды выполнения 0.15.1.

Проверка выявила существенные ошибки консоли и ещё один подробный набор данных идентификации HD1910. Записи совместного запуска пользователя и оба PT учителей были недоступны, поэтому нельзя объявить ошибку исходников причиной раскачивания в том запуске.

## 1. Происхождение обучения
<a id="1-先说当前训练到底来自哪里"></a>
<a id="1-training-provenance"></a>

Базовая конфигурация объединяет закреплённые задачи Pollen, параметры исполнительных механизмов Feetech от Luwu и адаптацию к локальному роботу массой 820 g. Она не копирует робота Luwu целиком и не сохраняет исходную динамику XL330.

| Компонент | Базовая конфигурация на момент проверки |
| --- | --- |
| Задачи / награды / сброс / завершение / наблюдения / PPO | `microduck_rl@8d0db749`; сопоставлены все 12 задач с обычными стопами |
| Совместное обучение | Официальный VelStand с защитой при падении, тёплый старт от ходьбы, BC с двумя учителями ходьбы / подъёма; выбранные пользователем локальные учителя |
| Время учебного курса | С R1.5.2 — эквивалентное число отсчётов `4096×24`; при 2048 средах пороги удваиваются, при 1024 — учетверяются. Одинаковое число отсчётов не гарантирует одинаковую траекторию оптимизации |
| Сохранение / журналы | Каждые 1000 итераций по запросу пользователя; локальный TensorBoard; независимо работающий серверный процесс |
| Исполнительный механизм | Исходный Luwu `1910_m6.json`, P5, 7.4–8.0 V, минимум 7 V, задержка команд 3–6×5 ms |
| Сброс Feetech | Исправление сброса истории целевых значений отдельно для каждой среды от fanhao375; рандомизация трения upstream сохранена |
| Робот | Официальный каркас, 15×23 g сервоприводов, добавка 3 g в голову / остальное в туловище, всего 820 g. Масштабирование инерции по существующему рецепту массы, а не полный измеренный тензор инерции локального робота |
| Действия | Масштаб при обучении 1.0 без дополнительного 0.7; развёртывание следует контракту |
| Калибровка | Импортированные нули / направления / крепление IMU сохранены; дополнение справочных данных не откатывает их |

Статические различия 12 загруженных конфигураций по умолчанию касаются исполнительного механизма, построения робота / распределения массы и интервала сохранения; они записаны в `data/official-studio-config-diff.json`. Сравнение выполнено до привязки локальных учителей / пересчёта времени по отсчётам; это не снимок текущего запуска.

### Luwu предоставляет больше 20 полей BAM
<a id="陆吾不只是提供了20个bam字段"></a>
<a id="luwu-provides-more-than-20-bam-fields"></a>

XgoDuck включает собственную геометрию / инерцию для массы 0.8 kg, HOME сгибания бёдер ±24°, высоты стояния / сидения, трение стоп 0.4–1.5, шум и награды. При восстановлении робот падает из воздуха, замирает на 2 секунды, затем действует в 8-секундных эпизодах. Здесь сохранены закреплённые задачи для официального каркаса, без переноса этих изменений геометрии.

Этот коммит не регистрирует новый VelStand XgoDuck с двумя учителями. Старый MicroDuck VelStand не равнозначен нынешней версии с защитой при падении; другие результаты Luwu не служат эталоном для данной совместной задачи. Локальный BAM совпадает с исходным SHA256 `ef2d51adfb1cc0831b9b02ca19aa9176fceecdf725148d084378d7d9a64afceb`.

Проверка добавляет указание источников / сравнение, не меняя значений по умолчанию и не заявляя превосходства.

## 3. Используемые и неиспользуемые поля
<a id="3-哪些字段确实用了哪些没用"></a>
<a id="3-fields-used-and-unused"></a>

| Поле | Фактический путь |
| --- | --- |
| kt / R / armature / трение | Вычисления модели вместе с напряжением, задержкой, коэффициентами |
| error_gain_ratio | Отклик PWM с P / преобразованием ошибки до насыщения, а не масштабирование угла |
| max_velocity 100 | Внутренний предел скорости изменения целевого угла, а не измеренная скорость без нагрузки / ходьбы |
| q_offset | Запись идентификации; в этом пути bam.mjlab не используется, не является zero_raw робота |
| command_delay≈0.006 s | Не используется; фактическая очередь составляет 3–6 физических шагов; добавлять ещё 6 ms нельзя |
| Трение 0.9–1.1 | Независимая от скорости составляющая трения BAM, а не трение стоп / вся динамика |
| Трение стоп | Официальное 0.7–1.3, независимо |
| Armature 0.9–1.1 / центр масс / масса / инерция / шум | Сохранены upstream-события, соответствующие каждой задаче |
| Номиналы / регистры / тепловые пределы XL330 | Справка по оборудованию, а не полная симуляция прошивки или перенос на Feetech |
| Аппаратные D / I | Путь STS3215 не воспроизводит PID полностью; kd_scale — множитель противо-ЭДС, а не аппаратный D |
| Люфт / температура / разброс экземпляров | В задачах с обычными стопами на момент проверки не было независимых суставов люфта / локальной тепловой модели / идентификации каждого сервопривода |

У XL330 также есть константы вне JSON: преобразование ошибки контроллера, предел PWM, ограничение тока. R1.5.3 добавляет считывание после построения: предел XL330 1.75 A, в модели Feetech такого ограничения нет, что не означает отсутствия физической защиты. Верхние границы полного момента не являются номиналами длительной нагрузки.

## 4. Исправлены три ошибки консоли
<a id="4-本次修复的三个中控问题"></a>
<a id="4-three-console-defects-fixed"></a>

1. **Заголовки / единицы BAM:** обращение к словарю по индексу массива теряло китайские описания. Именованные поля показывают все 20 параметров, два неиспользуемых отмечены явно.
2. **Путь переопределения не загружался:** R1.5.0–1.5.2 меняли публичный json_path, не обновляя кэшированный разобранный путь. Воспроизведение: kt на странице 0.7, фактически 0.623761. Повторное построение объекта конфигурации заставляет загрузку / скомпилированную инерцию следовать изменениям. Затронуты только ручные переопределения; это не доказывает неверность обучения с параметрами по умолчанию.
3. **BC скрывался в описании:** describe / evaluation оба очищали bc_cfg, скрывая 17 параметров учителей; фактическое обучение сохраняло BC. Теперь describe сохраняет / объясняет их; evaluate / export по-прежнему загружают только учеников.

Для старых записей, затронутых кэшированием BAM, воспроизведение / продолжение обучения / контракты учителей используют исходные фактически загруженные параметры с пояснением происхождения. Исходные PT / записи запусков не переписываются; новые переопределения работают.

## 5. Совместное обучение требует собственных проверок
<a id="5-联合训练为什么值得单独查"></a>
<a id="5-joint-training-requires-its-own-checks"></a>

Официальное переключение использует привязку к учителю ходьбы при наклоне ≤25°, учителя подъёма выше 35° и PPO между ними. Команды скорости учителя подъёма нулевые; каждый учитель сохраняет свою нормализацию. Тёплый старт от ходьбы сразу переводит унаследованные курсы ходьбы на конечные стадии, постепенно усложняя только новые курсы падения / толчков. Ранняя контрольная точка ходьбы может не справляться с этими начальными командами / рандомизацией, даже если ходит при простой оценке.

Upstream описывает случай, когда имитация подъёма повреждала ходьбу, и затем добавляет привязку к ходьбе, меньшую скорость обучения BC и ограниченные мини-пакеты. Эта консоль использует исправленную версию с двумя учителями; выбор двух учителей не доказывает совместимость действий / нормализации / распределения среды.

R1.5.3 показывает доли выборок, попавших под переключение ходьбы / подъёма, потери имитации, награду скорости и штраф раскачивания. Доля переключения — не доля успешных попыток; при слишком малом числе кадров падения BC подъёма пропускается. Нужно проверить фактические хеши учителей, источник тёплого старта, 17 значений BC, компоненты награды, завершение, часы курса, считывание BAM. Сравнить учителей и ранние / текущие совместные контрольные точки при одинаковой оценке стоя / на животе / на спине / на боку / после толчка. Обучение включает исследовательский шум / возмущения; один текущий вид утки не доказывает качество развёртывания.

Официальные пороги, например момент остановленного привода 0.4 N·m / скорость 0.5 rad / s, задают награду, а не измеренные критерии приёмки HD1910. Менять отдельный порог следует только после контролируемого подтверждения проблемы.

## 6. Однозначная средняя награда — это хорошо или плохо?
<a id="6-平均奖励个位数能不能判断好坏"></a>
<a id="6-is-a-single-digit-average-reward-good-or-bad"></a>

По ней одной судить нельзя. Mean reward — средняя накопленная награда rsl-rl за последние 100 завершённых эпизодов. Компоненты Episode_Reward делятся на максимальную длительность эпизода, поэтому напрямую складывать эти статистики нельзя. Важны задача, длительность, курс, штрафы, динамика. Это не процент и не сумма по параллельным средам; переход 1024→4096 не умножает среднее на 4.

У открытых примеров нет универсального проходного балла:

- [Официальный SitStand](https://github.com/pollen-robotics/microduck_rl/blob/8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec/docs/sitstand_policy.md): 140→125 и 131→116 при усложнении курса, затем восстановление; это другая задача.
- [Официальные исходники совместной задачи](https://github.com/pollen-robotics/microduck_rl/blob/8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec/src/mjlab_microduck/tasks/microduck_velstand_env_cfg.py), запуск `6op8a8u8`: восстановление после толчка в симуляции 88–95% на трёх seed, медиана 2.7 s, а не средняя награда 88–95. Сопоставимое итоговое среднее не получено.
- [Воспроизведение Datawhale с 256 средами](https://github.com/datawhalechina/dive-into-embodied-ai/blob/master/docs/practices/amd/microduck-rl/index.md): на 500 итерациях среднее 5.3664 / максимум 5.5925, но запрошенные 0.15 m / s дали ≈0.0052 m / s. На 1500 итерациях среднее 59.0012 / максимум 62.2754, последняя контрольная точка ≈0.0454 m / s, лучшая из проверенных — model_750. Рост награды / последняя итерация не означают лучшую походку. Другое оборудование / задача и воспроизведение в течение 4 секунд не являются длительной приёмкой робота.

При снижении награды с раскачиванием нужно проверить слежение за скоростью, ранние завершения, успех подъёма и отклонения от учителей. Одно усложнение курса не объясняет наблюдение.

## 7. Страница параметров и охват проверки

Исправления не меняли BAM по умолчанию, питание / P, награды или прошивку; соединение с ZERO не устанавливалось, обучение WSL не останавливалось. Выполненные проверки и ограничения см. в [отчёте о проверке](Verification.ru.md).
