# Microduck R17 v1.0.154

配套原生固件为 `1fa8438-feetech-ft6-control.33`。本版撤销此前的舵机手动覆盖，加入右脚踢球，撤掉独立 LB 起身测试和模型导入，修正随包固件版本显示。沿用 v153 的完整 ARM ONNX Runtime、安装完整性校验、SSH 与 robotd 数据连接分离、有限 UART 冷打开方案和 GameSir 修复按钮。

## 撤销舵机覆盖

高级参数移除 P50、D51、48 号转矩限制三个输入和后台处理，保留原动作缩放。升级清理旧测试 JSON 与已退役生产模块。P 按模型合同应用到全部 15 个舵机；当前随包合同为 P=5。上力与卸力恢复只写 P 的一个字节，48／51 保留设备当前值，不以写零恢复。准确机制见 [robotd 控制设计](../../../docs/design/robotd-design.md#r17-hd1910-合同-pcontrol33)。

## 内置右踢与联合起身

右脚踢球 `67ad09d82f4865d222a7ae06f250cf9f` 使用上传原始 ONNX、合同及训练元数据，基础缩放 1、头腿目标直通；按合同作为 0.5 秒零命令、不可连发技能运行。默认 RB 调用右踢，中控提供相同动作按钮，调用原 `robot.do`。按钮要求真实就绪状态，不自动 HOME、开启策略或延后重放请求。

独立 `stand_test`、LB 测试按钮及老师运行绑定移除。联合 Walk 已包含倒地恢复，继续使用 v153 的 1.0／0.5／0.7 执行配置。LB 回到官方左踢；没有左踢模型时不可执行。旧默认 LB 与空 RB 会迁移，其他用户按键设置保留。五个内置模型及升级规则见 [R17 设置设计](../../../docs/design/r17-settings-design.md)。

## 中控入口与版本

模型导入按钮、上传、API 和 CLI 已移除，正常模型加载的合同验证保留。固件 ZIP 导入继续可用。

“随包固件”显示通过完整性校验的真实 build，不再硬编码 `control.18`；读取失败会清除旧标签并显示未知。运行 build 仍取机器人实际回读，随包标签不能代替运行身份。

## 安装与验证范围

关闭旧中控，完整解压本版，支撑机器人并通过“系统维护 → 随包固件”安装一次。核对中控 `1.0.154`、运行 build `control.33`，等待总线与 IMU 就绪后使用原 HOME／策略流程。无需重装 Linux 或清空标定。

本版进行了本地原生构建、合同与寄存器报文校验以及相关管理和前端回归验证；准确结果与文件哈希以随包清单、源码验证记录为准。正常 50 Hz 控制不增加循环、采集或推理。本轮未连接真机，断电重启、蓝牙稳定性、动作效果及温度仍需实机确认。
