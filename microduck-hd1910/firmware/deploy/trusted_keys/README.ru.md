# Доверенные открытые ключи

Основа доверия робота. `scripts/install.sh` копирует эти ключи в `/etc/robot/trusted_keys/`, указанный как `trusted_keys_dir` в [`../updater.toml`](../updater.toml). Артефакт допустим, если его подпись проверяется **любым** ключом из этого каталога.

| | |
|---|---|
| `release-1.pub` | Сейчас подписывает все выпуски и продвижения |
| `release-2.pub` | Первый ключ замены при компрометации CI или `release-1` |
| `release-3.pub` | Последний резерв; его закрытая часть никогда не должна попадать на компьютер с доступом к сети |

**Все три поставляются с самого первого образа — в этом и смысл.** Робот может проверять подписи только набором встроенных ключей; если на нём единственный ключ, закрытая часть которого позднее утрачена или раскрыта, передать замену по сети невозможно — потребуется ручная перепрошивка. Заранее включить запасные ключи ничего не стоит; добавить их задним числом невозможно. Хранение описано в [`../../docs/project/ci-setup.md`](../../docs/project/ci-setup.ru.md).

**Открытые ключи не являются секретами.** Их коммит правилен и предусмотрен: именно они должны быть публичными, чтобы любой мог проверить наши подписи. Закрытые части находятся в `~/.duck-keys` и менеджере паролей; в CI есть только закрытая часть `release-1`.

**`team.dev.pub` намеренно отсутствует в этом каталоге.** Робот, доверяющий ключу разработки, устанавливает всё, что собирает любой участник команды. Он должен быть только в `trusted_keys_dir` платы разработчика вместе с `allow_dev_keys = true` в её локальном `updater.toml`, но никогда здесь, откуда ключи получают все роботы. Он закоммичен в [`../dev-key/`](../dev-key/README.ru.md), содержимое которого ничто не устанавливает по умолчанию.

<a id="adding-a-rotation-key"></a>
## Добавление ключа замены

Сгенерируйте ключ и поместите `.pub` сюда; он попадёт на роботов при следующей установке. Учтите асимметрию: *новый* ключ становится доверенным только для роботов с образом, записанным после его добавления; поэтому смена ключей защищает будущие установки и не спасает уже работающих роботов. Именно поэтому резервные ключи поставляются заранее.

```bash
cargo xtask keygen --kind release --name release-4 --out ~/.duck-keys
```
