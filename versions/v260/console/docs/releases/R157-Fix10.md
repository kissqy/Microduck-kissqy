# R157-Fix10 — 摄像头按需采集

开机和只打开中控页面时，真实摄像头保持休眠；mediad 与信令仍在线。点击视频连接后才唤醒采集，最后一个视频会话退出后休眠。多个页面独立计数，一个页面断开不会停止其他页面的视频。退出页面也释放本页会话。

自动曝光和鸭子检测在休眠时等待，不定时唤醒摄像头。截图和连续流使用同一个采集入口：请求期间持有采集使用权，最后一个使用者结束后休眠。中控通过已有系统数据流显示采集休眠状态，没有添加查询循环。

本版需要安装一次随包固件，以更新 mediad。安装保留原 mediad 参数、环境、用户和权限，只新增该服务的启动程序覆盖；摄像头配置失败会恢复该覆盖，失败不停止 robotd 或输入服务。原 robotd 四步启动完成后才执行这个附属步骤。

robotd、robotctl、padd、音库、推理库、模型和 GameSir 输入桥沿用 Fix9 原文件；50 Hz 控制、UART/IMU、SSH 数据、手柄修复和仲裁流程保持原样。

验证记录随源码附带：原生 GStreamer 采集生命周期与信令启动观察、Python 安装/控制回归、页面连接与退出逻辑、ARM64 编译和实际固件导入校验。尚未在真实 Zero/IMX219 上测温或验证启动后画面；安装后检查“休眠 → 连接出图 → 最后一个页面断开后休眠 → 再连接出图”。

采集机制见源码的 [WebRTC 设计](../../../docs/design/remote-webrtc.md#按需采集r157-fix10)。
