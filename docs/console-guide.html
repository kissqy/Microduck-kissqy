刷机后，怎么找到机器人 IP？

刚把系统镜像写入 TF 卡

从下面第 1 步开始，先给鸭子配网。

只在中控里升级了固件 / 以前已配网

沿用原来的网络，直接到 第 3 步查当前 IP。

1

手机连接鸭子发出的热点

给刷好本项目 R1 系统镜像的 ZERO 上电，等待首次启动初始化完成。在手机的 Wi-Fi 列表里连接：

Wi-Fi 名称Microduck-kissqy
热点密码12345678

手机提示“此网络无法上网”时，选择仍然连接。这一步是在连鸭子的配网热点；不要让手机自动切回其他 Wi-Fi。

2

在配网页面填写家庭 Wi-Fi

连接热点后，打开手机弹出的配网页面；没有弹出时，在浏览器地址栏输入：

http://10.42.0.1:8088仅在已连接机器人热点时使用
  1. 填写家里路由器的 5 GHz Wi-Fi 名称和密码。
  2. 设置并记住新的 radxa 系统登录密码。稍后连接中控要用它。
  3. 提交配网后，等待机器人连接家庭网络。再把手机、电脑接回同一个家庭路由器；电脑接这台路由器的网线也可以。
记住两个密码的用途：家庭 Wi-Fi 密码用于让鸭子上网；新设置的系统登录密码用于中控 SSH 连接。
3

到路由器的设备列表，查鸭子的 IP

这是推荐的查找方法，不需要先知道机器人的地址。

  1. 打开你家路由器的 App 或网页管理后台。
  2. 进入「已连接设备」「设备列表」或「DHCP 客户端」。不同品牌的名称可能不同。
  3. 在在线设备中找到刚接入的机器人。设备名可作为线索，但不保证显示为 Microduck；结合新上线记录或已知的设备 MAC 核对。多只鸭子配网时，先只给正在设置的一只上电。
  4. 记下这台设备的 IPv4 / IP 地址。这是中控连接栏要用的机器人 IP。
假设路由器里查到的机器人 IP 是192.168.1.123

中控的 SSH 地址就填写radxa@192.168.1.123

这里只是示例，请把后面的数字换成你实际查到的 IP。

不知道路由器管理后台怎么打开？

优先用路由器品牌对应的 App 查看设备。也可在电脑的网络设置中找到「默认网关 / 路由器」地址，再用浏览器打开这个地址。网关地址是路由器的管理入口，不是鸭子的 IP。

Windows 也可以按 Win + R，输入 cmd 打开命令窗口，再输入 ipconfig。在当前联网的网卡下查看「默认网关」，不要抄虚拟网卡或未连接网卡的地址。

管理后台用的是路由器管理账号和密码，不是鸭子的 radxa 密码。后台登录方式以自己的路由器说明为准。

设备列表里没有鸭子，或名称看不出来？

先确认鸭子已接入路由器：家庭 Wi-Fi 名称、密码是否正确，是否选择了可用的 5 GHz 网络。手机仍连着 Microduck-kissqy 热点，并不代表鸭子已经连上家庭 Wi-Fi。

刷新路由器的在线设备列表，结合上线时间和设备 MAC 核对；不要因为名字相似就随意选择。如果机器人热点仍可见，可重新连接热点，查看配网结果或重试。热点消失本身也不能单独证明配网成功。

02

把查到的 IP 填进中控

  1. 完整解压中控。Windows 打开 start.cmd，macOS 打开 start.command。由启动器打开本地页面，通常为 http://127.0.0.1:8090。
  2. 电脑与 ZERO 接入同一局域网。在「SSH 地址」填 radxa@实际IP，例如 radxa@192.168.1.123；「SSH / sudo 密码」填配网时新设置的系统登录密码，再点「连接」。
  3. 等待反馈。检查启动步骤 1/4～4/4、关节反馈与实际运行版本。连接成功后，新装的鸭子先做关节标定和IMU 核对；已标定的鸭子再进入日常操控。
连接前对照一遍
  • 地址来自路由器的机器人设备条目，不是电脑 IP 或路由器网关。
  • 密码是 radxa 系统登录密码，不是热点密码 12345678，也不是家庭 Wi-Fi 密码。
  • 运行的是本地中控；GitHub 上的在线演示不能连接实机。
在线演示使用模拟数据。这里用来熟悉界面；连接实机需要下载并启动本地中控。连接本身不会让鸭子开始走路。

04

关节标定：一颗一颗核对

更换舵机、重新装配或第一次制作后，都要核对本机标定。左右按鸭子自身：10–14 是右腿，20–24 是左腿，30–34 是颈部与头部。

  1. 切到标定模式。在「关节工作台」选择要核对的关节，确认 ID 与实物一致。
  2. 先看参考。在 3D 里查看「零位 0°」「HOME 站姿」「0 → +10°」。这些按钮只改变屏幕模型。
  3. 核对方向。实物沿 3D 正向运动时，counts 增加选 +1，counts 减少选 −1。
  4. 保存本关节。填入实物当前「已知角度」和实际机械限位，勾选核对框，点击「保存当前关节」。逐个完成全部关节。
「全部顺序回到 2048」仅供未装配舵机居中。该按钮要求舵机尚未装上骨架且空间无遮挡，已装好的鸭子不要用它代替标定。3D 中的模型限位也不能直接替代实物机械限位。

05

IMU 与 3D 姿态核对

  1. 确认 IMU 已固定。在实测视图中，缓慢前后、左右倾斜机身，对照屏幕鸭子的倾斜方向。
  2. 机身坐标采用 X 向前、Y 向左、Z 向上。直立参考姿态时，重力约为 [0, 0, −1]。
  3. 在「IMU 安装核对」中按实际安装填写四元数 w x y z；核对轴向和倾斜方向后，勾选确认并保存。

四元数反映实际安装方向，不要直接抄另一只鸭子的数值。「整机视角」或显示朝向归零只影响画面，不会校准实物 IMU。

06

HOME、保持与行走

这一步适合已完成关节和 IMU 标定、反馈正常的机器人。新装的鸭子先完成关节标定和IMU 核对。

切到运动模式→首次 Start：HOME→再按 Start：启用策略→摇杆行走
  1. 扶稳鸭子，松开摇杆，点击「切到运动模式」，等启动完成。
  2. 使用实体手柄时，首次按 Start 回到 HOME，等待站姿到位，再按 Start 启用策略。
  3. 左杆控制前后与侧移，右杆左右控制转向。先用小幅输入观察动作。
  4. 松开摇杆回到零速度保持；按 Start 关闭策略并回 HOME。需要卸力时，扶稳后短按并松开 Select。
松开摇杆仍在保持。想完全卸力，用「停止并松开」或 Select 短按松开；卸力前先扶稳。Select 长按 2 秒会坐下、卸力并关机。

装了滑轮，怎么切换？

先完成 HOME 并保持摇杆回中，实体手柄长按 ↑ 3 秒切换行走 / 滑轮。切换完成再按 Start 启用策略。左杆前后控制滑行，右杆左右转向。

滑轮 A 默认蹲下。要切换为原地转，先按 Start 关闭策略回 HOME，等待静止，再长按 ← 2 秒，随后启用策略再按 A。网页不提供专用滑轮切换按钮。

实体 L3 的起身测试只在滑轮模式、策略已启用且 IMU 确认倒地等条件满足时接受；Start 可取消。具体以运行版本与页面提示为准。

08

打开鸭子的头部视野

  1. 连接实机后，在「头部视野」点击「连接摄像头」。
  2. 等待视频建立，检查帧率、码率和丢包累计。画面方向不合适时，使用「旋转」选择显示方向。
  3. 使用完点击「断开」。最后一个视频使用者退出后，采集休眠。
摄像头按需启动。只打开中控或开机，不会一直采集视频；在线演示不连接摄像头。

09

升级固件与结束使用

系统维护 → 固件

  1. 先看「实际运行版本」，再选择当前中控配套的「随包固件」，或使用「选择 ZIP 文件」导入兼容固件。
  2. 等待校验完成，点击「升级所选固件」，按状态提示等待安装和服务重启。
  3. 完成后重新核对实际运行版本与反馈。安装不会自动回 HOME 或启用策略。

用完怎么关？

扶稳鸭子后卸力；需要关 ZERO 时，在电源区点击「关闭 Zero」，或使用实体 Select 长按 2 秒。等待关机完成后再断电。

关闭浏览器标签后，本地中控脚本可能仍在运行。更换或删除中控目录前，到启动终端按 Ctrl + C，等待退出。

10

遇到问题，从现象找入口

刷完系统后，不知道机器人 IP 在哪里？

先按配网与查找 IP完成连接家庭 Wi-Fi，再到路由器 App / 后台的在线设备列表查 IPv4 地址。中控填 radxa@实际IP；10.42.0.1 和 127.0.0.1 都不是家庭网络里机器人的 IP。

SSH 密码总提示不对，应该填哪个？

填首次配网时你自己设置的 radxa 系统登录密码。12345678 是机器人热点密码，家庭 Wi-Fi 密码用于连接家里无线网络，都不是这里的系统登录密码。

网页打开了，为什么不能输入 SSH 地址？

先看地址栏：GitHub Pages 是只读演示。下载中控、完整解压并运行启动器，在本地页面连接实机。

连接成功，但鸭子不走？

核对当前是否为运动模式、启动是否完成、模型是否就绪以及 HOME / 策略状态。实体手柄接入时，网页输入会暂停；先用实体手柄操作。

模型方向和实物不一致？

先检查是否处于「实测」视图，以及关节 ID、方向、零位与 IMU 安装方向。全新的装配需要自己的标定；不要用修改 P 或动作缩放来替代方向核对。

SSH 超时、接手柄后掉线？

先区分 ZERO 重启与网络中断。本项目推荐 ZERO 使用 5 GHz Wi-Fi；2.4 GHz 无线手柄可能产生干扰。更多步骤见复刻指南的常见问题。

服务一直没准备好，怎么反馈？

在「系统维护」区点击「导出启动诊断」，并附上中控版本、实际固件版本、出问题的步骤与现象。诊断内容按你的实际情况检查后再分享。
