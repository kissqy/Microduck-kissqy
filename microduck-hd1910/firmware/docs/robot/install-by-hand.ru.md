# Ручная установка по шагам

Действия `scripts/provision-board.sh`, разбитые на отдельные команды. Используйте этот вариант, когда нужно проверить конкретный шаг отдельно; если нужна просто рабочая плата, используйте `provision-board.sh`.

<a id="copy-the-files-up"></a>
## Копирование файлов на плату

Из клона репозитория на вашем компьютере. Копируйте в `~`, **не** в `/tmp`: в процессе есть перезагрузка, после которой содержимое `/tmp` не сохраняется.

```bash
scp scripts/setup-board.sh scripts/migrate-network.sh pierre@192.168.1.42:~/
```

```bash
scp scripts/install.sh deploy/dev-key/team.dev.pub pierre@192.168.1.42:~/
```

<a id="before-the-reboot"></a>
## До перезагрузки

Сначала группа `robot`, чтобы членство вступило в силу после перезагрузки и не требовало ещё одной:

```bash
sudo groupadd --system robot
```

```bash
sudo usermod -aG robot "$USER"
```

Начальная настройка платы: наложение дерева устройств, освобождение UART двигателей от консоли ядра, маскирование getty, `Privacy = device`, onnxruntime:

```bash
sudo sh ~/setup-board.sh
```

Сеть: переход с netplan на NetworkManager:

```bash
sudo sh ~/migrate-network.sh
```

```bash
sudo reboot
```

Перезагрузка обязательна: наложение дерева устройств и сетевой стек нельзя заменить под работающим ядром.

<a id="after-the-reboot"></a>
## После перезагрузки

Повторите оба шага. Они идемпотентны; второй запуск `migrate-network.sh` убирает страховочный механизм Wi-Fi, который иначе возвращал бы плату к netplan при каждой загрузке с медленно устанавливающимся Wi-Fi:

```bash
sudo sh ~/setup-board.sh
```

```bash
sudo sh ~/migrate-network.sh
```

Затем служба. `install.sh` читает настройки из окружения, а `sudo -E` передаёт их дальше:

```bash
export DUCK_TOKEN=github_pat_replace_with_your_token
```

```bash
export DUCK_REF=main
```

```bash
export DUCK_DEV_KEY=$HOME/team.dev.pub
```

```bash
sudo -E sh ~/install.sh
```

Уберите `DUCK_DEV_KEY` для платы, которая должна принимать только релизы. Чтобы установить последнюю сборку конкретной ветки, задайте её в `DUCK_REF`.

`DUCK_WEIRD_BLE=1` в приведённых выше запусках `setup-board.sh` соответствует `--weird-ble`: это настройка для платы, чей Bluetooth вообще не может сопрячься с геймпадом. См. [`pair-a-gamepad.md`](pair-a-gamepad.ru.md).

`DUCK_NO_START=1` устанавливает выпуск, службы, пользователей и группы, но **ничего** не включает — даже для следующей загрузки. Он также останавливает и отключает службы, оставшиеся после предыдущей установки, поэтому результат одинаков для новой и ранее использовавшейся карты. Это помогает отделить неисправность самой платы от работы служб: загрузите плату без наших запущенных компонентов, проверьте её, затем запускайте службы по одной.

```bash
sudo -E DUCK_NO_START=1 sh ~/install.sh
```

```bash
sudo reboot
```

Перезагрузка здесь — необходимая часть процедуры. Собственный `hooks/postinstall` выпуска включает и запускает все службы раньше, чем `install.sh` успеет их остановить, поэтому в текущем сеансе они уже работали при любом значении параметра. После завершения служба не отменяет изменения, сделанные в подсистемах: `btd` оставляет установленным `Pairable`, экземпляр рекламного объявления и возможность ввода-вывода, которую его агент сопряжения по умолчанию назначил адаптеру.

Чтобы снова получить работающего робота:

```bash
sudo systemctl enable --now updaterd robotd configd btd padd
```

При желании задайте имя:

```bash
robotctl system set-name duck-01
```

<a id="gstreamer-for-a-board-that-will-stream"></a>
## GStreamer для платы, которая будет передавать поток

Подготовка системы выполняет этот шаг по умолчанию. `--no-gstreamer` у `provision-board.sh` (`DUCK_GSTREAMER=0` здесь) его пропускает. Перезагрузка в любом случае не нужна, поэтому на плате, где шаг пропустили, его можно выполнить вручную в любое время.

```bash
scp scripts/setup-gstreamer.sh pierre@192.168.1.42:~/
```

```bash
sudo sh ~/setup-gstreamer.sh
```

Вывод показывает возможности кодирования этой платы: зарегистрированные элементы `webrtc*`, доступный кодировщик H.264 и доступность VPU в работающем ядре. На Zero 3W вывод содержит `/dev/mpp_service`, но не `v4l2h264enc`. Для BSP-ядра Rockchip это ожидаемо: VPU доступен через MPP, а не V4L2. Отчёт указывает два deb-пакета Radxa, подтверждающих работоспособность кодирования. Повторяйте проверку после изменения ядра — именно это событие меняет результат:

```bash
sudo /usr/local/sbin/robot-setup-gstreamer
```

Добавьте `--dev`, чтобы установить также заголовочные файлы для сборки `gst-plugin-webrtc` на плате или для sysroot aarch64 при кросс-компиляции.

<a id="check-it"></a>
## Проверка

```bash
robotctl health
```

```bash
robotctl version
```

Статус unhealthy у `robotd` на стендовой плате с обесточенными сервоприводами — корректный результат, а не неудачная установка.

Затем геймпад — [`pair-a-gamepad.md`](pair-a-gamepad.ru.md):

```bash
sudo robotctl pad pair
```
