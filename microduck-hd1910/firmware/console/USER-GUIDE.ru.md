# Руководство пользователя Microduck R17 V167 / control.43

<a id="microduck-r17-v167--control43-使用说明"></a>
<a id="microduck-r17-v167--control43-user-guide"></a>
Версия консоли — `1.0.167`, комплектной прошивки — `1fa8438-feetech-ft6-control.43`, соответствующей официальной системы — `0.15.1`. Физический геймпад использует нативный путь padd → robotd для моделей ходьбы и роликов. Четыре роликовые ONNX-модели устанавливаются вместе с прошивкой.

Проект: [Microduck-kissqy](https://github.com/kissqy/Microduck-kissqy). Ссылки размещены вверху страницы и в окне запуска Windows.

<a id="启动与安装"></a>
<a id="startup-and-installation"></a>
## Запуск и установка

1. Полностью распакуйте `Microduck-Console-R17-V167.zip`. В Windows запустите `start.cmd`; в macOS — `start.command`; в Linux используйте `python3 console.py --dashboard --feetech --open`.
2. Подключитесь к ZERO по SSH через страницу и проверьте версию консоли `1.0.167` и реально работающую прошивку `control.43`. Если control.43 уже установлена на ZERO, замените только папку консоли на компьютере. Для первичной установки используйте **系统维护 → 随包固件** («Обслуживание системы → Комплектная прошивка»).
3. Дождитесь завершения всех шагов запуска robotd 1/4–4/4, затем проверьте текущую обратную связь и подключение геймпада. Само подключение не запускает движение.
4. Если служба показывает `commissioning`, нажмите **切到运动模式** («Переключить в режим движения») и дождитесь четырёх шагов запуска. В режиме commissioning политики движения не загружаются.

<a id="实体手柄滑轮操作"></a>
<a id="physical-gamepad-roller-controls"></a>
## Управление роликами с физического геймпада

Сначала установите ролики, отпустите стики и придерживайте робота. Первое нажатие Start выполняет HOME. После завершения HOME удерживайте ↑ 3 секунды для перехода в режим роликов. Дождитесь переключения модели, затем нажмите Start, чтобы включить политику, и используйте стики или A.

| Ввод | Поведение |
| --- | --- |
| Удержание ↑ 3 секунды | Переключение ходьбы / роликов; при входе в режим роликов A по умолчанию выбирает приседание. |
| Удержание ← 2 секунды | В режиме роликов переключает A между приседанием и вращением; требуется неподвижное состояние HOME без выполняемого действия. |
| A | Выполняет выбранное действие на роликах; в режиме ходьбы — подбор с земли. |
| Левый стик вперёд / назад | Симметричное движение swizzle; в режиме роликов боковое перемещение не используется. |
| Правый стик влево / вправо | Изменяет целевой курс; robotd вычисляет ошибку курса модели по текущему курсу IMU. |
| Start | Первое нажатие: HOME. Последующие нажатия включают / выключают политику; выключение возвращает в HOME. |

Чтобы изменить действие A, отпустите стики и дождитесь окончания текущего действия. Нажмите Start для отключения политики и дождитесь HOME, затем удерживайте ← 2 секунды. После переключения нажмите Start, чтобы включить политику, и A для действия. Если запрос отклонён, прочитайте журнал, устраните причину и повторите попытку.

Удерживайте кнопку всё указанное время. Каждое удержание отправляет один запрос переключения; перед следующим переключением отпустите кнопку. Режимы и действия на роликах управляются физическим геймпадом; отдельной веб-кнопки режима роликов нет. При подключении физического геймпада ввод страницы автоматически отключается.

<a id="模型显示与执行参数"></a>
<a id="model-display-and-execution-parameters"></a>
## Отображение моделей и параметры выполнения

Слева под геймпадом показаны модели и дополнительные параметры; справа — китайские пояснения кнопок. Состояния моделей получаются одним чтением конфигурации. У модели восстановления показаны вход в тест через физическую L3 и его условия; веб-L3 только выводит подсказку и не отправляет ввод.

Четыре роликовые карточки: «滑轮对称滑 / Swizzle» («Симметричное движение»), «滑轮蹲下 / Crouch» («Приседание»), «滑轮原地转 / Spin» («Вращение на месте») и «滑轮倒地起身 / Stand up» («Подъём после падения»). Под названиями указаны итерации обучения и состояние установки.

| Роликовая модель | Базовый масштаб | Фильтр головы | Фильтр ног | Текущий запуск |
| --- | --- | --- | --- | --- |
| Swizzle | 1.0 | 1.0 | 1.0 | Стики в режиме роликов |
| Crouch | 0.8 | 0.5 | 0.7 | A в режиме роликов; период 5 секунд, конечная фаза 0.7 |
| Spin | 1.0 | 1.0 | 1.0 | A в режиме роликов; период 4 секунды, конечная фаза 0.7 |
| Stand up | 1.0 | 1.0 | 1.0 | Физическая L3: режим роликов, политика включена, IMU подтверждает падение; ручной тест 5 секунд |

При загрузке модели robotd читает `required_policy_settings` исходного контракта и применяет масштаб и фильтрацию текущей сети. После завершения действия возвращаются собственные параметры модели swizzle. Фильтрация crouch при развёртывании и историческое обучение без EMA зафиксированы отдельно; контракты обучения и веса не переписываются. Компенсация напряжения и коэффициенты усиления продолжают использовать существующую конфигурацию.

Фактическая контрольная точка пакета восстановления — 11000; число 10000 в имени файла не является метаданными модели. Исходный контракт объявляет `manual_skill` с нулевыми командами, без слота Stand и длительности. Существующая конфигурация `[[policy.skill]]` задаёт окно ручного теста 5 секунд; это настройка теста, а не параметр контракта обучения. Перед выполнением физическая L3 (нажатие левого стика) проверяет реальный режим и свежие данные IMU. Запуск разрешён только в режиме роликов с включённой политикой, завершённым HOME, без другого действия и при подтверждённом IMU падении. Вертикальная поза, ходьба, HOME, снятый крутящий момент и устаревшие данные IMU приводят к отказу с записью в журнал. Каждое нажатие отправляет один запрос; удержание или переподключение геймпада его не повторяет. Start отменяет действие. В конце управление возвращается к swizzle. LB остаётся ударом левой ногой; веб-L3 носит только информационный характер.

## Другие кнопки

| Кнопка | Действие по умолчанию |
| --- | --- |
| X | Кувырок вперёд |
| RB | Удар правой ногой |
| LB | Удар левой ногой, одно действие длительностью 0.5 секунды |
| Крестовина вниз | Переключение посадки / вставания |
| Y / B | Режим позы головы / корпуса |
| RT / LT | Управление клювом и звуком |
| Короткое нажатие Select с отпусканием | Снятие крутящего момента |
| Удержание Select 2 секунды | Сесть, снять крутящий момент, выключиться |

Отдельного теста восстановления на LB сейчас нет. Совместная модель Walk обеспечивает удержание и восстановление при ходьбе. Действительные сохранённые пользовательские назначения кнопок продолжают использовать локальную конфигурацию.

## Калибровка и настройки

Установка сохраняет действительную калибровку и параметры, уже записанные на ZERO. При восстановлении комплектной калибровки сборки используются подтверждённые пользователем настройки: направления всех 15 суставов −1; ноль шеи ID 30 — 2526, ID 31 — 2228, головы ID 33 — 1599; комплектная калибровка IMU также восстанавливается.

Эти настройки получены со сборки пользователя `duck-10e4`. На новом ZERO без действительной локальной калибровки запись «恢复装配标定» («Восстановить калибровку сборки») в журнале установки означает применение этих комплектных значений. При переходе на другого робота проверьте калибровку по фактической сборке.

Столбец направления в текущей обратной связи читает сохранённую локальную калибровку; при отсутствии данных показывает «—». Дополнительные параметры сохраняют масштабирование действий. P сервоприводов берётся из контрактов; остальные параметры следуют действительным локальным настройкам и текущему контракту.

<a id="摄像头与连接"></a>
<a id="camera-and-connection"></a>
## Камера и подключение

mediad постоянно работает и пробуждает видео по запросу. Нажатие Connect камеры запускает захват; после выхода последнего потребителя видео он засыпает. Несколько страниц могут совместно использовать поток. Загрузка системы или простое открытие страницы не удерживают захват включённым.

При первичном подключении показывается ожидание до получения полной обратной связи. Реальные ошибки SSH, служб или запуска поясняются в журнале. **导出启动诊断** («Экспорт диагностики запуска») сохраняет диагностику только для чтения. Для исправления подключения геймпада следуйте инструкциям страницы по режиму A+HOME и сопряжению.

<a id="退出"></a>
<a id="exit"></a>
## Выход

Закрытие вкладки браузера может оставить скрипт консоли работающим. Перед заменой или удалением распакованной папки нажмите Ctrl+C в её терминале и дождитесь выхода. В Windows адреса и защищённые DPAPI пароли хранятся в AppData; SSH использует общий механизм учётных данных консоли.

<a id="验证范围"></a>
<a id="validation-scope"></a>
## Границы проверки

robotd и padd действительно собраны для ARM64. В текущем целевом наборе ядра управления, IPC, padd и роликов пройдено 235 тестов. Новый ARM64 robotd загрузил и выполнил первый инференс шести обычных и четырёх роликовых ONNX-моделей в QEMU. Проверки манифеста / хешей пакета и импорта прошивки консолью пройдены.

Движение на роликах на реальном ZERO в этой среде сборки не проверялось. Результаты относятся к перечисленному объёму, а не ко всему рабочему пространству. Исходные записи сборки и тестов остаются в `verification/v163/`.
