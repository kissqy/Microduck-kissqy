# `duckctl`: все команды

<a id="duckctl--every-command"></a>
Обращение к роботу с ноутбука без сети и SSH. Это замена телефонному приложению и способ достучаться до робота, ещё ни разу не подключавшегося к Wi-Fi.

Сегодня используется Bluetooth LE, но имя намеренно этого не подчёркивает: `mediad` даёт роботу второй транспорт с другим набором методов. Поэтому инструмент назван по адресату, а не по текущему радио. Пока BLE был единственным вариантом, он назывался `duck-btctl`.

**Никогда не устанавливается на робота.** Ни один компонент выпуска от него не зависит. На роботе поставляется `robotctl`, команды которого описаны в [`cheatsheet.md`](cheatsheet.ru.md); для большинства ниже есть эквивалент `duckctl`.

<a id="getting-it"></a>
## Получение

Запуск из клона репозитория:

```bash
cargo run -q -p duckctl -- --name <robot-name> info
```

Либо однократная установка; при этом получается снимок, больше не следующий за веткой:

```bash
cargo install --path duckctl
```

```bash
duckctl --name <robot-name> info
```

Все команды ниже записаны для установленного варианта. Чтобы запускать из клона, заменяйте начало на `cargo run -q -p duckctl --`.

Раньше инструмент устанавливался как `btctl`. Если `which btctl` ещё находит его, это сборка на момент прежней установки, которая сама уже никогда не изменится:

```bash
cargo uninstall btd --bin btctl
```

<a id="finding-a-robot"></a>
## Поиск робота

```bash
duckctl scan
```

```
1 robot(s) advertising the duck service:
  aa:bb:cc:dd:ee:ff duck-c51b — 192.168.1.42, 1 service(s)  ← DUCK_ROBOT

7 other device(s) in range, not listed. …
```

Показываются только роботы; остальные устройства в зоне радио лишь подсчитываются. `--verbose` раскрывает полный список и полезен, если нужного робота в первом списке нет.

Каждый робот передаёт IPv4, поэтому здесь же находится адрес для SSH. Подключение не создаётся, PIN не нужен. `no address` означает отсутствие сети; полное отсутствие поля адреса означает выпуск до появления адреса в рекламе, и `duckctl wifi status` всё ещё может его показать.

SSID в рекламу не помещается и в списке отсутствует. Его вместе с сигналом и обоими адресами показывает `duckctl wifi status`.

Только адрес:

```bash
ssh microduck@$(duckctl ip)
```

`ip` выводит адрес и ничего больше, поэтому подходит для подстановки. Читает рекламу, не подключается, не требует PIN и занимает около секунды. Ответ свежий: `btd` перечитывает адрес раз в пять секунд и обновляет объявление при изменении.

Можно обойтись без подстановки:

```bash
duckctl ssh
```

```bash
duckctl ssh -- sudo robotctl pad pair
```

`ssh` находит адрес так же, как `ip`, затем превращается в `ssh`: запросы, терминал и код завершения принадлежат самому SSH. Пользователь берётся из `--user`, затем из `DUCK_BOARD_USER` — той же переменной, которую читает [`dev-push.sh`](dev-push.ru.md), поэтому настроенный для отправки сборок ноутбук уже готов, — затем используется `microduck`. Слова после `--` выполняются на роботе вместо открытия оболочки.

Файлы передаются аналогично:

```bash
duckctl scp report.md :/tmp/
```

```bash
duckctl scp :/var/log/robotd.log .
```

Путь с начальным `:` находится на роботе: это обычный `host:path` scp без хоста, который команда находит сама. Остальное передаётся `scp` как написано, включая `-r` и другие флаги; индикатор прогресса и код завершения также принадлежат `scp`. Пользователь определяется как у `ssh`.

Собственные флаги инструмента идут первыми, перед путями:

```bash
duckctl --name ducky scp -r logs/ :/tmp/
```

Копирование совсем без `:` отклоняется до сканирования: это локальная операция без участия робота, о чём вывод `scp` не предупредил бы. Локальный файл, действительно называющийся `:foo`, указывается как `./:foo`.

Сопряжённый с этой машиной робот часто перестаёт рекламировать ей службу. Тогда `ip` подключается и спрашивает `net.status`. Это медленнее и требует PIN, зато даёт ответ. `--verbose` сообщает, какой из двух путей сработал.

При отсутствии сетевого адреса выводится способ исправления, а не пустой ответ: исправлять нужно по радио, поскольку `net.connect` намеренно запрещён через WebRTC.

Ещё не переименованный робот зовётся `duck-` плюс четыре символа из серийного номера, например `duck-c51b`. Если показаны сразу два имени — в macOS это `radxa-zero3 [duck-c51b]`, — любое подходит для `--name`.

Если до первого подключения робот виден как `duck-c51b`, а после только как `radxa-zero3`, его выпуск задавал имя рекламе, но не адаптеру, и клиент закешировал имя адаптера. Обновите робота. Уже накопленный кеш клиента от этого не очистится: выполните `bluetoothctl remove <mac>` на Linux или забудьте робота в настройках Bluetooth macOS.

Без имени — ни `--name`, ни `DUCK_ROBOT` — выбирается первый найденный робот. Если имя задано, два совпадения вызывают ошибку, а не случайный выбор:

```
2 robots answer to "radxa-zero3": radxa-zero3, radxa-zero3
```

Так бывает, если загрузчик платы оставляет серийный номер пустым: имя берётся из hostname, одинакового у всех плат из одного образа. Переименуйте одну на самом роботе и используйте новое имя:

```bash
robotctl system set-name ducky
```

<a id="the-console"></a>
## Консоль

Робот отдаёт страницу с камерой и управлением:

```bash
duckctl open
```

Команда находит робота и открывает `http://<address>:8080/` в браузере. `--print` возвращает URL для скрипта или машины без браузера; `--port` нужен при нестандартном `mediad --web-port`.

Ничего устанавливать и самостоятельно раздавать не требуется: страница встроена в `mediad`, поэтому работающая служба означает наличие консоли.

На странице: камера с битрейтом, частотой кадров, потерями и временем кругового обмена; две сенсорные площадки и клавиши `W`/`A`/`S`/`D`, `Q`/`E` для движения со скоростями геймпада 0.3 m/s и 1.5 rad/s; перетаскивание по картинке для взгляда на точку; enable, init, relax, stop и shutdown; банк голоса в меню и **навыки в меню, заполняемом роботом**. Набор навыков — конфигурация, поэтому страница спрашивает `robot.policies`, а не угадывает список. Рядом поток состояния на 2 Hz и `robot.health`, где называются перегретый сервопривод, разряженная батарея или медленный цикл.

`stop` обнуляет намерения, отправляемые страницей. **Это не аварийный останов:** браузер не отключает питание сервоприводов. Поэтому кнопка выглядит обычной.

Поле сырого JSON, журнал и два вызова, запрещённых участнику WebRTC, находятся в нижней выдвижной панели. Они проверяют применение таблицы маршрутов, а не управляют роботом.

Используются два порта, но вводится только один: страница сама обращается к серверу сигнализации 8443 на хосте, который её отдал. Если страница загрузилась, но сообщает об отсутствии ответа порта сигнализации, робот работает, а путь к 8443 чем-то закрыт, чаще всего межсетевым экраном.

Камера и управление работают только по WebRTC, поэтому без сетевого адреса консоли нет. Сначала подключите робота к сети по радио: описанный ниже `duckctl wifi connect` не требует собственной сети.

<a id="always-the-same-robot"></a>
## Всегда один и тот же робот

Задайте имя в окружении вместо каждой командной строки:

```bash
export DUCK_ROBOT=duck-c51b
```

Чтобы сохранить настройку, добавьте строку в `~/.zshrc`. Все команды ниже работают без `--name`:

```bash
duckctl info
```

`DUCK_PIN` аналогично заменяет `--pin`, необходимый каждой команде для робота с собственным PIN:

```bash
export DUCK_PIN=418299
```

Для отдельной команды другому роботу `--name` имеет приоритет:

```bash
duckctl --name duck-ffff info
```

Чтобы один раз проигнорировать значение по умолчанию, например для чужого робота на стенде, задайте пустую переменную:

```bash
DUCK_ROBOT= duckctl scan
```

`scan` помечает робота из `DUCK_ROBOT` и ставит первым; каждая команда поиска сообщает нужное имя до сканирования.

<a id="identity"></a>
## Идентичность

```bash
duckctl --name <robot-name> info
```

Имя, серийный номер и время работы.

```bash
duckctl --name <robot-name> name <new-name>
```

До 24 символов. Изменение действует через несколько секунд без перезапуска, но Mac продолжает показывать ранее выученное имя, поэтому `scan` и настройки Bluetooth macOS отстают. Все последующие команды используют новое имя.

Переименование не обновляет `DUCK_ROBOT`. Инструмент об этом сообщает; переменную нужно изменить вручную, иначе команды будут искать больше не отвечающее имя.

```bash
duckctl --name <robot-name> reboot
```

<a id="wifi"></a>
## Wi-Fi

```bash
duckctl --name <robot-name> wifi status
```

SSID, сигнал и адреса.

```bash
duckctl --name <robot-name> wifi scan
```

Занимает несколько секунд: робот действительно сканирует радио, а не возвращает старый результат.

```bash
duckctl --name <robot-name> wifi connect <ssid> --psk <passphrase>
```

Для открытой сети опустите `--psk`. Подключение разрывает прежнюю сеть робота, поэтому SSH по Wi-Fi отключится: это штатное действие команды. Ответ может занять до 45 секунд.

```bash
duckctl --name <robot-name> wifi forget <ssid>
```

<a id="is-it-alright"></a>
## Всё ли исправно

```bash
duckctl --name <robot-name> health
```

Здоровье контура управления.

```bash
duckctl --name <robot-name> reboot-motors
```

Восстановление сервопривода после аппаратной ошибки — перегрузки, перегрева, электрического воздействия, — которая иначе удерживает момент выключенным до отсоединения батареи. `health` называет сустав. Добавьте ID, чтобы перезагрузить только выбранные:

```bash
duckctl --name <robot-name> reboot-motors 3 11
```

**Сначала момент снимается со всех суставов**, поэтому удерживайте робота или положите его. После операции он остаётся расслабленным; коэффициенты восстанавливаются при следующей записи. Для подъёма нажмите Start на геймпаде или выполните `duckctl call robot.init`.

```bash
duckctl --name <robot-name> status
```

Согласование версии и состояние обновления.

<a id="which-release-is-it-running"></a>
## Какой выпуск работает

```bash
duckctl --name <robot-name> version
```

Версия API, выпуск и git-ревизия сборки. `revision: null` означает сборку на чьём-то ноутбуке, а не в CI.

<a id="logs"></a>
## Журналы

```bash
duckctl --name <robot-name> logs robotd
```

Последние 40 строк журнала службы за текущую загрузку. Для большего числа и предыдущей загрузки:

```bash
duckctl --name <robot-name> logs robotd -n 200
```

```bash
duckctl --name <robot-name> logs btd --boot -1
```

Доступны `updaterd`, `robotd`, `configd`, `btd`, `padd`, `mediad`, `tofd`, а также `bluetooth` и `NetworkManager`. Суффикс `.service` необязателен; другое имя отклоняется с этим списком.

Строки идут в stdout, остальное в stderr, поэтому работает `logs robotd -n 200 | grep -i panic`. Длинный конец журнала обрезается под возможности радио, сначала самые старые строки, с соответствующим примечанием.

Если выборка пересекает перезапуск, место отмечается:

```
2026-09-09T12:27:20+00:00 systemd[1]: Starting robotd.service - Robot control daemon...
-- new robotd process, pid 3227 --
2026-09-09T12:27:21+00:00 robotd[3227]: control loop running joints=15 hz=50.0 driving=true
```

Это важно после обновления, когда сорок строк могут содержать вывод двух сборок. Всё в `-- … --` добавлено роботом, а не журналом.

Нет `-f`, `--since` и поиска. Для них войдите по SSH:

```bash
ssh microduck@$(duckctl --name <robot-name> ip)
```

```bash
journalctl -u robotd -f
```

<a id="updates"></a>
## Обновления

Те же слова, что в `robotctl update`, поэтому изученная на роботе команда работает и здесь. Все принимают `--component <name>`, по умолчанию `daemon` — пока единственный компонент робота.

```bash
duckctl --name <robot-name> update check
```

```bash
duckctl --name <robot-name> update status
```

```bash
duckctl --name <robot-name> update versions
```

```bash
duckctl --name <robot-name> update log --limit 20
```

Установка длится несколько минут и выводит прогресс:

```bash
duckctl --name <robot-name> update apply
```

```
· daemon: preflight
· daemon: downloading 12%
· daemon: downloading 47%
· daemon: verifying
· daemon: swapping
· daemon: health_gate
{
  "outcome": "applied",
  "from": "0.5.1",
  "to": "0.6.0"
}
note: the robot restarts its daemons now, and `btd` about five seconds after this reply — so this
connection drops. That is the update working. Reconnect and run `duckctl update status`:
`last_attempt` carries the outcome of what just ran.
```

Разрыв соединения после apply означает работающее обновление, а не сбой. Переподключитесь и прочитайте `update status`.

Сборка ветки, конкретная версия или кандидат staging:

```bash
duckctl --name <robot-name> update apply --ref my-branch
```

```bash
duckctl --name <robot-name> update apply --version 0.5.1
```

```bash
duckctl --name <robot-name> update apply --staging
```

`--dry-run` проверяет всё и останавливается до переключения. `--ref` и `--version` — альтернативы; совместное указание отклоняется.

Возврат: предыдущий выпуск или выбранный из `update versions`:

```bash
duckctl --name <robot-name> update rollback
```

```bash
duckctl --name <robot-name> update select 0.5.1
```

Оба проходят тот же контроль, что apply, поэтому не запустившийся вариант откатывается. Ни один ничего не удаляет.

Прогресс обновления, начатого другим человеком или самим роботом:

```bash
duckctl --name <robot-name> update watch
```

Показывает текущий этап и всё последующее. Окончательного ответа не получает, поэтому завершается Ctrl-C.

<a id="the-hugging-face-account"></a>
## Учётная запись Hugging Face

```
duckctl account login
```

Печатает код и открывает <https://hf.co/oauth/device>, где его нужно ввести. Страница Hugging Face не принимает код в URL, поэтому открытие экономит переход, но не ввод. **Ожидает сам робот**; инструмент отключается сразу после печати кода. Подтвердите его в открытом браузере или на другом устройстве, затем:

```
duckctl account status
```

```
duckctl account logout
```

Это тот путь доступа, который работает с роботом, ещё не подключённым к сети: без Wi-Fi нет консоли и LAN, остаётся Bluetooth. Вход через BLE использует ту же процедуру, что мастер настройки.

```
duckctl account login --no-open
```

Возвращает код и URL без браузера. При выводе не в терминал это выбирается автоматически, поэтому скрипт ничего не запускает.

Уже вошедший робот отказывает, называя учётную запись; так же поступает ожидающий подтверждения кода. `--force` заменяет оба состояния, и оставленный код перестаёт работать.

<a id="policies-and-skills"></a>
## Политики и навыки

Какие модели работают в слотах и какие навыки есть у робота:

```bash
duckctl policy list
```

Массив `skills` отвечает на вопрос «что можно попросить у этого робота». Это конфигурация, различающаяся между роботами; заранее предполагаемого списка нет. Прочитайте его до создания кнопок.

Запуск навыка:

```bash
duckctl do roulade
```

**Робот должен быть в режиме движения.** Сначала нажмите Start на геймпаде, иначе ответ объяснит это требование. При этом *ввод* геймпада не нужен: deadman сам обнуляет twist, поэтому неуправляемый человеком робот стоит на месте и выполняет действие.

Смена походки во время работы:

```bash
duckctl policy load walk /opt/robot/policies/current/alpha_walking.onnx
```

Восстановление слота:

```bash
duckctl policy reset walk
```

Один слот за раз, поскольку сетевой вызов принимает один. Сброс всех семи выполняется `robotctl policy reset` на роботе. Путь находится *на роботе* и должен быть абсолютным.

Загрузка отсюда **сохраняется после перезагрузки**, как `robotctl policy load` на роботе: служба записывает слот в `robotd.toml` до переключения. Отмена — `duckctl policy reset <slot>`.

Перечитать все слоты из конфигурации после внешнего изменения:

```bash
duckctl policy reload
```

Робот переходит в домашнюю позу с включённым моментом, загружает и снова управляет; это занимает несколько секунд, учтённых таймаутом. Файл, не соответствующий `obs[1,61] -> actions[1,14]`, отклоняется до изменений; при другой ошибке загрузки сохраняется прежняя политика.

<a id="from-the-hub"></a>
### Из Hub

Что ещё опубликовано для робота и обновился ли официальный комплект:

```bash
duckctl policy search microduck
```

```bash
duckctl policy check
```

Установить новейший официальный комплект либо вернуться через `--version v1`:

```bash
duckctl policy update
```

Скачать чужую модель без запуска:

```bash
duckctl policy fetch RemiFabre/microduck-flamingo-cycle
```

Ответ называет путь сохранения. `load` принимает путь, никогда `org/repo`: здесь скачивание и загрузка — два вызова, тогда как `robotctl` выражает оба одной строкой.

<a id="giving-it-a-name"></a>
### Назначение имени

`fetch` скачивает файл; следующий шаг превращает его в действие для `robot do`:

```bash
duckctl policy skill polite-bow --path /var/lib/robot/policies/fffiloni/microduck-polite-bow-b1d864/main/policy.onnx --duration 4
```

```bash
duckctl do polite-bow
```

Один вызов: робот записывает конфигурацию и перечитывает её, без перезапуска процессов. `--duration` обязателен впервые и затем сохраняется, поэтому для изменения поля достаточно передать только его:

```bash
duckctl policy skill polite-bow --command 1,0,0
```

`--command` — twist, подаваемый сети во время выполнения. Обычно нули, если политика не интерпретирует twist иначе; у flamingo это `[flag, side, 0]`. `--unwind` и `--unwind-s` возвращают из политики, удерживающей состояние до внешней команды.

Доступные действия и их тайминги:

```bash
duckctl policy skills
```

`built_in` в ответе называет `ground_pick` и `sit_toggle`, которые также принимает `robot do`, но ими управляет сам робот, и они не являются записями таблицы.

```bash
duckctl policy unskill polite-bow
```

Навык, поставляемый выпуском робота, после удаления вернётся: удаляется только переопределение.

Опубликованное незнакомым автором никто не проверяет. Безопасность попытки обеспечивают проверка манифеста до скачивания, формы тензоров при загрузке, ограничения суставов и реакция на падение, а не описание. Первый раз установите робота на подставку.

<a id="which-button-runs-which-skill"></a>
## Какая кнопка запускает какой навык

```bash
duckctl pad bindings
```

```bash
duckctl pad bind x polite-bow
```

```bash
duckctl pad reset x
```

**Ничего не перезапускается и больше ничего не нужно:** `padd` перечитывает файл в течение секунды. Имя сначала проверяется по навыкам этого робота, поэтому опечатка даёт отказ со списком настоящих имён, а не неработающую кнопку.

Список отмечает два факта, которых клиент сам не знает: `overridden` показывает пользовательские изменения без знания значений по умолчанию; `error` — кнопку, связанную с уже отсутствующим навыком. Реалистичная причина последнего — удаление навыка, а не опечатка.

`""` отключает кнопку; это отличается от `pad reset`, возвращающего поставляемое назначение. Настраиваются пять кнопок: `a`, `x`, `lb`, `rb`, `dpad_down`. `lb`/`rb` — **бамперы**, поскольку аналоговые курки управляют клювом и кряканьем.

Сопряжение — другое пространство имён и другая служба: `pad.pair` и `pad.forget` принадлежат `configd` и доступны через `call`. Эти две команды относятся к `robotd`, поскольку для проверки имени нужен список навыков.

<a id="anything-else-call"></a>
## Остальное: `call`

<a id="anything-else--call"></a>
```bash
duckctl --name <robot-name> call <method> '<json-params>'
```

Параметры по умолчанию `{}`. Следующие вызовы доступны по Bluetooth, но не имеют отдельных обёрток; здесь опущен префикс `duckctl --name <robot-name>`:

| | |
|---|---|
| `call system.services` | Какие службы работают и какой выпуск у каждой. |
| `call pad.status` | Сопряжён ли геймпад и подключён ли он. |
| `call pad.pair '{"timeout_seconds":30}'` | Сопрячь геймпад, находящийся в режиме сопряжения. |
| `call pad.forget '{"mac":"<address>"}'` | Удалить сопряжение. |

`call` ждёт ответ 60 секунд. Команды обновления выше ограничивают *тишину* — три минуты без единого сообщения, — поэтому обновление нужно выполнять ими, а не `call update.apply`.

<a id="global-options"></a>
## Глобальные параметры

- `--name <robot-name>` — нужный робот. Без него используется `DUCK_ROBOT`, без неё — первый найденный. Лучше указывать всегда: это пропускает медленный резервный уровень, перебирающий все уже подключённые периферийные устройства Mac, включая наушники.
- `--pin <six-digits>` — по умолчанию `DUCK_PIN`, затем `000000`. Настоящий PIN показывает `robotctl system pin` на роботе.
- `--verbose` — печать каждой отправленной и полученной строки; `scan` показывает все устройства вместо одних роботов. Первый флаг для добавления при зависании.

<a id="what-it-prints"></a>
## Вывод

Ответы идут в stdout как форматированный JSON, всё остальное — прогресс, диагностика, увиденное радио — в stderr. Исключение — `logs`, печатающий строки как строки, поскольку экранированный JSON журнала нечитаем; отказ этой команды всё равно выводится JSON. Поэтому `duckctl ... info > reply.json` разделяет каналы, а ошибка JSON-RPC от робота всё равно даёт ненулевой код завершения. Строки прогресса начинаются с `·` и занимают одну строку; `update apply > outcome.json` оставляет их на экране, сохраняя итог в файл.

Одна команда — одно соединение: поиск робота, сопряжение при необходимости, подтверждение PIN, запрос и отключение.

Команды завершаются после периода тишины, а не фиксированного общего времени: медленное обновление не обрывается, а переставший отвечать робот обнаруживается за секунды. *Разрыв* связи сообщается сразу, без ожидания; после apply объясняется, что соединение оборвал перезапуск. Выполняющееся обновление переживает оба случая: робот сам скачивает данные и продолжает без наблюдателя, а последующий `update status` сообщает результат.

<a id="what-is-refused"></a>
## Что запрещено

Дистанционное непрерывное управление (`robot.move`, `robot.head`, `robot.look`, `robot.pose`, `robot.mouth`), аварийная команда остановки (`robot.stop`), снятие удержания суставов (`robot.relax`), высокочастотная телеметрия (`robot.subscribe`), две требующие осознанного решения команды обновления (`update.pin`, `update.resetToGolden`) и PIN сопряжения (`system.pairingPin`, `system.setPairingPin`) отклоняются самим `btd` и не доходят до служб. Ответ — код 14, «not available over Bluetooth».

`robot.do`, `robot.init`, `robot.enable`, `robot.rebootMotors` в список **не входят**, хотя все четыре двигают робота. Непрерывное управление — поток пятидесяти малых обновлений в секунду, который не помещается в бюджет уведомления 20 байт; каждое из этих действий — один запрос. `robot.relax` остаётся запрещённым по другой причине: единственный результат — робот, который держался сам, перестаёт держаться.

Это граница безопасности, а не недостающая возможность. Обоснование каждого отказа находится рядом в `btd/src/route.rs`; проектирование — [`app-path-design.md`](../design/app-path-design.ru.md) §3.1. Эти команды выполняются через `robotctl` на роботе.

<a id="when-it-cannot-find-the-robot"></a>
## Робот не находится

```bash
duckctl --verbose scan
```

Пустой список, даже без наушников, указывает на Mac, а не робота: Bluetooth выключен либо терминалу не предоставлено разрешение Bluetooth.

Список без робота указывает на робота. Он передаёт имя в scan response, который можно отдельно пропустить, поэтому устройство без имени и служб вполне может быть роботом; `--name` всё равно попробует подключиться. Если macOS показывает пару, но connect или первое чтение зависает, сопряжение не завершено:

```bash
sudo pkill bluetoothd
```

Удаление робота из настроек Bluetooth macOS делает то же. На самом роботе `journalctl -u btd -b` показывает, зарегистрировалось ли вообще приложение GATT.
