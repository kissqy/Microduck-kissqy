# Рекуррентные политики ONNX

Среда выполнения поддерживает политики прямого распространения и экспорт LSTM с явным состоянием, создаваемый mjlab/rsl_rl. Оба варианта получают существующее наблюдение размерности 61D и выдают те же 14 исходных управляющих действий для суставов на частоте 50 Hz. Нормализация наблюдений должна быть встроена в экспортируемую модель.
Критик, используемый при обучении, на робота не переносится. Поддержка рекуррентности не добавляет датчиков или фильтрации действий.

<a id="model-contract"></a>
## Контракт модели

Все тензоры имеют тип float32. Входы и выходы сопоставляются по именам независимо от порядка.

| Модель | Входы | Выходы |
| --- | --- | --- |
| Прямого распространения | `obs [1, 61]` | Один выход `[1, 14]` (существующие имена выходов остаются допустимыми) |
| LSTM | `obs [1, 61]`, `h_in [layers, 1, hidden]`, `c_in [layers, 1, hidden]` | `actions [1, 14]`, `h_out [layers, 1, hidden]`, `c_out [layers, 1, hidden]` |

Размерность пакета может быть символической; инференс всегда выполняется для одного робота. Число слоёв и ширина скрытого состояния должны быть положительными статическими размерностями, одинаковыми у всех четырёх тензоров состояния.
Размер каждого состояния ограничен 1,048,576 элементами. Неподдерживаемые имена, ранги, типы, ширины и лишние тензоры вызывают ошибку при загрузке. Прогрев также отклоняет некорректные или нечисловые и бесконечные выходные значения.
GRU и другие сигнатуры экспорта рекуррентных моделей не реализованы.

Публикуйте рекуррентные политики с **`model_api: 2`**, чтобы старые службы отклоняли их до установки. Эта служба также поддерживает существующие модели прямого распространения с API 1. Схема манифеста и размерности наблюдений и действий не меняются.

<a id="memory-lifetime"></a>
## Время жизни памяти

Каждая загруженная политика владеет заранее выделенными тензорами скрытого состояния и состояния ячеек. После каждого успешного инференса оба новых состояния копируются в эти буферы. Неудачный инференс очищает память; нечисловые и бесконечные выходы отклоняются до фиксации любого из состояний. Состояние, полученное при прогреве, отбрасывается.

Память обнуляется при первой активации, переключении сети (в том числе обратно), явном отключении, сбросе контроллера после паузы или восстановления после падения, а также при повторном запуске цепочки навыка. Краткие пропуски данных датчиков обрабатываются в рамках существующего льготного периода возобновления. Изменение команды в активной сети сохраняет память.

Замена неактивного слота сохраняет память активной сети только тогда, когда её ONNX-файл имеет прежний SHA-256. Изменённая активная модель начинает с чистого состояния, даже если путь файла остался тем же.
Для этой гарантии используйте самодостаточные ONNX-файлы: внешние файлы весов не входят в хеш самого ONNX. Явный сброс контроллера всегда очищает все слоты.

Существующее масштабирование действий и необязательные фильтры среды выполнения сохраняют свои настройки. Если политика обучалась без фильтрации действий, отключите эти фильтры в настройках развёртывания; добавление рекуррентности не делает несовместимую конфигурацию фильтров корректной.

<a id="offline-rehearsal-and-board-timing"></a>
## Проверка без оборудования и измерение времени на плате

Пример использует рабочий Rust-код инференса и никогда не открывает шину двигателей:

```sh
export ORT_DYLIB_PATH=/path/to/libonnxruntime.so
cargo run --release -p duck-control --example policy-rehearsal -- policy.onnx > rehearsal.json
```

Он прогревает актор, очищает состояние, затем измеряет 1,000 проходов инференса с номинальной гравитацией, нулевыми командами и обратной связью по предыдущему действию. JSON содержит задержки p50/p95/p99/max, число превышений 20 ms и действия. Для оценки времени на роботе запустите собранный пример **на Radxa**; измерения на компьютере разработчика не подтверждают соблюдение временного бюджета робота.
В эти времена не входят чтение датчиков, запись команд двигателям и задержки планировщика.

Для детерминированного многошагового сравнения с PyTorch или Python ONNX Runtime передайте вторым аргументом JSON-массив записей:

```json
[{"obs": ["replace with exactly 61 numbers"], "reset": true}]
```

Каждая запись содержит полное наблюдение, включая предыдущие действия. На границах эпизодов задавайте `reset`. Сравнивайте полученную последовательность действий с эталоном при одинаковых наблюдениях и сбросах. Такая проверка охватывает инференс и работу с памятью, но не физический перенос sim2real. Экспортируйте обученные контрольные точки нормализованным экспортёром из репозитория обучения.

<a id="tests"></a>
## Тесты

```sh
cargo test -p duck-control
# Requires ONNX Runtime >= 1.23:
cargo test -p duck-control --test recurrent_policy -- --ignored
cargo test -p robotd recurrent_memory_resets_with_controller_feedback -- --ignored
```

Небольшие тестовые модели в репозитории используют настоящий оператор ONNX LSTM. Они проверяют непрерывность памяти, сбросы, переключение политик, выбор резервного варианта, прогрев, горячую замену, динамическую размерность пакета, некорректные контракты и нечисловые/бесконечные состояния. Для повторной генерации выполните `python duck-control/tests/fixtures/generate.py` в окружении с `onnx` и `numpy`.
