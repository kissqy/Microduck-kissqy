# Microduck R17 v1.0.150 — 重启后的启动与手柄恢复

本版基于 v1.0.149，原生固件 build 为 `1fa8438-feetech-ft6-control.31`。

## 故障定位

2026-10-08 的失败记录明确显示 `Feetech ID 200 response timeout`、`configuration_error`、控制周期数 0、初始化只尝试 1 次。原版初始化失败后结束控制线程，IPC 与声音仍可响应，导致“能叫但 HOME、行走不工作”。后两份记录的 IMU 与约 50 Hz 循环正常；日志不足以认定 IMU 损坏或确定 Zero 重启的电源原因。

原 padd 选择首个枚举手柄，可能选到被 GameSir 桥独占的实体输入节点。手柄断线后还会保留头部或身体姿态模式，使摇杆继续发送零行走速度。

## 修复范围

- 仅在启动时最多尝试 5 次，失败间隔 400 ms，复用同一 UART。先写寄存器 40 卸力并回读 15 个舵机，再等待 IMU 身份及原有寄存器检查；未确认卸力不继续，不写增益或目标。
- 启动未完成或已经失败时，HOME、策略启用与运动技能明确拒绝，恢复后需重新按键。失败按键不延后执行，重新连接不自动 HOME 或开始运动。
- 真实 GameSir 使用其虚拟 Xbox 节点；精确排除被桥独占的实体 Nova 2 Lite 节点，保留其他原生手柄和网页手柄。
- 手柄断开或切换后清除旧输入模式与保持状态；异常机器人 socket 回执会退出，使用现有 padd 服务恢复路径。
- 固件重启操作复用原有有限就绪确认，控制循环未启动时不再报成功。检查仅发生于管理操作，没有新增常驻巡检。

保持正常 50 Hz 控制、模型文件、缩放与滤波、舵机 P/D、速度与加速度、标定、HAT 固件、原 R17 界面以及 GameSir 桥映射。

## 安装

关闭旧中控，完整解压 `Microduck-Console-R17-v1.0.150.zip`，照常启动并连接 Zero。在原“系统维护 → 随包固件”安装一次本版配套固件。无需重装系统或恢复默认设置。

核对中控版本 `1.0.150` 与运行 build `control.31`。机器人保持卸力，扶稳后再按原 HOME → 保持 → 行走流程操作。

## 验证与当前状态

构建与测试结果记录在随包清单及源码的 `verification/recovery150.json` 中。离线验证不代表真机重启、蓝牙无线稳定性或温度已经验证。

当前保留的 Known-Good 基线是 v149 的模型、参数、机械与通信配置；v150 恢复修复等待真机确认。下一步唯一主任务是验证一次正常重启后的初始化及手柄重新进入 HOME；若仍失败，记录具体启动错误，不再用重装系统掩盖。
