# Исправление повторной записи загрузочной конфигурации Armbian

`scripts/repair-armbian-env.py` — отдельная утилита обслуживания для исправления подтверждённой ошибки скрипта аппаратной оптимизации Armbian 26.2.1. Она не требует обновления системы или переустановки прошивки робота, не запускает службу аппаратной оптимизации, не перезагружает систему и службы робота и не отправляет команды движения. Исправление используется при следующей обычной загрузке.

Это необязательное исправление из исходников. Опубликованный пакет V167 из-за него не изменён; установка старого выпускного пакета не добавляет исправление автоматически.

<a id="问题与范围"></a>
## Проблема и область применения

Старая версия `add_usb_storage_quirks()` при каждой загрузке несколько раз обрабатывает `/boot/armbianEnv.txt` через `sed -i`, затем удаляет и дописывает `usbstoragequirks=`, а в конце запускает фоновый `sync &`.
Даже без USB-накопителей и при неизменных параметрах весь загрузочный конфигурационный файл перезаписывается.

Во время одного сбоя Radxa ZERO 3W / Armbian 26.2.1 U-Boot увидел файл размером 0 байт, после чего использовал неверный путь дерева устройств по умолчанию и не смог загрузиться. После ручного запуска Linux файловая система воспроизвела журнал, и конфигурация восстановилась полностью. Это соответствует незавершённой транзакции файловой системы, но не доказывает, что единственной причиной была какая-то конкретная запись или событие питания.
Upstream Armbian также добавил защиту в этот процесс записи; см. [скрипт аппаратной оптимизации](https://github.com/armbian/build/blob/main/packages/bsp/common/usr/lib/armbian/armbian-hardware-optimization).

Утилита распознаёт только подтверждённую старую USB-функцию и собственное исправление. При другой версии системы, изменениях upstream или пользовательской функции она явно сообщает об ошибке и сохраняет файл как есть. Она не пытается угадать совместимость заменой всего системного скрипта.

<a id="使用"></a>
## Использование

Скопируйте из исходников `microduck-hd1910/firmware/scripts/repair-armbian-env.py` на плату, например в `/tmp/repair-armbian-env.py`. Нужен только этот файл; зависимости — имеющиеся в системе Python 3.9+, Bash и GNU coreutils. Для перечисления USB по-прежнему используется `lsusb`, от которого зависит исходный системный скрипт.

Сначала выполните проверку только для чтения:

```bash
python3 /tmp/repair-armbian-env.py --check
```

- `needs-fix`: найден известный старый вариант, можно применить исправление ниже.
- `already-fixed`: такое же исправление уже установлено; повторные изменения не нужны.
- `not-applicable`: скрипт аппаратной оптимизации Armbian отсутствует.
- Неизвестная функция или способ её вызова: ненулевой код завершения; проверьте системный скрипт и не заменяйте его принудительно.

Исправление:

```bash
sudo python3 /tmp/repair-armbian-env.py --apply
```

Утилита сначала проверяет синтаксис Bash, сохраняет исходный скрипт, текущую загрузочную конфигурацию и запись хешей в `/var/backups/microduck-armbian-env/<время-и-случайный-суффикс>/`, синхронизирует их на диск, затем атомарно заменяет скрипт аппаратной оптимизации. Поле `backup` выходного JSON содержит каталог этой резервной копии. Сама загрузочная конфигурация не меняется; исходный владелец и права сохраняются. Пустую загрузочную конфигурацию необходимо восстановить заранее: утилита не считает пустой файл корректной конфигурацией и не продолжает исправление.

После исправления USB-параметры сначала вычисляются в `/tmp`. При одинаковом содержимом загрузочная конфигурация не затрагивается. Только при изменении в `/boot` создаётся временный файл, полностью записывается, синхронизируется, атомарно подменяет исходный файл, после чего синхронизируется файловая система. Функция выполняется в переднем плане, поэтому служба не сообщает об успехе до завершения синхронизации или при ошибке. Другие функции аппаратной оптимизации остаются как есть.

Установка утилиты не добавляет systemd drop-in; имеющееся исправление с последующей синхронизацией можно сохранить. Это не абсолютная гарантия защиты при отключении питания и не средство исправления неисправного носителя или аппаратной части питания.

<a id="回退"></a>
## Откат

Замените каталог в примере на путь `backup`, выведенный при исправлении:

```bash
sudo python3 /tmp/repair-armbian-env.py --restore /var/backups/microduck-armbian-env/<备份目录>
```

Откат восстанавливает только исходный скрипт аппаратной оптимизации, но не старую загрузочную конфигурацию. Утилита проверяет хеши резервной копии и отказывается перезаписывать системный скрипт, если после исправления его изменил пакет или пользователь. Обновление пакета может заменить локальное исправление; после обновления повторите `--check` и проверьте скрипт upstream. Не перезаписывайте неизвестную новую версию автоматически.

<a id="验证"></a>
## Проверка

Выполните в каталоге `microduck-hd1910/firmware`:

```bash
python3 -m unittest discover -s scripts/tests -p test_repair_armbian_env.py -v
```

Linux выполняет все тесты; macOS пропускает тесты загрузочной функции, зависящие от GNU coreutils. Из корня репозитория их можно выполнить изолированно в существующем Linux-образе Python без подключения робота:

```bash
docker run --rm --network none -e PYTHONDONTWRITEBYTECODE=1 \
  -v "$PWD:/src:ro" -w /src/microduck-hd1910/firmware \
  python:3.12-slim-bookworm \
  python3 -m unittest discover -s scripts/tests -p test_repair_armbian_env.py -v
```

Тесты охватывают повторную запись старого скрипта, идемпотентность исправления, сохранение USB-правил и остальных полей загрузки, владельца и прав, сбои частичной записи/синхронизации/подмены, отказ заменять неизвестную функцию, резервное копирование и защищённый откат. Конфигурация, перечисление USB и файлы параметров ядра представлены временными копиями; испытания с физическим отключением питания и полная проверка загрузки после исправления не выполнялись.

USB-функция и её фрагменты в тестах сохраняют лицензию Armbian GPL-2.0-only; см. [`scripts/licenses/GPL-2.0.txt`](../../scripts/licenses/GPL-2.0.txt).
