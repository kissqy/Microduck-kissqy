# R17 v1.0.157-Fix6

本版按 robotd 优先的顺序安装并接入。原生程序仍为 control.36，模型权重与 50 Hz 控制代码不变。须安装本版随包固件一次，以更新 Zero 上的安装脚本及手柄启动配置。

## 安装顺序

1. 关闭旧 robotd 数据和启动状态连接，清除网页旧输入。在条件变量上等待本次安装结果，安装期间不轮询 socket。
2. 创建随机暂存目录，上传、比较字节数和 SHA256、解压，检查 AArch64 可执行文件与推理库完整性。保留上传进度和各步失败原因。
3. 读取并生成本机参数与标定，停止旧输入，提交松开请求并由 systemd 停止旧 robotd，逐文件原子替换固件。写入本版主服务配置，不扫描、备份或清理旧启动钩子。
4. 首次安装需要的音库文件和音频参数在 robotd 读取配置前准备；系统 ALSA 和音量设置留到主服务就绪之后。已有有效音库和配置不重复生成或写入。
5. systemd 启动 robotd。安装脚本通过已有 startupSubscribe 接收一次订阅的变化事件，不发送 busStatus 就绪查询、不访问串口、不写就绪状态文件。等待最多 60 秒；失败保留原始阶段原因和 journal，观察者不会停止或重启 robotd。
6. 四步全部成功才通知 PC 接入实时数据：1/4 配置、锁、IPC 与控制线程；2/4 硬件初始化及第一份有效关节与 IMU；3/4 模型与推理运行时；4/4 首个控制周期。仅第 4 步成功不能代替前面步骤。失败时保留状态，不自动重试安装或重复接入。
7. 四步成功后安装 R7 输入桥、官方 padd 配置及开机启用设置，重载输入配置并启动本版输入服务。手柄配置或启动失败只报告手柄失败，已经运行的 robotd 保持独立。停止旧输入失败不会使首次安装的新输入永久跳过启动。
8. 系统音频设置、尚未完成的自动更新/golden 禁用配置放到最后。已安装的禁用配置不重复执行；未成功的项在下一次用户安装时重新处理。安装脚本和 PC 各自清理自己的临时目录；失败也清理，清理错误不替换安装根因。

IPC 由 robotd 自己在第一步创建，早期连接只接收启动事件。实时 rawSubscribe 在四步完成后建立。普通 SSH 连接同样先订阅启动状态，确认四步后才接实时数据；建立新数据流时复用现有 SSH 转发，随后关闭启动状态订阅，删除原来的额外启动监听线程。独立 ToF 路径保持原流程。

## 开机与日志

GameSir 和 padd 的服务启动命令先运行短暂事件等待程序；四步完成后用 exec 替换为原生桥接程序或 padd，不保留常驻等待进程。等待 IPC 创建使用 inotify，等待阶段不轮询文件或串口。等待失败返回 78，由 RestartPreventExitStatus 阻止辅助服务反复启动；不添加 robotd 的 Wants/Requires 或逆向重启依赖。设备热插拔和实体/网页互斥仍沿用已有内核事件。Type=exec 的 active 可能表示等待程序已启动；是否真正就绪以 robotd 四步与设备反馈为准。

步骤日志记录成功或失败及原因，等待状态仍用于页面提示。安装中的启动事件由中控统一输出四步日志，JSON 仅作内部传输；接入实时流不清除已收到的四步结果。同一实例的进程核对共享一次读取，旧网页请求返回后不能覆盖新实例。模型日志列出实际模型名称，并明确未配置的槽位；这项读取是目录配置查询，不代表额外启动五份推理。

保留 Fix5 的顶部 SSH 模块、自己的连接状态行、远端 POSIX 路径修复，以及删除实时画面/日志暂停显示后的行为。

## 验证

本版通过 151 项 Python 检查和 10 组浏览器逻辑脚本，覆盖启动订阅、等待/失败/超时、IPC 创建事件、开机 exec、安装顺序、后续输入失败、上传校验与清理、进程查询并发合并、旧请求失效、音库与系统设置分阶段、原子文件替换和现有控制门禁。Linux socket 创建事件测试使用实际 inotify；需要时仅在测试的 OS socket 边界替换传输。

校验原生源码、7 个可执行/推理库文件和随包模型与 Fix5 一致；校验 ZIP、固件 tar、源码 tar 所有文件并通过生产固件导入器。未连接机器人实机，未进行原生 Windows 或浏览器像素验证，也未重跑 Rust 原生历史测试。
