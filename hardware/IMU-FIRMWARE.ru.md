# Прошивка IMU FT6: скачать, записать и проверить

**Вновь собранному IMU корпуса нужна собственная прошивка STM32. Текущая конфигурация Feetech HD1910 использует FT6. Уже запрограммированный IMU, работающий правильно, перепрошивать не нужно.** Эта прошивка читает реальную угловую скорость и объединённую ориентацию LSM6DSV16X и передаёт их службе управления ZERO по шине Feetech.

**У проекта IMU есть варианты разъёмов EH2.5 и AMP2.0.** [Оба проекта](README.ru.md) · [Версия AMP2.0](AMP2.0-VERSION.ru.md). Оба используют одинаковую распиновку J2 SWD.

## Выбор правильного файла

| Компонент | Куда записывается | Текущая версия проекта |
| --- | --- | --- |
| **Прошивка IMU `.bin`** | В **STM32G031F8P6** отдельного IMU через ST-LINK / SWD | **FT6_SYNC15_UART_IRQ_v1** |
| Служба робота ZERO `.tar.gz` | В Linux на Radxa ZERO 3W, устанавливается через консоль или SSH | control.43, в паре с R17 V167 |
| Образ системы `.img.xz` | На microSD ZERO | Public Image R1, предустановленная control.40 |

**Запись образа системы или обновление служб ZERO через консоль не программирует внешний IMU.** Проект PCB сохраняет аппаратное имя `imu_to_dxl_RevA_V1`; для Feetech HD1910 выбирайте приведённую ниже прошивку **Feetech FT6**.

## Запись через ST-LINK

Подготовьте ST-LINK, провода и [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html) от ST. Инструкция относится к плате RevA по ссылке выше.

<a id="1-接-imu-板的-j2swd-15"></a>
<a id="1-connect-j2-swd-15"></a>
### 1. Подключение J2 (SWD 1×5)

Номера контактов взяты из **цепей PCB проекта от 7 октября 2026 года**. Найдите маркировку площадки 1, не определяйте лево / право по фотографии наугад.

| Контакт J2 | Сигнал платы | Сигнал ST-LINK |
| --- | --- | --- |
| **1** | **3V3** | Опорное напряжение целевой платы VTref / VAPP; плате нужен стабильный источник 3.3 V |
| **2** | **SWDIO** | SWDIO |
| **3** | **GND** | GND |
| **4** | **SWCLK** | SWCLK |
| **5** | **NRST** | NRST / RESET |

**VTref — опорное напряжение, этот контакт не обязательно питает плату.** По руководству вашей модели ST-LINK отличайте вход опорного напряжения от выходов питания. J2 3V3 связан с питанием MCU; подавать на него 5 V нельзя. Соединяйте при отключённом питании, при программировании используйте один определённый источник питания и оставляйте шину сервоприводов отключённой.

<a id="2-连接并写入"></a>
<a id="2-connect-and-program"></a>
### 2. Подключение и программирование

1. Подключите ST-LINK к компьютеру и подайте питание на IMU. Откройте STM32CubeProgrammer, выберите **ST-LINK → SWD → Connect** и убедитесь, что обнаружен STM32G031.
2. На панели программирования выберите `imu_to_feetech_ReVA_FT6_SYNC15_UART_IRQ_v1.bin`.
3. Установите **Start address / Address = `0x08000000`**, включите **Verify after programming** и нажмите **Start Programming**. Файл `.bin` не содержит адреса, поэтому его нужно указать.
4. Убедитесь, что программирование и проверка успешны. Отключите соединение, выключите питание, отсоедините ST-LINK и снова включите плату для запуска.

Процедура следует [инструкции ST по программированию внутренней flash](https://dev.st.com/stm32cube-docs/prog/2.23.0/en/docs/markup/CubeProg_UserManual/Memory_programming_and_erasing.html). Альтернативно, если установленный CLI доступен в PATH, выполните запись и проверку этой командой, затем выключите и включите питание как в шаге 4:

```sh
STM32_Programmer_CLI -c port=SWD -w imu_to_feetech_ReVA_FT6_SYNC15_UART_IRQ_v1.bin 0x08000000 -v
```

В Windows исполняемый файл называется `STM32_Programmer_CLI.exe`. См. [справочник команд ST](https://dev.st.com/stm32cube-docs/prog/2.23.0/en/docs/markup/CubeProg_Command_Lines.html).

## Проверка работы

Оставьте крутящий момент робота отключённым, подключите IMU к шине Feetech через HAT и просмотрите данные IMU соответствующими службами ZERO и консолью V167. Во время этих проверок не включайте стояние и ходьбу.

| Проверка | Ожидаемый результат |
| --- | --- |
| Программирование | И запись, и Verify в STM32CubeProgrammer успешны |
| Идентификация шины | ID 200, 1 Mbps; старшая версия идентификатора протокола 6 |
| Данные датчика | При медленном вращении или наклоне IMU меняются угловая скорость и ориентация; в покое выборки продолжают обновляться |
| Связь | После прогрева IMU готов, нет постоянных ошибок связи или устаревших данных |
| Светодиод | Две вспышки при запуске; в исправном состоянии и простое может быть выключен; очень короткие импульсы активности при успешных ответах со свежими данными; постоянно включён при ошибке инициализации или длительном отсутствии новых данных ориентации |

Текущее поведение светодиода FT6 определяют [`main.c`](../microduck-hd1910/firmware/firmware/imu-source/src/main.c) и [`ft_led_status.c`](../microduck-hd1910/firmware/firmware/imu-source/src/ft_led_status.c). Для окончательной проверки используйте фактические данные датчика, готовность и состояние связи.

| Симптом | Что проверить сначала |
| --- | --- |
| STM32 не обнаружен | Питание платы 3.3 V, общую землю, номера контактов J2, SWDIO / SWCLK, NRST и драйвер ST-LINK |
| Запись успешна, но хост не читает IMU | Бинарный файл FT6, проводку и питание шины, скорость 1 Mbps и отсутствие другого устройства с ID 200 |
| Ответы поступают, но ориентация застыла / светодиод постоянно горит | Пайку LSM6DSV16X, питание, соединения SPI и реальные данные датчика; сам ответ не доказывает работоспособность датчика |
| В конфигурации указано `feetech-ft5` | Это сохранённое для совместимости имя пути; само по себе оно не означает старую прошивку. См. руководство протокола FT6 ниже |

## Текущие исходники и сборка

Для обычной сборки запишите указанный выше `.bin` без компиляции. Точка входа для разработчика — [`Makefile.feetech`](../microduck-hd1910/firmware/firmware/imu-source/Makefile.feetech). Инструменты и зафиксированные зависимости перечислены в [сборке прошивки IMU](../microduck-hd1910/docs/BUILD.ru.md#imu-stm32); подробности протокола — в [протоколе и совместимости FT6](../microduck-hd1910/firmware/firmware/imu-source/README_FT6_SYNC15.ru.md). Быстрый блок начинается с адреса 56, имеет 15 байт; ID 200 идёт первым в Sync Read. По адресу 124 сохранён диагностический блок 20 байт.
