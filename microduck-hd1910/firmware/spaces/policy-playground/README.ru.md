# Площадка политик управления microduck

Войдите в учётную запись, разбудите утку, нажмите трюк. Он загрузится из Hub на утку и исполнится; карточка показывает текущий этап.

**Не редактируйте этот Space напрямую.** Исходники находятся в `spaces/policy-playground/` репозитория `pollen-robotics/microduck`; публикует их сюда `scripts/publish-space.sh`.

<a id="working-on-it"></a>
## Разработка

```bash
cd spaces/policy-playground/web && npm install
```

```bash
npm run dev
```

Это настоящая страница с настоящими Hub и rendezvous. Для входа нужно OAuth-приложение, чей redirect URI точно равен адресу разработки; передайте его:

```bash
open "http://localhost:5173/?client_id=<an app registered for localhost:5173>"
```

Сборка пишет самостоятельный `index.html` рядом с `Dockerfile`:

```bash
npm run build
```

Файл коммитится: `publish-space.sh` публикует *верхний уровень* каталога Space — файлы, не деревья, — а bundler создаёт `assets/`. Встраивание сохраняет те же четыре файла, что у консоли: страница, Dockerfile, entrypoint, карточка. На Hugging Face ничего не собирается, поэтому скрытой причины падения сборки там нет.

<a id="why-it-is-a-browser-and-not-a-python-container"></a>
## Почему это браузер, а не контейнер Python

Версия Gradio по-прежнему опубликована и работает; все её сложные проблемы происходили от исполнения клиента в дата-центре:

- **Rendezvous отказывал.** `requests` подписывает запросы `python-requests/2.x`, что край Hugging Face принимает за бота. Из контейнера Space первый `GET /api/robot-status` получал `429`, HTML и `server=awselb/2.0`; до сервиса запрос не доходил. Браузер отправляет адрес и подпись самого посетителя.
- **Все посетители делили одного робота.** Сессия жила в глобальном объекте модуля: globals принадлежат процессу, а Space — один процесс. Здесь каждый посетитель — свой браузер, изоляция сессий бесплатна.
- **`aiortc`, `av`, патч DTLS-шифра, `PyGObject`** давали Python стек WebRTC. В браузере он уже есть.
- **Серверный рендеринг** ставил перед страницей Node-прокси, прекращавший работу через десять секунд без traceback.

Здесь этих проблем нет. `microduck-console` устроен так же и никогда их не имел.

<a id="who-it-is-for"></a>
## Для кого это

Для десятилетнего ребёнка с уткой. Это ограничение всей страницы, а не внешнего оформления: на ней нет методов, транспорта, сокетов и схем. У трюка есть имя, предложение о действии и одна кнопка.

Четыре вызова — `policy.fetch`, `robot.setSkill`, `robot.policies`, `robot.do`, их линия передачи и причины отказа живут внизу в **What just happened?** («Что сейчас произошло?»). Туда идут при поломке, а не ради поклона утки.

<a id="the-parts"></a>
## Состав

`src/rendezvous.ts` — перенос `spaces/shared/wire.py`: `GET /events` для потока, `POST /send` для остального, envelope `peer` с `rpc` — вызов управления. В заголовке описаны четыре неочевидных свойства протокола, выясненных ещё в Python-версии и по-прежнему верных.

`src/hub.ts` выполняет те же два запроса, что `updater/src/policy.rs`: `?search=microduck`, затем `manifest.json` каждого результата. Поэтому галерея и `policy.search` не расходятся. Каждое поле ниже репозитория — утверждение издателя, которое лишь отображается. Устанавливаемое определяется собственным чтением скачанного манифеста на роботе.

`src/auth.ts` реализует PKCE; client id подставляется в страницу `entrypoint.sh`, а не платформой. Dockerfile консоли описывает, что задокументированная инъекция вместо этого делала целый день: ничего.

<a id="what-a-press-does"></a>
## Что делает нажатие

    получение → установка на утку → ожидание утки → исполнение

**«Ожидание утки» необходимо.** Установка трюка вызывает перезагрузку модели, робот возвращается в стоячую позу и до прибытия отказывается действовать. Без ожидания нажатие установки получило бы отказ, трюк тихо не выполнился бы. Ждать нужно `homed` из `robot.policies` (`API_VERSION` 30). Слишком старая утка не публикует флаг, поэтому ждать нечего.

Пока нажатие исполняется, остальная страница неактивна. Утка делает одно действие за раз; второе принятое нажатие обещало бы невыполнимое.
