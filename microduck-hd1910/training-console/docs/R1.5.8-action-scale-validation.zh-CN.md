# R1.5.8 · 动作系数与目标滤波

以R1.5.7滤波实现为基础，修正本次行走实验的动作系数为0.9。官方冻结训练提交与0.15.1运行端提交不变。

| 用途 | 新训练动作系数 | 运行端对应项 |
|---|---:|---|
| 行走老师 / Walking | 0.9 | policy.action_scale |
| 倒地起身老师 / Stand-up teacher | 0.9 | 供walk槽联合模型训练；不能直接当stand槽保持模型 |
| 行走＋起身联合 / VelStand | 0.9 | policy.action_scale |
| 坐下站起 / Sit–stand | 1.0 | 官方坐站分支固定1.0 |
| 低头捡取 / Ground pick | 1.0 | policy.ground_pick_action_scale |
| 右脚踢球 / Right kick | 1.0 | policy.standing_action_scale |
| 前滚翻 / Forward roll | 1.0 | policy.roulade_action_scale |

参考运行端 `Tuning::default()` 的行走0.9、头颈0.5、腿部0.7。运行端另有standing_action_scale=1.0、ground_pick_action_scale=1.0，坐站分支也固定1.0。不能把全部技能统一改0.9。当前官方训练源码的scale仍为1.0；把0.9写入行走训练环境是本次对齐实验。

执行顺序是 `target = Home + scale × 原始策略输出`，然后执行头颈0.5/腿部0.7目标EMA。0.9只乘相对Home的动作偏移，不乘Home，不乘观测，不改折扣系数γ，也不在ONNX图重复乘。滤波仍按50Hz更新一次、每个环境独立复位，原始上一帧动作观测不变。

新训练的默认系数由任务角色统一解析；用户可直接在页面选择系数，后端校验与运行适配器按选择值执行，不强制覆盖为默认值。旧模型的续训、PT/ONNX仿真和导出沿用来源运行记录，即使新训练默认改为0.9，原来1.0或0.7的模型也不被重标。联合老师与学生仍需动作系数、滤波与物理合同匹配。

导出的 `[policy]` 参数片段只包含当前模型实际使用的缩放分支。例如走路包只写action_scale=0.9，不写standing_action_scale、ground_pick_action_scale、roulade_action_scale；捡物包只写ground_pick_action_scale。manifest记录本模型实际训练系数，不用其他动作槽的系数代替。头腿滤波是运行端共享配置，使用时应保持包内对应值。

沿用R1.5.7的11项专项验证，并增加全12任务缩放分支及导出片段范围核对。重新运行真实CPU目标处理与PPO→PT→官方ONNX导出，检查0.9只执行一次、上一帧动作保持原始值、ONNX输出与PT一致，导出记录0.9及0.5/0.7。浏览器验证新建行走显示0.9、旧模型续训显示其原1.0。未做GPU长训或实机稳定性保证。

原后台进程保活的3项环境回归失败在未修改R1.5.6中同样出现；本次没有修改那部分实现，训练时保持原启动窗口。没有新增环境检查、改变BAM/质量/标定/奖励/课程或电压动作补偿。

最终回归：145项中129通过、13条件跳过、3项为上述既有后台保活环境失败；动作系数/滤波的12项专项用例均通过。

界面与执行修正：动作系数为可选择的绿色下拉框（0.1～1.0），和头颈/腿部滤波一排显示。行走默认0.9，其他技能默认1.0。浏览器验证0.7/0.9/1.0均可选择，轮询与任务切换保留手动选择，实际启动请求记录所选0.7；旧模型续训仍沿用来源值。真实CPU环境验证0.7/0.9/1.0分别作用于Home之外的动作偏移一次，部署合同分别记录相同值。页面顶部显示实际后端版本。
