# R1.5.16 安装完成后的就绪状态修复

## 已装好的服务器立即恢复

在现有中控页面下方找到“执行环境”，点击“首次检查本机”（新版按钮名称为“首次检查训练机器”）。保留服务器的Linux本机执行模式和原源码路径。若准备环境任务仍在运行，先等待它结束再点击。

此按钮对SSH服务器调用环境检查，使用`uv run --frozen --no-sync`，不会执行`uv sync`或重新下载依赖。检查通过后保存检查缓存。队列若已显示失败，点击对应任务的“重新训练”，再点击“开始训练”；已有等待项直接开始。

恢复当前服务器无需重新部署或重启服务器，不删除已下载文件、模型或训练记录。

## 原因与修复

原结束流程只为“环境检查”保存成功记录，却对“准备环境”无条件清掉环境就绪状态。安装流程虽然已经完成CUDA与任务注册检查，结束时仍会变成未就绪，随后队列启动报“这台电脑首次使用请安装训练环境一次”。

修复后记录该任务实际返回的环境检查结果，只有任务成功结束、进程退出码为0且检查返回ready=true时才保存成功缓存。CUDA不可用、检查结果缺失或进程失败均不会伪造就绪。缓存保留于当前训练机器，重启中控仍可复用。

界面改用“当前训练机器”，适用于本机WSL和SSH服务器。队列启用但正在等待安装时按钮显示“等待环境就绪”；实际训练任务运行时才显示“训练运行中”。

正在运行的同版服务器后台不会因为更换本机ZIP自动重载已在内存里的Python代码；因此当前服务器先用上面的环境检查恢复。修复包用于后续新启动的后台安装流程。

## 验证

6项实际管理器流程测试覆盖成功缓存及重启复用、安装后队列直接启动、CUDA不可用、异常退出、缺少环境结果及旧安装状态通过检查恢复。测试模拟工作进程协议输出，没有下载软件包或启动GPU训练。另通过队列状态界面测试、训练队列、官方版本、训练工作台及SSH相关回归。
