# R17 中控参数来源

此页管理 R17 可调参数的默认定义、保存位置和回读关系。

中控可调的全局策略参数只有官方 `policy.action_scale`：默认 0.70，范围 0.10—1.00，步进 0.01。默认只编辑 `config/r17-management.json` 的 `defaults.policy`；发行生成程序将它复制到中控和服务包。用户选择保存到 Zero 的 `robotd.toml` 与 `robotd.saved.toml`，重启沿用保存值。v1.0.146 联合模型使用独立的固定运行参数，见下一节；界面区分全局保存值与当前模型实际值。

## v1.0.146 唯一 Walk 联合模型与独立运行配置

`requested_model_replacement` 将唯一 Walk 替换为 9600 轮联合模型 `1cbf8730eadd75a5704332c9f3c10f60`。旧 14000 轮 Walk `9e3ff8bde021be28a728c02dbd8e7aaf` 加入 `retired_model_ids`，普通升级删除其模型目录并迁移旧引用。正式模型目录共五个模型：新联合、LB 起身老师、起坐、捡取、前滚翻。旧老师仅在源码 `test-data/walk-teacher14000` 留作数值回归样本，不进入运行载荷。

本次明确授权联合模型全程使用基础缩放 0.9、头部滤波 0.5、腿部滤波 0.7。原始 ONNX、manifest、合同和训练记录仍逐字保留原来的 1／1／1；运行配置单独保存为 `deployment-execution.json`，不混进原始 `export-data.zip`。模型导入验证任务、模型 SHA256、严格字段及数值范围；重复导入无运行配置的同一原始 ZIP 时，保留已验证匹配的本机配置。无该文件时执行原训练参数。参数加载、原始动作历史和固定输出算法由 [robotd-design.md](robotd-design.md) 统一定义。

升级描述符记录该配置的 SHA256。第一次安装此请求时，即使相同模型已导入且其目录按原规则保留，也只补入这个独立配置文件；原始训练数据不重复复制。配置文件先原子替换，管理描述符在它之后写入，避免中断后误记为已完成。后续安装同一请求不再覆盖用户之后的配置选择。损坏合同的恢复继续使用既有完整模型恢复机制。

原全局 `policy.action_scale`、头腿参数、电压补偿、本机标定、其他动作绑定、LB 时长和 P／D／48 保存值不因本次替换重设。界面显示当前联合模型的固定参数；高级参数里的全局缩放编辑在该模型绑定时不可用，P／D／48 仍走原应用入口并提交原已保存全局值。当前执行倍率和滤波取原生回读，不把目录中的固定配置当作正在执行的证据。模型列表只轻量读取该小 JSON，不新增 ONNX 哈希计算、训练 YAML 解析、推理或轮询。

以下各历史版本小节记录其引入时的行为；与本节涉及联合模型的规则重叠时，以本节为准。

## 全局参数与保存位置

全局头部滤波、腿部滤波、电压补偿由官方 `robotd-params/src/lib.rs` 中 `PolicyParams` 的默认及解析逻辑提供。R17 的管理定义和 TOML 模板不再包含这些字段，不根据模型合同写入全局值，不提供开关或修改接口。v1.0.137 对明确声明无滤波的模型执行合同中的目标直通，作用范围仅为当前模型，详见下文。

| 参数 | 默认来源 | 默认值 | 中控角色 |
| --- | --- | --- | --- |
| 官方动作缩放 | R17 管理定义 | 0.70 | 可调、保存、读取实际回读 |
| 头部滤波 | 官方 `PolicyParams::resolved` | 0.50 | 固定、只显示实际回读 |
| 腿部滤波 | 官方 `PolicyParams::resolved` | 0.70 | 固定、只显示实际回读 |
| 电压补偿 | 官方 `PolicyParams::default` | 开启，参考 7.4 V | 只显示实际开关及补偿倍率 |
| 嘴巴最大开度 | R17 `defaults.pad` | 100% | 保存到 `/etc/robot/feetech-ft5/pad-settings.json`，网页及真实手柄共用 |
| 手柄头部幅度 | R17 `defaults.pad` | 2.5 rad | 同上；与策略滤波无关 |
| 音量 | R17 `defaults.audio` | 50% | 原生 ALSA；`alsactl store` 保存系统声卡状态 |

升级时读取旧安装的管理定义，删除旧定义拥有、但新定义已移除的策略字段；本次删除旧 R17 的头、腿滤波及电压补偿覆盖值。运行和重启副本同时更新，字段省略后由原生 robotd 解析官方默认。没有额外的补偿恢复请求、完成标记或周期修复。新定义不再拥有这些字段；后续显式写入的原生配置由普通配置合并保留，R17 不控制它们。

升级保留已保存动作缩放、音量、手柄幅度、模型绑定与本机装配标定。v123 已约定的旧动作默认 0.9 → 0.7 迁移保留。本次 Walk 沿用修正版合同 v2；同一 ONNX ID 的旧合同可刷新，其他导入模型与绑定保留。模型导入和绑定只处理动作槽位，不重设动作缩放、滤波、电压补偿或增益。显式重置模型保持既有流程。

中控只提交用户设置，运行取 Zero 已保存配置，不新增持续取值通信。页面显示真实运行回读；未知值显示等待，不用默认值冒充生效值。

音量百分比与 ALSA 数值换算只在 `packaging/voice_preferences.py` 实现。发行程序复制同一模块到中控，SSH 通道注入同一管理定义和模块。系统保存和恢复关系见下一段。

v1.0.136 直接使用声卡原生 `PCM Playback Volume`，`Line Playback Switch` 负责静音；robotd 使用 `plughw:aic3104`，取消 R17 软件 PCM 与 `ALSA_CONFIG_PATH`。网页一次设置请求写入声卡，然后使用系统 `alsactl store aic3104` 保存到 `/var/lib/alsa/asound.state`。普通 SSH 用户通过安装时的限定 sudo 命令保存系统声卡状态；不再写 home 下的音量 JSON。开机恢复由系统 `alsa-restore.service` / `alsa-state.service` 负责，两者使用系统原有互斥条件；排序放在官方 `aic3104-init.service` 之后、robotd 之前，避免官方初始化的 PCM 最大值覆盖系统保存值。固件重启没有任何声音启动钩子。旧 R17 软件音量只在首次迁移时换算到原生 PCM，保持当时响度；音库按原生种子与版本保留，只有首次缺失或种子/版本变更时生成。网页连接只异步读当前系统音量，不设置它、不阻塞手柄。

实际硬件标定优先当前装配数据，再读取本机保存副本。训练模型中的编码器数字只作训练来源记录，不覆盖拆装后的实际零位。

没有临时测试配置时，自训加载按既有 HD1910 路径应用合同 P 增益，当前 Walk 是 P=5、D=20、嘴巴 P=10。模型 HOME、关节顺序和单位转换仍按合同解释，UART、官方动作处理、手柄及 HOME 流程保持。

## v1.0.131 临时舵机测试参数

“缩放与滤波”改名“高级参数”。临时增加 P（50号，Kp）、D（51号，Kd）、转矩限制（48—49号，Torque Limit）。默认草稿 3 / 0 / 681 只定义在 `config/r17-management.json defaults.servo`；升级和编辑都不激活测试。三个数字横排，官方动作缩放后面的应用按钮同时提交四项。P/D 为 0—255 整数，转矩限制为 0—1000 整数。模型标定、合同及训练数字不变。

界面由 `console/static/advanced-parameters.js` 与同名 CSS 独立负责草稿与保存/生效显示；参数保存由 `packaging/advanced_parameters.py` 负责。沿用既有动作缩放应用流程，先校验数值，再卸力、停止 robotd；保存官方 `policy.action_scale` 至现有 TOML 及其启动副本，三个舵机值单独保存为 `/etc/robot/feetech-ft5/servo-test-parameters.json`，随后重启固件。没有增加定时 SSH、额外常驻服务或手柄协议。

原生测试模块 `duck-control/src/hd1910_test.rs` 在启动时读取标定文件同目录的测试 JSON。文件不存在，原来的 HD1910 上力路径继续负责；文件存在，全部 15 个舵机（包含嘴巴）在下一次 HOME 上力时通过原 bus.sync_write 一次写 48—51 的四个字节（转矩限制小端两字节 + P + D），并回读确认，不使用另一个进程访问串口。52号 I、41号加速度、EEPROM、位置写报文和采集事务不变。运行中的模型/官方 gain 请求不会覆盖它。卸力时恢复上力前的转矩限制及 P/D，再次上力会重新应用已保存测试值。该恢复数据在首次写入前保留，部分写入失败仍可恢复。

页面区分待应用、已保存、舵机已确认。仅在 native.hd1910.temporary_gains_applied 为真时显示实际写入确认，不把默认草稿当作实际值。保存的测试值重启/普通升级保留，模型导入不修改它。

配置读取沿用模型列表的维护请求，不新增轮询。v1.0.132 修正维护日志混入回执的问题：持久 SSH 中的子进程分别收集 stdout 和 stderr，两者仍实时进入系统日志，JSON 只从 stdout 解析。前端只有完整的模型列表响应才会替换配置；异常回执保留实际错误，既有读取重试继续工作。服务操作开始/完成、运行身份改变、SSH 目标改变时取消旧读取；旧响应即使延迟返回，也不能覆盖新服务的配置。读取失败和服务缺少参数分别显示，不再一直写“等待读取”。这是中控读取修复；v131 的 control.18 原生固件、参数默认和实际寄存器应用路径均复用。

v1.0.134 修正列表读取的计算量和连接恢复：catalog 只读取已安装合同、manifest、名称和模型文件存在性，提供目录中的声明哈希；不解析训练 YAML、不推导运行文件、不启动推理验证。导入/绑定/启动仍执行各自的模型处理，运行实际哈希由 bus.loaded_models 回读。数字参数应用不再进入 model-check，也不在保存时重复 verify_directory。保存参数和实际寄存器确认的关系不变。

后台维护完成后保留现有手柄 SSH；remote_control.call 已有的本地 socket inode 检测负责连接新服务。后台仅请求一次状态确认，连接已死亡时才由原 ensure 重建。网页将 input.status=recovering 视为输入恢复阶段，暂停连接和动作；后台确认 ready 后复用已连接状态，再建立网页 WebSocket。维护开始时关闭网页旧 socket，动作及原来的 owner 不带入新服务。输入恢复失败仍显示原始错误，网页既有连接恢复继续工作。

### 移除测试功能

运行上先卸力，删除测试 JSON 后重启固件，原来的 P/D/转矩限制处理恢复；已保存的官方动作缩放继续保留。源码上移除上述独立模块、defaults.servo 与它们的调用入口即可：ServiceManagement 构造/render 入口，runtime/service.sh/console.service_control 的三个附加参数，FeetechIo.configure_servo_test 及 hd1910::State 的可选测试分支。把原有动作缩放行保留在常规管理模块，标题可改回“缩放与滤波”。没有需要回退的模型、滤波、UART或手柄策略改动。

48—49号地址对照飞特官方 HLS 内存表：[HLSCL.h](https://github.com/ftservo/FTServo_Arduino/blob/main/src/HLSCL.h)。P/D 沿用现有 HD1910 50/51 寄存器映射。

## v1.0.135 独立起身动作系数

独立 Stand 和 LB 的 stand_test 使用基础动作系数1.0。行走及零速度保持继续使用中控保存的 policy.action_scale（默认0.7），起坐基础1.0，滤波与官方电压补偿保持。训练合同中的0.7保留为训练来源，不叠乘。实际输出仍接受官方电压补偿，基础系数1.0不代表关闭电压补偿。

原生 Contract.uses_global_action_scale 只将粗糙行走合同标记为使用行走缩放。独立起身采用官方 standing_action_scale，随包 profile 设为1.0；LB 的官方命名技能采用 params.action_scale=1.0。升级只更新这两个起身系数，保留已有模型路径、时长、其他技能参数及按键绑定。bus.model_action_scales 增加 Stand、stand_test 的实际配置回读。没有重绑自动Stand槽，没有改训练合同或姿态处理。v1.0.136 按明确请求将 LB 命名技能路径替换为平地起身老师 10000 轮；保留已有动作时长，基础系数1.0。仅补充合同任务名称识别，包内运行建议不写入全局滤波及电压补偿。

## 完整包安装与重启

v1.0.136 继续上传完整服务包并执行随包安装入口，固定安装目录不从临时目录运行。原有模型在复制前跳过；非模型代码与运行库仍完整替换，使用重命名避免运行中可执行文件的 Text file busy。暂存与解压命令复用现有维护 SSH，只文件字节上传使用上传连接。手柄桥、padd、网页输入集中写入配置，升级只执行一次 daemon-reload，再各启动一次。普通重启只重启 robotd，复用已有启动配置及 SSH；webpad 正在运行且 socket 存在时复用，否则单次恢复，由现有页面状态回读接口确认。

取消安装参数生成失败后的默认重建、robotd 启动失败重试及 ExecStopPost 自动重建模型配置；robotd 系统服务覆盖 Restart=no。启动失败保留第一条错误与实际 journal，不自动更改配置后再尝试。现有 UART 启动流程、显式 HOME 上力、舵机读写及模型合同不变。该机制没有硬件耗时保证，需以 Zero 系统日志的实际时间为准。

## v1.0.137 LB 无滤波倒地老师

本次明确替换 LB 命名技能为 11000 轮粗糙地面倒地老师，ONNX SHA256 `a481d9f211f31d9476ab1a319fe362a21ef0879d9fa59442a122845af598268c`。原始合同 `action_filter.enabled=false`、头腿 alpha 均为1、训练动作系数1。Python 导入和原生 Contract 同时识别此合同；无滤波合同不能声明小于1的 alpha。与滤波合同一样使用编码器侧齿隙观测和原始上一帧动作。

config.r17-management.json 的 requested_skill_replacement 指向新模型；升级时仅在安装来源从旧模型变为本次模型的那次迁移更新技能路径和 LB 绑定，基础系数1.0，原技能时长和其他参数保留。首次配置仍为6秒。自动 Stand 仍不绑定倒地老师，原地保持仍走 Walk。原始模型及合同逐字保留，本机标定不取训练零位覆盖。

## v1.0.138 合同修复与旧模型清理

普通安装不再仅凭 deployment-contract.json 存在就保留随包模型：读到空文件、截断 JSON 或非对象 JSON 时，从完整随包目录恢复；修正版 Walk 合同仍按修订号迁移。有效的已导入同 ID 模型不重复复制，未知导入模型不因此删除。合同最后重命名，便于中断后再次升级完成恢复。本次未确认设备上的首次损坏原因。

retired_model_ids 由同一管理定义列出明确弃用的三个 ID：7000 轮起身、平地 10000 轮起身、18000 轮联合模型。普通升级只清理这些目录；配置引用同时迁移到对应随包动作或移除无替代的命名技能，避免留下已删除路径。当前 Walk、LB 新老师及其他有效模型保持。

catalog 保持 active 表示官方 policy 动作槽已绑定；新增 skill_bindings 和 manual_recovery 显示命名技能及 LB 绑定，即使合同读取失败也仍显示配置指向的模型和实际错误。中控显示 LB 名称、ID、基础系数与可用状态，不将“已绑定”声称为“正在运行”，实际运行仍以原生 loaded_models 回读为准。自动 Stand 槽为空与 LB 已绑定可以同时成立；列表读取复用原请求，不新增 SSH 或轮询。

## v1.0.141 原始位置与固定标定目标

按用户明确要求删除139的读数取模和140的目标圈数偏移。反馈只解码飞特15位符号幅值，position_raw与position_signed_raw都保留原生正负值，position_wire_raw保留报文字节。角度与模型观测直接使用 (native-zero_raw)*direction*2π/4096，不使用取模、最近圈选择或动态零位。中控接受完整原生带符号范围，负数不再显示为无效设备。

上力前仍预置新鲜采样的实际原生位置；之后HOME与策略目标仅通过既有JointCalibration.target_raw按本机零点、方向与限位换算，发送结果不加减4096。标定零点与标定目标仍为0～4095。关节工作台从带符号当前位置线性移动到用户请求的正数目标，中间报文也保留正负号；到位确认比较实际目标，不把差4096的坐标视为同一目标。散件回中也采用相同语义。

原来的HOME姿态、2秒回位、机械限位、转矩确认、P/D/48、速度、电流、41号加速度、串口时序、EEPROM、本机标定、模型和输入流程保持。坐标换算验证覆盖12号从-1回1500、22号从-1670回2276，以及重启/重新上力后目标不变。录制中22号-1670到2276相差3946计数，约346.8°；该明确要求的原始绝对坐标行为不保证最短路径，也不能据本地报文测试声称消除实机绕圈。

## v1.0.142 诊断回读的所有权与刷新

控制循环保持 50Hz。HOME 安全检查仍在原来的推理前时刻读取反馈、IMU 挂载与就绪、扭矩三态确认和关节冻结判断；轻量 FeetechControlStatus 只计算这些字段，避免为一次布尔判断复制完整诊断。冻结条件继续使用同一 joint_holding，不修改超时或连续缺帧阈值。

完整 FeetechDiagnostics 在 safety.apply 之后每轮生成一次，因此包含该轮实际应用后的转矩确认及限位计数；通信统计 observe、bus JSON 与订阅的 limp 标记使用这一轮快照。完整动态 JSON、关节反馈、逐轮通信计数和错误提示仍每 20ms 更新，不做发布降频。订阅复用时中间没有新的 safety 写入，不使用推理前状态代替应用后状态。

HD1910 最近一次寄存器检查结果由共享不可变数组保存，完整诊断仅复制引用。下一次 inspect 成功时整体替换；已有诊断快照保留原数组，新的诊断取得新数组。扭矩、冻结、增益确认、通信状态等可变字段继续实时采样。JSON 中寄存器数组的字段、内容与顺序不变。

模型的 SHA256 字符串、路径和任务身份在模型加载时生成；Controller 在建立时缓存已加载模型身份，active_model 每轮按当前活动策略取引用。热重载先创建带有新身份缓存的控制器，再按原 carry_over 继承运动状态，不复制旧身份缓存；HOME 清除活动策略时保留已加载模型列表。模型权重、张量、推理线程数、频率、动作处理和状态转换不变。

对应验证覆盖虚拟串口的新鲜、丢帧冻结、按时冻结、恢复及扭矩切换，以及寄存器重新检查时的快照隔离；真实 ONNX 验证模型热重载刷新身份并保持活动动作连续。输入服务的断连与设备监听机制由 [r17-connection-design.md](r17-connection-design.md) 管理。

## v1.0.143 诊断 JSON 与订阅快照复用

运动模式仍在 safety.apply 后按 50Hz 构造该轮完整诊断，再生成 native JSON。已经生成的 native Value 直接移动到完整报告的 native 字段，不再通过 json! 把整棵 Value 序列化并复制一次。回读采样时点、动态字段、通信统计及错误提示保持；没有把诊断移出控制线程，也没有停订阅时降低诊断刷新率。

robot.busStatus 的运动模式分支用借用结构编码已有不可变 JSON 缓存；持有的 Arc 保证缓存替换后，当前回复仍可完成序列化。下一次请求取得新缓存。JSON-RPC 结构和 ID 保持，commissioning 的 typed bus_snapshot 仍优先，缺少报告的错误响应也沿用原逻辑。借用只省掉构造 Response::ok 时的额外深复制，不复用旧帧代替新帧。

状态广播持有 Arc<proto::RobotState>，多个订阅者接收同一不可变帧时仅复制引用；每个订阅者按原有频率和字段选择生成通知。队列仍为 256 帧，落后订阅者仍走原来的 lag 处理。存在订阅者时，完整状态和骨架仍在原控制周期内生成；没有订阅者时，原来不构造状态帧的判断保持。中控最高 20Hz 的请求与原有抽样方式保持，控制循环仍为 50Hz。

生产 IPC 测试覆盖运动报告字段与缓存替换、缺报告错误、typed 报告优先级，以及多订阅者共享快照、通知内容和队列界限。遥测 SSH 转发由 [r17-connection-design.md](r17-connection-design.md) 管理。上述代码复用不能代替实机 CPU 或温度测量；v143 发布前的断开中控测试只说明原版本的连接开销。


## v1.0.144 原始快照与按请求报告

本节取代v143的逐轮完整JSON生成。50Hz控制线程仍在原有时刻读取硬件、推理和safety.apply；应用后把固定大小的原生动态诊断与所需状态放入共享最新快照。HOME推理前检查仍使用既有FeetechControlStatus，发布的limp仍取本轮应用后扭矩确认。完整JSON只在robot.busStatus等实际请求时由IPC线程组装，现有JSON结果与commissioning/startup响应保持。

通信统计observe从原来的JSON构造块独立出来：无订阅时仍按真实事务更新累计成功/失败、连续错误与最后失败信息。传输断开不清安全状态、模型状态或故障计数，不影响控制线程继续运行。HD1910寄存器检查、本机标定、加载模型身份保留共享元数据，变化后发送新定义；不按每一帧复制静态大树。

原始流有订阅者时，由独立发送任务把最新typed快照直接编码一次，多个连接共享该编码结果。没有订阅者时发送任务休眠，不编码、不读取低频系统信息。原有官方robot.subscribe仍按订阅规则生成其完整状态与骨架；R17原始流只发送状态数值，显示/导出的骨架在浏览器从同一静态模型派生。控制用的原生FK、模型推理与安全流程保持。

参数、P/D/转矩限制、标定公式、飞特多圈位置、HOME/LB、UART/HAT和全部模型文件没有为降低温度而改动。实现移除了遥测复制/处理链的重复工作，尚不能据此给出实机CPU或温度降幅。传输帧、连接生命周期、网页手柄按需启动与浏览器记录由[r17-connection-design.md](r17-connection-design.md)管理。
