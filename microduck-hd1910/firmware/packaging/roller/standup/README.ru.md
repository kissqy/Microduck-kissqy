# Самостоятельно обученная модель HD1910 · Целевая прошивка 0.15.1

<a id="hd1910-自训模型--目标固件-0151"></a>
<a id="hd1910-self-trained-model--target-firmware-0151"></a>
Навык с нулевыми командами и проверенное окно выполнения нужно настроить вручную; автоматический слот восстановления не создаётся.

- Проверенный нативный интерфейс: `0.15.1` / `1fa84386f07884e27866411bc1ba166977bced95`; маршрут `manual_skill`; область поддержки `manual_configuration_required`.
- Исторический список допустимых задач R148 не принимает эту задачу; экспорт обучения не подразумевает импорт на робота одним нажатием. Это самостоятельно обученные веса, а не официально проверенная выпущенная модель. Конфигурация робота автоматически не записывается.
- Режим роликов автоматически не переключается на Stand; настройте отдельный универсальный навык с нулевыми командами. Upstream не задаёт окно выполнения этой задачи; длину эпизода нельзя подставлять вместо длительности. Этот экспорт не создаёт ни запускаемого навыка, ни слота stand.
- Эта задача требует аппаратных пассивных роликов; одной заменой ONNX нельзя обеспечить совместимость робота с обычными стопами.
- Исходная задача обучения: `Mjlab-RollerStandUp-Flat-MicroDuck`; официальный коммит обучения: `8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec`.
- Задача оценки / экспорта: `Mjlab-RollerStandUp-Flat-MicroDuck`; исходник экспорта: `8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec`. Исходное трение обучения: `official` (fixed=фиксированное трение; official=официальная рандомизация).
- Модель: `policy.onnx`; `checkpoint.pt` предназначен для продолжения обучения и не может напрямую передаваться robotd для инференса.
- `manifest.json` использует официальную схему 2. Этот ZIP — архив обучения, а не пакет обновления прошивки.
- `deployment-profile.toml` — официальный фрагмент `[policy]` / `[[policy.skill]]`. Объедините его с существующей конфигурацией, не заменяя файл целиком. При назначении этой модели сохраните настроенные пути навыков и множители усиления.
- При обучении не использовалась дополнительная EMA головы / ног; голова / шея и ноги используют пропуск без фильтрации 1.0. Это описание истории обучения; фактический инференс использует параметры deployment-profile.toml. Динамика сервоприводов BAM сохраняется в модели обучения. Фильтрация применяется к целям суставов после Home + масштаб действий × сырой выход, без уменьшения итогового угла. Этот фильтр не встроен в граф ONNX.
- Комплектный `manifest.json` фиксирует параметры, но не гарантирует их автоматическую загрузку средой выполнения. При развёртывании применяйте масштаб действий и фильтрацию головы / ног из `deployment-profile.toml`.
- Компенсация напряжения, усиления и множители усиления не являются полями конфигурации этого обучаемого действия. Экспорт не включает / выключает их принудительно и не устанавливает в 1; они сохраняют существующую рабочую конфигурацию. Этот фрагмент не включает отключённую настройку. Рандомизация питания BAM и падение напряжения под нагрузкой сохранены в снимке обучения и не подтверждают обучение рабочей компенсации действий по напряжению.
- `training-config.json` хранит происхождение конфигурации `training_run_readback`, среду, награды, программы обучения, экспертное BC, BAM, массы, люфт и другое. Приоритет имеет исходное считывание при старте обучения. Отсутствующие исторические записи явно помечаются как реконструкция из сохранённых конфигураций, а не выдаются за исходное считывание.
- Нормализация наблюдений: `embedded_in_onnx_once`; если она включена, официальный экспортёр встраивает её в ONNX. Не нормализуйте данные повторно при выполнении.
- Используйте драйвер адаптации HD1910/IMU и калибровку текущей физической сборки. Комплектная калибровка служит только сведениями о происхождении и не перезаписывает нули физических суставов.
- Симуляция люфта: `{"enabled": false, "joint_count": 0, "ranges_rad": {}, "encoder_position": "motor", "motor_velocity": "motor-side for friction and back-EMF", "policy_joint_velocity": "motor"}`. Пассивные суставы люфта не экспортируются как действия ONNX; робот использует фактическую обратную связь энкодеров.
- Учителя ходьбы и совместные модели используют слот walk; только совместная модель включает соответствующее обучение восстановлению после падения. Учитель восстановления не является отдельной политикой неподвижного удержания.
- Подбор, приседание на роликах и вращение используют фазовые команды с периодом из исходного снимка обучения и конечной фазой 0.7. Посадка / вставание использует флаг позы. Кувырки вперёд и удары левой / правой ногой используют официальное окно однократного действия. Длительность эпизода симуляции не является окном запуска прошивки.
- Удар левой ногой использует отдельно обученную модель задачи левой ноги. Наличие left в имени файла не заставляет среду выполнения зеркалировать модель правой ноги.
- Этот пакет прошёл проверки формата модели и конечности выходных значений; это не подтверждает пригодность физической походки на вашем роботе.

Порядок действий / наблюдений, фактический Home, параметры BAM и снимки обучения см. в `deployment-contract.json`, `training-config.json` и `upstream-params/`.
