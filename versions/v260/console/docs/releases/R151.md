# R17 v1.0.151：手柄连接修复按钮

基线为已交付 v1.0.150。只更新中控 Python、界面与操作说明；随包 ARM64 固件 tar、HAT bin、控制循环与模型全部保持原字节，服务 build 为 control.31。中控源码包含新增 helper 与测试，可直接审阅。

按钮位于“模拟手柄”标题旁。打开后显示 A+HOME 模式、HOME+截图键配对指引，可选 MAC、支撑确认、手机蓝牙恢复选项和一次性开始按钮。状态复用原有中控遥测快照，不新增请求定时器。

## 一次操作的边界

- 通过既有 SSH、sudo 密码处理和串行服务管理作业执行。密码不进入作业记录；动作不会自动重发。机器人/IMU 数据未就绪时仍可提交蓝牙修复。
- 一个 `/run` 文件锁防止多个中控同时修复。先核对安装、设备名称及服务，再暂停 padd 和桥；通过 robotd IPC 请求卸力并确认，未运行的 robotd 不阻挡配对。启动已失败且周期数为零时不伪造扭矩确认。不开第二个 UART。
- 已配对手柄先尝试 HID profile 连接。连接成功不删配对、不重置适配器。连接失败只删除精确选中的 Nova 2 Lite 记录，保留其他蓝牙设备。
- 需要配对时只进行一次适配器电源恢复、一次 15 秒扫描、一次配对（30 秒上限）和必要的 HID 连接（20 秒上限）。同一个存活的 bluetoothctl 客户端持有 agent、扫描和配对会话。
- 主修复事务另有 120 秒总时限，结束清理保留独立命令时限。临时 agent 仅处理本客户端发起的配对，不替换系统默认 agent；处理 JustWorks 配对确认，不猜测 PIN。
- 不重启 bluetooth.service、不清空蓝牙数据库、不更改模式与映射。电源或 discovery 失败明确显示原始错误与需要重启 Zero；界面提供重启入口，重新上线后由用户再次开始修复。
- 必须同时确认蓝牙已连接、原始 GameSir 输入存在、虚拟 Xbox 存在以及 bridge/padd active，才报完成；恢复手机广播后再回读一次。仅服务 active 不算修复成功。
- 正常结束、配对超时、电源/扫描失败及桥接失败都关闭临时蓝牙客户端并尝试恢复服务。恢复失败保留原故障、显示额外错误，不报告完成。默认启用并启动 btd；取消手机恢复选项时保留原启用状态。
- 完成后保持卸力，不自动 HOME、启用策略或重放旧输入。

## 验证

新增故障注入覆盖首次配对、旧 HID socket 失败、adapter power Failed、discovery InProgress、配对超时、缺虚拟 Xbox、btd 恢复失败及停用状态、密码与目标验证、无 IMU 作业提交、同一子进程会话生命周期。界面测试覆盖按钮位置、只提交一次、sudo 通道、离线/回放/忙状态、阶段提示、部分结果和重启入口。另运行现有中控服务与固件校验回归。

未在实际 Radxa / BlueZ / systemd / GameSir 无线设备上执行。浏览器运行时没有可用 Chromium，采用 DOM 操作测试；不声称已完成真实浏览器渲染。结果见 `verification/gamepad-repair151.json`。
