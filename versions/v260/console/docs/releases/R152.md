# Microduck R17 v1.0.152

**历史说明：v152 发布包的 ONNX Runtime 文件被截断，会导致 SIGBUS；请停用并安装 v153 随包固件。以下是当时的设计说明，不代表该发布包已通过实际启动验证。**

配套固件 `1fa8438-feetech-ft6-control.32`；中控基于 v151，固件基于 v150。安装必须同时更新中控和随包固件，无需重装系统或重置标定。

## 为什么替换旧方案

2026-10-09 的失败记录显示，寄存器 40 卸力回读未收到全部 15 个舵机响应，控制周期为 0。同一 UART 五次重试仍然失败；此时尚未进行 IMU 身份读取，因此“IMU 未就绪”不能用于判定 IMU 故障。后续记录中同一旧 build 在重新启动服务后恢复约 50 Hz，IMU 正常。

该证据支持优先排查 UART/服务启动状态，尚不足以证明特定驱动或硬件是根因。SSH 断连是另一条故障链，需要内核与网络日志。

## 本版替换

旧五次重试函数、常量与相应测试已删除。首次通信超时后释放旧 UART，等待一次 400 ms，再执行一次完整新开串口。安装启动助手为两个代次分别验证 IRQ/FIFO 后确认；旧代次确认不能放行新串口。新串口同样失败则结束并报出原因，不自动重启。

启动仍先写寄存器 40 卸力并确认全部 15 个舵机，再读 IMU 身份与寄存器。未确认卸力不继续，不写增益或目标；启动期间和失败后的 HOME、策略与技能请求不排队。

systemd 的启动后检查等到真实总线循环开始后才通过。IPC/声音能响应不再作为启动成功。控制线程退出会使本次启动明确失败，`Restart=no` 保留。

中控保留 v151 手柄修复，增加只读的“导出启动诊断”，并显示实际总线初始化错误。诊断每次只运行一次，读取本次/上次内核日志、robotd/蓝牙/网络日志、UART 占用与配置，不打开串口或重启服务。

正常 50 Hz 循环、Sync Read 期限、模型、标定、P/D、滤波、HAT 固件及手柄映射保持原值。没有新增常驻监控或后台重试。

## 使用与验证

完整解压本版中控，连接 SSH，支撑机身，在“系统维护 → 随包固件”安装。核对 `control.32` 后等待就绪，再重新按 HOME。

若仍失败，先导出启动诊断 JSON。SSH 离线时按钮无法读取 Zero 日志，恢复连接后导出。离线测试与 ARM64 构建结果见 `BUILD_MANIFEST.json` 及源码 `verification/recovery152.json`；尚未验证真机断电重启和温度。

机制说明由源码 `docs/design/robotd-design.md` 的 R17 UART 启动章节维护。
