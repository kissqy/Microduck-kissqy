# R17 v1.0.157-Fix5

修复 Windows 中控安装固件时的远端路径错误：Linux 的 `/tmp/.../service.sh` 曾通过本机 `Path` 拼接成反斜杠，导致上传、校验和解压完成后找不到安装脚本。远端安装路径现在使用 POSIX 拼接，本机路径仍使用本机规则。安装脚本执行失败或缺少成功回执时，日志明确报告该步骤失败和原因。

SSH 地址、密码、连接、断开和清除密码移至页面顶部、导出记录旁边。连接中及连接错误提示显示在 SSH 模块自己的状态行，移除原来的横向连接提示栏样式。原有连接、密码保存与维护通道继续复用。

移除实时画面及系统日志的“暂停显示”按钮、状态变量、绑定和相关显示门禁。历史回放播放／暂停、断开连接、关机和安装期间的连接等待仍按原流程工作。

安装、服务操作、模型读取与 robotd 四步流程不再输出“开始”日志；各步记录最终成功或失败及原因。中间等待状态仍传递给界面，上传字节进度保留。完整日志没有增加全局过滤器，实际错误和诊断输出仍可下载。

本版只修改 PC 中控。随包固件与 Fix4 字节一致，原生构建仍为 `control.36`；未增加机器人线程、查询、轮询或 50 Hz 工作。安装完成后恢复数据连接的机制见 [Fix4 安装流程](R157-Fix4.md)。

## 使用

退出旧中控，完整解压并启动 Fix5。若此前遇到反斜杠路径错误，重新执行一次随包固件安装；此前失败没有执行到安装脚本。已成功安装 Fix4 固件的机器，仅更换中控即可使用本次修复，无需为这次 PC 修改重新安装固件。

## 验证

本次通过 117 项 Python 检查及 9 组浏览器逻辑脚本。新增回归在生产安装入口模拟 Windows 路径语义，确认传往 Linux 的安装脚本路径始终使用正斜杠，同时确认安装日志没有“开始”行。原有上传校验、安装失败、清理、成功回执、安装期间阻塞与完成后一次连接、输入、连接、遥测、原子替换和动作门禁检查继续通过。

页面结构检查确认 SSH 表单在顶部、提示在其状态行、ID 唯一，且两个暂停显示按钮及其逻辑已移除。未在原生 Windows 或机器人实机上验证，未运行浏览器像素渲染或重跑原生历史测试。准确结果见源码的 `verification/changes157fix5.json`。
