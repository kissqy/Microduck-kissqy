# История версий Training Studio
<a id="training-studio-version-history"></a>

Архив описывает прежние версии и эксперименты. Для R1.5.27 с 14 категориями действий и 35 рецептами используйте [актуальное руководство пользователя](../USER-GUIDE.ru.md). Исторические списки 12 задач и экспериментальные параметры ниже не являются текущими значениями по умолчанию.

## R1.5.17 — Оценка подъёма и проверки переворота
<a id="r1517-recovery-evaluation-and-rollover-checks"></a>

<a id="r1517--recovery-evaluation-and-rollover-checks"></a>
- Обычная оценка StandUp PT / ONNX использует конечную стадию курса исходного рецепта, чтобы счётчик ONNX не начинал облегчённый курс заново. Обычный рельеф сохраняется.
- Отдельные проверки на ровной поверхности с нулевыми командами охватывают полностью лежачие положения на спине, левом / правом боку, животе и конечную смесь стартов.
- Исходный менеджер событий сбрасывает фиксированные позы. Высота и наклон должны удерживаться в пределах критерия; тайм-аут означает неудачу, ручной сброс отменяет попытку. Стояние в новом эпизоде не считается успехом предыдущей попытки.
- Оба viewer записывают фактические суставы, корневую позу, команды и контакты для воспроизведения застрявших состояний.
- Изменена только оценка; дополнительное обучение учителя на 11000 итераций остаётся отдельным незапущенным предложением.

## Дополнение R1.5.16 — SSH с паролем
<a id="r1516-supplement-password-ssh"></a>

<a id="r1516-supplement--password-ssh"></a>
Поддерживаются парольная аутентификация и существующие системные ключи. Одно аутентифицированное соединение обслуживает развёртывание, вызовы API, передачу моделей и перенаправление viewer. При первом подключении нужно подтвердить идентичность хоста; пароли остаются только в памяти консоли. Неверные пароли и изменившиеся ключи хоста дают явные ошибки. Версия сервиса остаётся R1.5.16; существующие серверы могут переподключиться. Исправления путей инструментов GPU WSL и конфигурация обучения сохранены.

## R1.5.16 — Локальное тестирование SSH в WSL
<a id="r1516-local-wsl-ssh-testing"></a>

<a id="r1516--local-wsl-ssh-testing"></a>
Существующий локальный WSL продолжает использовать `wsl.exe`; проверка одним нажатием проверяет серверный путь SSH через отдельный loopback SSH, ключи, ключи хоста и записи сервера. Она повторно использует фактический код загрузки / перенаправления и проверяет существующую среду, не устанавливая и не меняя движки и не запуская обучение. Сохранённые внешние соединения можно восстановить. Scale, фильтры, P и физика сохранены; при сбое цель SSH остаётся выбранной, непреднамеренное локальное выполнение блокируется.

## R1.5.15 — Удалённое обучение по SSH
<a id="r1515-remote-ssh-training"></a>

<a id="r1515--remote-ssh-training"></a>
- Добавлены выбор локальной / SSH-среды, локальное сохранение соединений, нестандартные порты, системные ключи, ssh-agent и явные пути ключей.
- OpenSSH загружает ту же консоль в независимый каталог сервера. Сервер, доступный только через loopback, использует существующую подготовку закреплённой среды.
- Очередь, обучение, симуляция, графики, журналы, остановка и скачивание проходят через туннели SSH. Серверные очереди переживают отключение рабочего компьютера.
- Загрузка полных ZIP сохраняет scale, фильтрацию, P, контракты и происхождение. Старые экспорты считывают фактические преобразования из `policy_parameters`; отсутствие исходного параллелизма может допускать использование как учителя, но продолжение требует полного исходного снимка обучения.
- Поведение обучения / P версии R1.5.14 сохранено. Удалённые сбои блокируют отправку без локального запасного пути. Калибровка ZERO считывается локально и передаётся на сервер.

## R1.5.12 · Единая очередь и параметры контактов
<a id="r1512-unified-queue-and-contact-parameters"></a>

<a id="r1512--unified-queue-and-contact-parameters"></a>

Остановка сначала сохраняет решение не запускать последующие задачи, затем останавливает текущую; ожидающие задачи остаются. Поддерживается обновление только статических файлов. Старые серверы очереди приостанавливают планирование перед остановкой текущей задачи. «Добавить» перенесено к параметрам обучения; «Начать» / «Остановить» / «Отменить» — на панель очереди без изменения логики отправки. ## R1.5.8 · Эксперимент с масштабом ходьбы 0.9 и фильтрацией
<a id="r158-walking-scale-09-and-filtering-experiment"></a>

<a id="r158--walking-scale-09-and-filtering-experiment"></a>
Селектор масштаба действий 0.1–1.0 находится рядом с фильтрами головы / ног. Для цепочки ходьбы по умолчанию 0.9; для остальных навыков 1.0. Ручной выбор сохраняется при смене задачи и обновлении статуса. Продолжение обучения использует сохранённые значения; возврат к новому обучению восстанавливает черновик. Отображаемая версия приходит с сервера, чтобы новая страница не скрывала старый скрипт. Запустите обновлённый скрипт и обновите страницу Ctrl+F5; активное обучение сохраняет начальную конфигурацию.

Новые учителя ходьбы, учителя подъёма для совместного обучения и совместные модели используют scale 0.9, фильтр головы 0.5 и ног 0.7 в UI, обучении, симуляции, проверках ONNX и экспорте. Исходный scale upstream остаётся 1.0; 0.9 — локальный эксперимент согласования с развёртыванием. Сидение / стояние, подбор, удар и перекат по умолчанию используют 1.0. Учителя подъёма соответствуют контракту совместной ходьбы и не являются моделями неподвижного Stand.

Старые продолжение, оценка и экспорт сохраняют собственные scale / фильтр каждой модели, включая модели R1.5.7, обученные с 1.0. Экспорт записывает только соответствующие настройки действия, не меняя другие слоты. Развёртывание применяет один фильтр цели и одно преобразование действия, без ещё одного умножения на 0.9.

Порядок эксперимента: обучить нового учителя ходьбы, нового учителя подъёма, затем совместную модель. Переустановка / проверка среды не нужна. Калибровка, BAM, масса, курсы и макет сохранены. См. [проверку](Verification.ru.md).

## R1.5.7 · Эксперимент с фильтрацией целевых положений суставов
<a id="r157-joint-target-filtering-experiment"></a>

<a id="r157--joint-target-filtering-experiment"></a>
Новое обучение по умолчанию использует α=0.5 для головы / шеи и α=0.7 для ног при масштабе действия 1.0. Для сравнения фильтрацию можно отключить. Это локальный эксперимент, а не утверждение, что upstream-обучение уже использует EMA.

- Исходный выход → `Home + 1.0 × raw output` → EMA цели → существующий BAM. Вес новой цели — α, прежней — 1−α. Обновление один раз за цикл 50 Hz, а не на каждом из четырёх физических подшагов.
- По именам выбираются четыре сустава головы / шеи и десять ног, исключая клюв / пассивные суставы. У каждой среды независимая история; первая цель после сброса проходит напрямую. Наблюдения предыдущего действия и награды скорости изменения действия по-прежнему используют исходные выходы.
- Продолжение, оценка и экспорт сохраняют записанную фильтрацию модели. Старые модели без записей фильтра используют прямую передачу. Изменения страницы влияют только на новые запуски.
- Оба учителя и совместная задача требуют совпадающих фильтров. Обучайте новых совместимых учителей, не считая нефильтрованных эквивалентными.
- Контракты, метаданные ONNX и `deployment-profile.toml` записывают настройки. ONNX выдаёт исходные действия; среда выполнения фильтрует один раз. R1.5.13 позднее исправляет историческое принудительное поведение экспорта напряжения / усиления.
- Существующие кэш среды, BAM, масса 820 g, калибровка, награды и выравнивание выборки сохранены. Дополнительный масштаб 0.9 или компенсация напряжения не вводятся.

Запускайте из распакованного каталога через `start-training.cmd`, либо `python3 training_console.py` в Linux, без переустановки движка. Перед сменой каталогов держите окно активного обучения открытым до завершения. Этот выпуск не гарантировал сохранение обучения при закрытии терминала Windows / WSL. Функциональная проверка CPU не является приёмкой физической устойчивости.

## R1.5.4 · Ошибка симуляции обученной модели
<a id="r154-trained-model-simulation-error"></a>

<a id="r154--trained-model-simulation-error"></a>
Удаляет обращение к несуществующему `policy.scale` в журнале инициализации. Политики MLP и ONNX входят в официальный Viewer без дополнительного масштабирования. Неиспользуемые запросы `inference_scale` удалены / игнорируются; сохранённый `training_action_scale` остаётся. Очистка Viewer предшествует остановке Viser, предотвращая `Event loop is closed` и сохраняя восстановление после тайм-аутов и изоляцию обучения. Новое обучение по-прежнему использует 1.0. PT, BAM, калибровка, награды и курсы неизменны. Для исправления viewer не нужны переобучение, повторный экспорт или переустановка среды.

## R1.5.2 · Выравнивание отсчётов относительно 4096 сред
<a id="r152-align-samples-to-4096-environments"></a>

<a id="r152--align-samples-to-4096-environments"></a>
Цель: официальная 0.15.1, официальный каркас + HD1910, 820 g с аккумулятором. Средам R1.5.0/1.5.1 переустановка не нужна. Запускайте новый каталог в простое; записи остаются в том же каталоге данных.

- Эталон: 4096 сред × 24 шага за итерацию. При 2048 временные пороги / бюджеты удваиваются; при 1024 учетверяются. Другой параллелизм масштабируется пропорционально.
- Пересчитываются зависящие от времени курсы падения / полуприседа, толчков, плавности, диапазона команд и поз. Вероятности, значения параметров и продвижение по рельефу на основе результатов остаются неизменны.
- Изменение параллелизма пересчитывает текущий стандартный / ручной бюджет; последующее редактирование итераций задаёт фактический бюджет. Таблицы / журналы / считывание показывают эталонные и локальные значения. Смена задачи читает встроенные данные без пробы среды.
- Сохранение каждые 1000 фактических итераций без масштабирования интервала. PT хранит накопленные отсчёты; нумерация итераций PPO остаётся upstream. Новые совместные тёплые старты начинают курс с нуля.
- Активные запуски сохраняют стартовую конфигурацию. Старое продолжение использует записанные параллелизм / rollout; прежний опыт курса не отменяется. Для полностью нового сравнения нужно новое обучение.

| Эталон 4096 | Фактически 2048 | Фактически 1024 | Сброс в падение / полуприсед |
| ---: | ---: | ---: | --- |
| 0–149 | 0–299 | 0–599 | 0% / 0% |
| 150–699 | 300–1399 | 600–2799 | 0% / 20% |
| 700–999 | 1400–1999 | 2800–3999 | 15% / 20% |
| 1000–1399 | 2000–2799 | 4000–5599 | 30% / 20% |

- VelStand принимает прежние PT учителей ходьбы / подъёма; одно отсутствие старой рандомизации трения не требует переобучения учителей.
- Источник обучения `cb70b792…` загружается текущим `8d0db749…` без установки старого движка. Происхождение PT, параметров робота и калибровки сохраняется; экспорт указывает фактическую версию обучения.
- Модели фиксированного трения используют исходный множитель BAM 1.0; рандомизированные модели R1.4.23 сохраняют настройки. Новое совместное обучение по-прежнему рандомизирует 0.9–1.1.
- Нормализуется только эквивалентная запись селектора. Реальные несовпадения действий, порядка, HOME, BAM, массы или инерции явно отклоняются. Контрольные точки старого совместного оптимизатора V2 не мигрируют; используйте старых учителей для нового совместного запуска.

Совместимость подтверждает загрузку, оценку и участие в обучении, а не отсутствие физического эффекта от пропущенной рандомизации.

## Исторические инструкции запуска
<a id="historical-startup-instructions"></a>

1. Распакуйте в новый каталог и запустите `start-training.cmd`; Windows требует Python ≥3.10. Linux: `python3 training_console.py --open`. Страница: `http://localhost:8092`.
2. При первом использовании выберите «Среда выполнения → Установить среду обучения» (执行环境 → 安装训练环境). R1.5.0/1.5.1 повторно используют кэш. Последующие изменения задачи / калибровки / модели / обучения / viewer не запускают проверки.
3. Выберите задачу, параллелизм и итерации. Пустые поля алгоритма используют официальные значения. Изменения робота сохраняются автоматически. Используйте «Получить из ZERO» (从 ZERO 获取) или импортируйте полную калибровку.
4. Эта историческая версия запускала обучение напрямую; поздние версии с очередью требуют сначала добавления. Руководствуйтесь текущей инструкцией. Обучение могло показывать девять реальных сред; отдельная оценка не останавливает обучение.
5. Оцените PT и экспортируйте ONNX, PT, манифест schema 2, фрагмент развёртывания, фактические параметры и происхождение калибровки.

Движок: `~/microduck-training-studio/engines/official_0151`. WSL устанавливает через `uv sync --frozen --python 3.12`; Python 3.10 рабочего компьютера менять не нужно. Если Git / uv отсутствуют:

```bash
sudo apt-get update
sudo apt-get install -y git curl
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Затем установите среду через страницу. Обучению нужна NVIDIA CUDA; новый хост проверяется один раз.

Эта консоль читает калибровку, не записывая ZERO и не двигая сервоприводы.
