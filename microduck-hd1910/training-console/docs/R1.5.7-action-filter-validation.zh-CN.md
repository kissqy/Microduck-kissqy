# R1.5.7 · 训练动作滤波实现与验证

本次改动是训练中控的本地实验，不修改官方训练仓库或机器人固件。基于随包 R1.5.6 最新版（版本30），保留页面结构、R17配色、标定、820g质量配置与HD1910 BAM参数。

## 对齐的处理顺序

官方训练提交固定为 `8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec`；参考运行端 `0.15.1` 的 `duck-control` 处理顺序，运行端提交为 `1fa84386f07884e27866411bc1ba166977bced95`。

| 阶段 | 本次实现 |
|---|---|
| 策略输出 | 原始14维动作；不在模型输出层缩放或滤波 |
| 关节目标 | `target = Home + action_scale × raw`；新训练动作系数1.0 |
| 头颈目标滤波 | `filtered = 0.5 × target + 0.5 × previous_filtered` |
| 腿部目标滤波 | `filtered = 0.7 × target + 0.3 × previous_filtered` |
| 执行器 | 沿用既有编码器偏差处理和HD1910 BAM，不重写舵机参数 |
| 上一帧动作观测、动作变化奖励 | 保留原始策略动作 |

头颈：`neck_pitch` 颈俯仰、`head_pitch` 头俯仰、`head_yaw` 头偏航、`head_roll` 头横滚。腿部：左右两侧的 `hip_yaw` 髋偏航、`hip_roll` 髋横滚、`hip_pitch` 髋俯仰、`knee` 膝、`ankle` 踝，共10个。按解析后的关节名称匹配；不包含嘴巴和passive关节。

例如上一帧滤波目标为20°，新目标变成30°，这一帧头颈目标为25°、腿部为27°；持续保持30°时最终仍趋近30°。α是新目标的权重，α=1为直通，不能解释成最终角度乘0.5或0.7。

滤波在 mjlab `process_actions()` 中更新，每个50Hz策略周期一次。`apply_actions()` 的四次物理子步只重复下发已算好的目标。每只鸭子有独立的历史；指定环境复位时仅清除它的历史，首个目标直通，与运行端没有previous目标时的分支对应。

## 保存、仿真与部署

- 新建训练的页面默认启用头颈0.5、腿部0.7；可取消启用或修改系数，字段始终可见。
- 请求、实际配置日志、`resolved.json` 和运行记录保存实际设置。仿真、ONNX验证、导出、续训读取模型的原始运行记录，不能被页面随后修改的系数覆盖。
- 老模型没有此记录时保持直通1.0；续训沿用源模型。新滤波实验选择“新建训练”。
- 联合模型与两位老师沿用既有合同核对；滤波配置不同不能被当作相同执行语义。应分别训练使用同一组滤波的行走和起身老师，再选择它们训练联合。
- ONNX图仍输出原始动作。额外元数据 `microduck.action_filter` 记录参数和执行语义；外部运行端必须在关节目标层只执行一次滤波。导出包的 `deployment-contract.json`、`manifest.json`、`deployment-profile.toml` 和使用说明同步记录它。
- 导出配置保持动作系数1.0、头颈0.5、腿部0.7、额外电压动作补偿关闭（旧模型沿用各自记录）。仅加载ONNX不等于运行端已应用该配置；本次没有修改实机固件。
- 本次未增加任何环境前置检查，也没有加入动作系数0.9、电压补偿或额外BAM修改。原运行端增益约定不变。

## 已完成的验证

1. **11项滤波专项测试通过**：参数校验、旧记录回退、模型设置优先于页面、双教师合同、远程与后台工作包、全部12任务配置、真实动作管理器、真实PPO与官方导出。
2. 实际 mjlab 1.3.0 / torch 2.9.1 / mujoco 3.10.0 / mujoco-warp 3.8.1 / warp-lang 1.12.0 / BAM锁定提交 `62bd8ce12154340be97e06f7f41a0ca8f116d967`。使用CPU构建两只鸭子并执行物理步骤；检查每周期的递推、原始动作观测、部分复位和物理子步不重复滤波。
3. 12个任务中，启用前后只有动作项增加滤波配置；机器人、奖励、课程、算法和网络保持相同。实际快照的新增字段有中英解释，联合教师合同可匹配。
4. 在CPU执行一次真实PPO迭代、保存PT，通过官方路径导出ONNX。ONNX的 `[1,61] → [1,14]` 接口正常，输出与PT原始推理结果数值一致；导出合同、TOML和元数据包含0.5/0.7，不把滤波重复嵌入神经网络图。
5. 三组真实HTTP/Playwright界面验证通过：4K滤波控件、旧模型续训保留直通、新运行保存参数、任务切换不发起检查；既有官方任务/执行器页面及R17布局回归通过。检查4K截图及中文显示。
6. 常规回归运行142项：127通过、12条件跳过、3个后台进程保活用例失败。同样3个用例在未经修改的R1.5.6中也失败，不能把此环境的测试结果作为Windows/WSL关脚本继续训练的保证。新增的源模型参数优先级用例另行通过；未修改旧版后台进程生命周期实现。

这些测试验证滤波接入和模型接口，未执行GPU长训或本机实机试走，不代表已经证明步态更稳。训练后用相同供电、标定、地面和部署参数对照前进、后退、转向、保持与倒地恢复。

## 本次主要文件

`training/action_filter.py` 管理可移植设置与合同；`training/filtered_actions.py` 实现每个环境的目标滤波。`runtime_adapter.py` 接入训练/仿真/导出；`deployment.py` 生成运行端参数。三个工作包入口同步包含新模块；前端和配置哈希保存设置。
