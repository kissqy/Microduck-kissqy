# Microduck R17 v1.0.155

配套原生固件为 `1fa8438-feetech-ft6-control.34`。本版修正传感器暂停后的 HOME 返回和回位目标保留，首次连接等待采用中性提示，并在全部 15 个关节反馈中增加本机已保存方向。

## HOME 与保持切换

此前网页 HOME 在策略已启用时，显式关闭策略依赖“上一轮仍在驱动”的下降沿设置 HOME。策略被 IMU 或总线暂停后，该分支可能遗漏 HOME，保留暂停时的实测姿态。本版单次记录该 HOME 意图，仍直接选择完整合同 HOME，不为这条路径新增两秒插值；重复关闭已停策略不产生 HOME 或上力。实体 Start-off 和策略已关闭时的 `robot.init` 在反馈有效时仍按原两秒线性回位。

Ready 状态的 HOME 请求在无反馈时保留绝对合同 HOME 目标，原冻结关节保护继续生效，反馈新鲜后使用该目标；Limp 且无反馈不动作。HOME 清除原策略／技能历史，回位不自动重新启用策略。5° 关节、10° 倾斜、连续三帧与反馈新鲜度条件保持，原生路径见 [robotd 设计](../../../docs/design/robotd-design.md#r17-显式关闭策略回-homecontrol34)。

两条 HOME 路径都绕过模型目标低通；审查未发现目标按上次目标累加。本版未提高 P／D／48，也未改已有插值时长。目标设置或插值完成不代表载荷下实测已完全到位。本版只修上述状态路径，不能据此认定“不够硬”、前倾或摔倒的全部原因，也不声称已通过实机保持验证。

## 连接与关节方向

首次连接无第一帧时显示“连接中”或“SSH 已连接，等待首次完整反馈”；未完成首控制周期不冒充传感器故障。真实 SSH、服务、启动错误和已收到反馈后的过期仍显示。断开与重连按代次清除旧报告，避免沿用上次故障或就绪，详见 [连接设计](../../../docs/design/r17-connection-design.md#initial-feedback-and-reconnection-v10155)。

全部 15 个关节含嘴巴增加方向列，读取本机已保存标定、严格按 ID 与名称匹配：+1 显示“正向 +1”，−1 显示“反向 −1”，未知或无效显示“—”。仅显示，不改方向、角度或目标，不使用默认方向补齐，也不新增轮询，详见 [设置设计](../../../docs/design/r17-settings-design.md#v10155-已保存方向显示)。

## 继承的参数与安装

v154 的合同 P、48／51 不显式写入、模型导入退役、五个原始内置模型、联合 Walk 起身、RB 右踢、LB 左踢为空和真实随包版本显示继续保留。完整 ARM 运行库、有限 UART 启动恢复、SSH 分离判断和 GameSir 修复机制不变。模型权重与执行参数未因本次修复调整，正常控制保持 50 Hz，没有新后台循环、采集或推理次数。

关闭旧中控，完整解压本版，支撑机器人，通过“系统维护 → 随包固件”安装一次。核对中控 `1.0.155`、运行 build `control.34`。等待总线与 IMU 就绪，使用原 HOME／策略流程；回位完成后仍由用户再次开启保持。无需重装 Linux 或清空标定。

构建与回归的准确结果、文件哈希见随包清单和源码验证记录。本轮未连接真机，保持／行走、断电重启、蓝牙和温度仍需实测。
