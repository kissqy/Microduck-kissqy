# R1.5.17：倒地老师评估修复与翻身检查

日期：2026-10-06。基于用户现有 R1.5.16 完整包修复。

## 修复内容

### PT / ONNX 普通查看统一使用最终课程

原 ONNX 仿真新建环境后，环境计数从零开始；没有恢复 checkpoint 的训练时钟。StandUp 的初始课程是站40%、坐40%、趴20%、背0%，所以新打开的 ONNX 窗口不能用来直接判断最终训练分布。PT 加载路径会恢复部分环境状态，因此两条路径的起始采样不一致。

本版在实际事件、奖励、命令管理器建立后调用原官方定时课程，应用最终阶段，再固定本次评估课程。普通 StandUp 的 PT / ONNX 评估一致地使用站15%、坐20%、趴30%、背部/侧倾35%的最终混合（原配方没有另外覆盖时）。普通查看使用模型原训练地形；开启推扰仍按原查看选项处理。

这项修改只作用于官方适配的倒地起身老师和 `play` / `onnx` 操作。训练、预检、初始模型预览、导出重建和其它任务不应用这项课程固定。模型权重没有改变；它原本不会的翻身动作不会因此自动学会。

### 独立的固定姿态检查

“模型与验证”卡片中新增 **翻身检查**。它根据所选模型的任务角色启用，与当前训练动作下拉框无关，支持老师的 PT 与 ONNX。

专项使用平地，保留原机器人、质量、HD1910、齿隙、动作系数、P、滤波和模型对应配置，强制关闭推扰并归零速度/头部/身体指令。它从下列类别选择起点：

| 选项 | 起点含义 | 是否统计通过率 |
|---|---|---|
| 完全背朝地 | 背部朝下，轴向侧滚为零 | 是 |
| 左侧躺 | 由背朝地绕身体纵轴转到左侧 | 是 |
| 右侧躺 | 由背朝地绕身体纵轴转到右侧 | 是 |
| 趴地 | 脸朝下 | 是 |
| 训练最终混合 | 保留最终的站/坐/趴/背部混合，仍处于专项平地环境 | 否，站姿起点不能计成起身 |

固定姿态通过官方的 reset 事件执行，并写入实际 EventManager 的 term；不是只修改已失效的配置副本。轴向侧滚使用官方坐标约定。初始化时根据真实机器人碰撞几何计算最低可碰地的位置，把它放到平面上方1mm，并把速度归零；清理动作历史和滤波状态。没有隐藏的动作辅助或策略热身。

### 记录实际卡住时的姿态

普通倒地老师查看与专项检查都提供 **记录当前姿态**。点击后在仿真线程采集当时的根姿态、速度、关节映射、关节状态、命令、地形和接触诊断，并把结构化记录写入该仿真的完整日志。普通查看保留原地形和指令；记录动作本身不会重新摆放机器人。

这项功能用于把“脚抬一下才能起来”的描述变成可用于下一步复现的姿态数据。可在卡住时记录一次，帮助后刚进入可自行起身的位置再记录一次。它是姿态诊断记录，不是包含全部随机数和执行器内部状态的完整环境存档。

## 怎么使用

1. 解压完整 `Microduck-Training-Studio-R1.5.17.zip`，运行其中 `start-training.cmd`（Windows）或 `start-training.command`（Linux）。页面顶部应显示 R1.5.17；仅刷新旧网页或替换 `training/static` 不会更新后端。
2. 在“模型与验证”选择已有 11000 轮倒地老师 PT 或其 ONNX。点击 **翻身检查**，默认从完全背朝地开始。
3. 在仿真里的 **翻身检查** 分组选择姿态；点击 **重新放置并检查** 开始一次新检查。通过或到时后暂停，便于看结果；再次重放开始下一次。
4. 看各姿态的“通过/完成”与取消次数。普通查看仍使用 **查看所选策略**；它会使用原地形和最终混合。
5. 比较不同模型时，在主页重新选择模型再开检查。专项窗口不在内部热切 checkpoint，避免把不同模型计入同一张表。
6. 在普通仿真复现卡住时，点击 **记录当前姿态**；在中控日志选择该仿真并打开 **完整日志**，保留这次记录。默认背躺能够成功而实际卡住姿态失败时，后续补课使用后者作为目标。

原本的训练记录、模型和环境缓存继续使用。本版没有修改数据目录或清理旧模型。如果中控运行在 SSH 服务器，服务器后端也需要部署同版；现有版本检查会阻止在同一目录并行启动另一版后台。不要把只更新本机网页当作已更新服务器评估代码。

## “通过”具体表示什么

采用所选任务实际 `height_stand.target_height`，要求躯干高度达到该目标减10mm、机身倾角不超过15°，连续保持1秒。本次原模型任务对应的数值以仿真面板读回为准。

- 正常回合终止或到时，计为失败；先判断终止标志，再读姿态，避免自动 reset 的新站姿造成假成功。
- 中途手动重放/切换姿态计为取消，取消独立列出；计算错误也不算成功。
- 混合模式只观察，不把其中本来站着的回合加入起身成功率。
- 一次通过只计一次，暂停后继续检查会开始新的试次。

**这是姿态与高度指标。** 本版没有把脚底接触、冲击或真实硬件稳定性纳入通过判定。固定起点是无穿透的几何初始化，最低碰撞面留1mm间隙，不是提前被动落稳后的真实跌倒状态库。其关节主要仍使用原官方 HOME 初态；原 yaw/位置与相应环境随机化保留。重复重放结果用于复现，不能替代各种实际卡住关节/接触状态下的验收。

## 本次验证范围

真实源验证使用冻结官方提交 `8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec`，CPU 环境为 Python 3.12.14、Torch 2.9.1、MuJoCo 3.10.0、mjlab 1.3.0、Viser 1.0.30、ONNX Runtime 1.24.4 与 better-actuator-models 1.0.1。

验证包含运行中的 EventManager、课程状态、四种姿态重力方向、碰撞几何位置、动作历史/滤波重置、零指令，以及真实 Viser 服务启动、姿态切换和关闭。API 回归覆盖所选模型绑定、PT / ONNX、非法 flag、禁止把专项当训练入口；前端使用实际脚本配 DOM/HTTP 桩检查选择和提交行为。

未在本次环境进行 GPU 训练、真实机器人测试或真实浏览器的4K/CSS/WebGL渲染验收。单次原模型回放若有记录，也仅是管线检查，不是成功率估计。具体命令和最终结果见同目录 `R1.5.17-verification.txt`。
