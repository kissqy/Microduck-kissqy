## 开始使用

1. 把本包解压到一个新目录，运行 `start-training.cmd`。Windows 端支持 Python 3.10 及以上；Linux 可运行 `python3 training_console.py --open`。页面地址是 `http://localhost:8092`。
2. 首次使用这台训练电脑时，在“执行环境”点击一次“安装训练环境”，安装本版统一的官方源码和锁定依赖。已有 R1.5.0 / R1.5.1 的电脑跳过，沿用原来的检查缓存。之后切换任务、标定、模型、训练和仿真都不再触发环境检查。
3. 选择动作、并行环境和轮数；留空的算法字段直接使用该动作的官方默认值。机器人参数编辑自动保存。需要更新标定时点击“从 ZERO 获取”，或导入完整标定文件。
4. 点击“开始训练”。训练画面支持同时看 9 个实际并行环境；模型评估单独运行，不占用或停止训练进程。
5. 选择 PT 评估，导出模型包。包内包含 ONNX、PT、官方 schema 2 manifest、部署参数片段、实际生效参数和标定来源记录。

新执行目录固定为 `~/microduck-training-studio/engines/official_0151`。WSL 依赖由 `uv sync --frozen --python 3.12` 安装，Windows 的 Python 3.10 不需要更换。

如果 WSL 尚无 git/uv，可在 WSL 终端执行：

```bash
sudo apt-get update
sudo apt-get install -y git curl
curl -LsSf https://astral.sh/uv/install.sh | sh
```

然后重新点击“安装训练环境”。训练需要可用的 NVIDIA CUDA 环境；新电脑只验证一次。

## 本版保留的任务

| 官方任务 | 地面 | 官方源码 max_iterations | 用途 |
|---|---|---:|---|
| Velocity / 行走老师 | 平地、粗糙地面 | 50000 | 行走、转向、姿态控制；可放 walk 槽 |
| StandUp / 倒地起身老师 | 平地、粗糙地面 | 15000 | 倒地恢复老师；供联合训练，不冒充原地保持 stand 槽 |
| VelStand / 行走与起身联合 | 平地、粗糙地面 | 6000 | 选择当前或兼容的既有 V2 行走、起身老师 PT；部署到 walk 槽 |
| SitStand / 坐下与站起 | 平地、粗糙地面 | 15000 | sitstand 槽；vx=1 坐下，vx=0 站起 |
| GroundPick / 低头捡取 | 平地、粗糙地面 | 20000 | ground_pick 槽；4 秒周期相位指令 |
| BallKick / 右脚踢球 | 平地 | 10000 | kick_right 槽 |
| Roulade / 前滚翻 | 平地 | 10000 | roulade 槽 |

共 12 个任务。上面的轮数是官方源码默认训练上限，不是保证收敛或必须训满的轮数。中控将其作为 4096 环境、每轮 24 步的预算基准：例如联合的 6000 轮，在 2048 下自动显示 12000 轮，在 1024 下显示 24000 轮。实际可随时停止或手动修改预算。

按既有使用要求，每 1000 轮保存；不保存 model_0.pt，短于 1000 轮不会自动留下 PT。运行记录只显示最近 10 次，模型记录继续保留。只在明确点击删除或清理按钮时删除模型。

## 与 0.15.1 的对齐范围

- 官方训练源码固定为 `pollen-robotics/microduck_rl@8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec`。
- 固件目标固定为 `pollen-robotics/microduck@daemon-v0.15.1`，提交 `1fa84386f07884e27866411bc1ba166977bced95`。训练仓库没有同名固件版本号；这里是核对模型协议后的固定配对。
- 使用真实官方任务 ID，沿用其奖励、课程阶段内容、终止条件、接触几何、PPO 和联合训练算法；时间课程阈值由 R1.5.2 按 4096 基准换算。去掉陆吾独立训练引擎、旧 HD1910 任务别名、旧 V2 别名、轮滑模型入口及旧版本参数台账。
- 本机差异保留：HD1910 BAM、15 颗舵机的质量差、820g 配重、本机标定、速度指令 0、不写加速度寄存器 41。
- 训练动作系数固定 1.0；不再提供额外 0.7 训练或推理缩放。
- 同一冻结源码中的 XL330 参数仍作为舵机对照，不会应用到 HD1910 上。

**0.15.1 官方原版硬件驱动面向 XL330，本机仍需要对应的 HD1910 + IMU 驱动适配。** 模型格式兼容不等于未经适配的官方原版固件可以直接驱动飞特。

官方基础训练源码没有额外的头腿 EMA。R1.5.7 新增本地滤波实验：启用时导出要求对应的头颈/腿部系数（默认0.5/0.7）；关闭或旧模型则要求1（直通）。动作系数和增益沿用训练记录，关闭额外电压动作缩放。当前R1.5.8行走训练链使用0.9，其他技能及旧模型按各自记录；运行端不能再次叠加动作缩放。运行端应合并 `deployment-profile.toml` 和模型合同；它不是整份 robotd.toml，也不是固件升级包。

模型包还区分行走速度、捡取相位、坐站标志及翻滚/踢球动作窗口。PT 用于续训，ONNX 用于推理。新增的格式、Home、关节顺序和输出检查在导出时执行，不增加训练前置检查。

## 原有数据

当前标定和机器人编辑会迁移保留，迁移前的 recipe 另有备份；不会把当前机械装配退回旧零点。兼容的既有 V2 模型进入仿真、导出及老师列表；其他历史引擎的记录保留，仍可下载和删除。不会删除旧 WSL 源码目录或替换原 PT。

浏览器关闭、日志解析异常及训练画面断开不会主动发送停止请求；明确“停止训练”操作才发送停止请求。关闭中控启动脚本是否会影响 Windows/WSL 进程存活仍需验证，训练时请保持该窗口开启。训练进程自身报错仍会按真实错误显示。

标定是每台机器人当前装配的硬件参数，不改变官方 Home 和训练课程。随包标定来源于用户最新导出模型的快照；机械重装后的值以 ZERO 当前保存文件为准。训练中控只读取标定，不写 ZERO 或驱动舵机。

完整核对结果见 `docs/Verification.md`，来源文件哈希见 `data/source-evidence.json`。本次已经完成 CPU 配置、真实 PPO/联合算法、ONNX 及中控流程验证，尚未完成你的 GPU 长训与实机步态验收。
