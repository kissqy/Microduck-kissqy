# Ключ разработки команды

`team.dev.pub` — открытая часть ключа, которым CI подписывает сборки веток, чтобы `robotctl update apply --ref <branch>` работала на доверяющей ему плате.

**Его намеренно нет в [`../trusted_keys/`](../trusted_keys/README.ru.md).** Тот каталог `scripts/install.sh` копирует на *каждого* робота, а робот, доверяющий этому ключу, устанавливает всё, что собирает любой участник команды. Поэтому ключ находится здесь, где по умолчанию ничто его не устанавливает: `provision-board.sh` передаёт его, а `--no-dev-key` отказывается от передачи.

**Коммит открытого ключа ничего не раскрывает.** Для подписи сборки нужна закрытая часть, которая находится в `~/.duck-keys` и никогда его не покидает. Плата принимает dev-сборки только при выполнении двух независимых условий: ключ находится в её `trusted_keys_dir`, *и* в её `updater.toml` установлено `allow_dev_keys = true`. На пользовательском роботе оба условия отключены, и наличие этого файла ни одно из них не меняет.

Раньше ключ вообще не хранился в репозитории. Это не давало дополнительной защиты сверх двух условий выше, но вынуждало каждого нового разработчика обращаться к коллеге за файлом.

Повторное создание при утрате закрытой части: на каждую существующую плату разработки затем нужно вручную установить новую открытую часть, поскольку плата доверяет только тому, что уже находится в её `trusted_keys_dir`:

```bash
minisign -R -s ~/.duck-keys/team.dev.key -p team.dev.pub
```
