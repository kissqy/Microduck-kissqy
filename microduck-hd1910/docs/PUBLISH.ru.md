ZIP-ссылки на главной странице скачивают файлы непосредственно из репозитория и не зависят от отдельных вложений Release. Актуальные исходники находятся в `main`; автоматически сформированные вложения Source code у старого тега образа не обновляются вместе с `main`.

## Последующая синхронизация

При отсутствии незакоммиченных локальных изменений сначала получите изменения удалённого репозитория, затем замените программы и исходники, требующие обновления:

```powershell
git pull --ff-only
git status -sb
```

В разделе Source Control VS Code: **добавить в индекс → ввести сообщение коммита → создать коммит → отправить push**. Добавление в индекс или локальный коммит не обновляют GitHub; удалённый репозиторий меняется только после успешного push. Если есть незавершённые изменения, перед pull закоммитьте или надёжно сохраните их. Не отбрасывайте их и не применяйте force-push.

При обновлении вместе проверяйте названия загрузок на главной, BUILD прошивки, исходники и ZIP-пакеты запуска. Сохраняйте существующую LICENSE компонентов; не заменяйте лицензирование репозитория новой MIT или Apache.

Новые пакеты запуска можно размещать в `release-assets/` или **Releases → Edit release → Attachments**. Большие системные образы распространяются через Releases. Тег выпуска указывает на один коммит; не перемещайте старые теги ради подмены их исходников.
