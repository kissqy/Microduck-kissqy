# microduck console

Управляет уткой за пределами вашей сети. Войдите через Hugging Face, и появятся роботы, принадлежащие вашей учётной записи: это та же страница консоли, которую робот предоставляет в своей локальной сети, но доступ к ней идёт через rendezvous-службу вместо WebSocket.

**`hf_oauth: true` критически необходим:** этот параметр создаёт OAuth-приложение, чей client id и области доступа этот Space получает в окружении, а `entrypoint.sh` записывает в выдаваемую страницу. Без него консоль не может выполнить вход и сообщает об этом.

**Docker вместо static — следствие прежних проблем.** Согласно документации, статический Space должен внедрять в страницу `window.huggingface.variables`; но в этом Space этого не происходило ни после изменения метаданных, ни после переключения приватности, ни после удаления и повторного создания, ни после добавления странице настоящего `<head>` для инъектора. Поэтому контейнер сам записывает тот же объект из окружения, предоставленного `hf_oauth: true`. Именно так работает `server.mjs` проекта `telepresence`, благодаря чему его вход работает со страницы Hugging Face. Страница, которой не нужен сервер, получила его ровно по этой причине.

Запрашиваются только `openid profile`; они читаются из `OAUTH_SCOPES`, а не вписываются в страницу, потому что в этой переменной Hugging Face сообщает, какие области выдал приложению Space. Единственное назначение токена — подтвердить личность rendezvous-службе, которая проверяет его через `whoami-v2` и извлекает имя пользователя из ответа. Запрашивать у браузера области доступа к репозиториям было бы той самой ошибкой, исправлению которой на роботе посвящён §2.4 `remote-access-design.md`.

**Вход действует `hf_oauth_expiration_minutes`, не дольше.** Страница сохраняет его в `localStorage` и проверяет срок действия перед передачей rendezvous-службе; просроченный токен считается отсутствием входа. Поэтому консоль просит войти заново, а не сообщает, что утка отсутствует.

**Не редактируйте этот Space напрямую.** Страница находится в [`mediad/webclient/index.html`](https://github.com/pollen-robotics/microduck/blob/main/mediad/webclient/index.html) репозитория `pollen-robotics/microduck`, а сюда её публикует `scripts/publish-console.sh`. Она должна оставаться там, поскольку следует двум вещам из того же репозитория: протоколу сигнализации и именам методов робота. См. §5 `remote-access-design.md`.

Одна страница, два транспорта. При выдаче роботом она открывает `ws://<robot>:8443`. При выдаче отсюда — через https, где браузер вообще не открывает `ws://`, — она читает поток событий rendezvous-службы и отправляет ей POST, передавая те же конверты с идентификаторами для каждого участка маршрута.
