# Происхождение параметров консоли R17 — проектная запись v148

<a id="r17-console-parameter-provenance--v148-design-record"></a>
Историческая страница определяет настраиваемые умолчания, хранение и чтение параметров проекта v148. Обычный глобальный `policy.action_scale`: 0.70, диапазон 0.10–1.00, шаг 0.01. Менять только `config/r17-management.json`, `defaults.policy`; генерация копирует его в консоль и службу. Значения пользователя сохраняются на ZERO в `robotd.toml`/`robotd.saved.toml`. Совместные модели имеют отдельные настройки исполнения; в v148 тот же ползунок меняет их базовый масштаб, умолчание 1.00. Последующие правила: [текущий проект настроек](../../docs/design/r17-settings-design.ru.md).

## Ползунок масштаба совместной модели v1.0.148

При привязанной совместной Walk с профилем исполнения ползунок называется «联合模型动作缩放» («Масштаб действий совместной модели»), кнопка — «应用联合缩放» («Применить совместный масштаб»). Умолчание `defaults.joint_action_scale=1.0`, диапазон 0.10–1.00, шаг 0.01. Перетаскивание меняет лишь черновик. Применение использует существующие `set-action-scale`, снятие момента, сохранение, перезапуск и новый HOME; P/D/момент сохраняются из той же формы.

Служба выбирает путь по привязанной модели: совместная меняет только `deployment-execution.json.action_scale`, сохраняя глобальные значения, фильтры, LB, исходные данные обучения и локальную калибровку. Обычная меняет глобальный `policy.action_scale`. Нативная загрузка использует совместный масштаб без умножения на старый глобальный, как описано в [проекте robotd](../../docs/design/robotd-design.ru.md). Существующие бинарники используются повторно.

Каталог объявляет `joint-action-scale` и `default_joint_action_scale`. Редактирование использует сохранённую конфигурацию модели; живое отображение — чтение контроллера. Успех требует совпадения SHA модели и `runtime_execution_profile`, а не просто того же ONNX со старым множителем. Старые службы без возможности выключают ползунок и предлагают обновление; их применение P/D/момента всё ещё отправляет сохранённый глобальный масштаб.

Нетронутые 0.9/0.5/0.7 однократно мигрируют в 1.0/0.5/0.7, только если SHA файла совпадает со старым дескриптором, а все прочие поля — с новой конфигурацией. Пользовательские масштаб/фильтры сохраняются. Генерация, перезапуск, переустановка и повторный импорт сохраняют масштаб. Корректные локальные калибровка и сохранённые копии важнее комплектных снимков. Этот раздел определяет редактирование, умолчания и сохранение совместных моделей вместо исторических правил ниже.

## Единственная совместная Walk v1.0.146 и отдельный профиль исполнения

`requested_model_replacement` делает совместную модель после 9600 итераций `1cbf8730eadd75a5704332c9f3c10f60` единственной Walk. Старый учитель 14000 `9e3ff8bde021be28a728c02dbd8e7aaf` включён в `retired_model_ids`; обновления удаляют каталог и мигрируют ссылки. Пять рабочих моделей: совместная Walk, учитель LB, sit/stand, pick, roll. Старый учитель остаётся только в исходном `test-data/walk-teacher14000` для регрессий.

Пользователь согласовал общие параметры исполнения 0.9/голова 0.5/ноги 0.7. Исходные ONNX, манифест, контракт и данные обучения побайтово сохраняют 1/1/1. Отдельный `deployment-execution.json` находится вне `export-data.zip`. Импорт проверяет задачу, полный SHA, строгие поля и диапазоны. Повторный импорт того же исходного ZIP без настроек исполнения сохраняет проверенные совпадающие локальные настройки; без профиля применяются исходные тренировочные параметры. Загрузка, история сырых действий и выход принадлежат проекту robotd.

Дескрипторы обновления записывают SHA профиля. Начальная миграция добавляет лишь профиль, даже сохраняя каталог той же модели. Профиль атомарно заменяется до дескриптора для восстановления после прерывания; повторы сохраняют последующий выбор пользователя. Повреждённые контракты восстанавливаются полным комплектом модели.

Глобальные масштаб/фильтры/напряжение, калибровка, прочие привязки, длительность LB и сохранённые P/D/48 не сбрасываются. UI показывает фиксированные параметры совместной модели; глобальное редактирование для неё отключено, P/D/48 используют прежний запрос с сохранённым глобальным значением. Активные масштаб/фильтры подтверждает нативное чтение, не файл профиля. Каталог читает небольшой JSON без дополнительного хеширования ONNX, YAML, инференса или опроса. v148 заменяет эти исторические правила редактирования.

## Глобальные параметры и хранение

Официальный `PolicyParams` владеет глобальными фильтрами и компенсацией напряжения. Определения/шаблоны R17 больше не содержат и не управляют ими, не пишут глобальные значения из контрактов. v137 добавляет passthrough отдельной модели для явного контракта без фильтрации.

| Параметр | Источник умолчания | Умолчание | Роль консоли |
| --- | --- | --- | --- |
| Официальный масштаб действий | Управление R17 | 0.70 | Изменение, сохранение, фактическое чтение |
| Фильтр головы | `PolicyParams::resolved` | 0.50 | Фиксированное фактическое чтение |
| Фильтр ног | `PolicyParams::resolved` | 0.70 | Фиксированное фактическое чтение |
| Компенсация напряжения | `PolicyParams::default` | Включена; опора 7.4 V | Фактический флаг/множитель |
| Максимум клюва | R17 `defaults.pad` | 100% | Общий `/etc/robot/feetech-ft5/pad-settings.json` |
| Диапазон головы | R17 `defaults.pad` | 2.5 rad | То же хранилище, не фильтрация |
| Громкость | R17 `defaults.audio` | 50% | Нативная ALSA, `alsactl store` |

Обновления удаляют из рабочей и перезапускной копий поля старых определений, отсутствующие в новых, включая прежние переопределения фильтров/компенсации R17. Отсутствие разрешается в upstream-умолчания. Нет запроса исправления, маркера или таймера. Позднее явно записанная нативная конфигурация сохраняется обычным merge.

Сохранённые масштаб, громкость, диапазон геймпада, привязки и калибровка остаются. Миграция старого умолчания 0.9→0.7 из v123 сохраняется. Walk contractv 2 может обновить старый контракт того же ID; прочие импорты/привязки сохраняются. Импорт/привязка управляют лишь слотами, не масштабом, фильтрами, напряжением, усилениями; явный сброс модели сохраняет прежний процесс. UI отправляет пользовательские настройки, показывает фактическое чтение, а неизвестное — ожиданием вместо умолчания.

Только `packaging/voice_preferences.py` преобразует громкость; генерация и SSH используют один модуль/определение. v136 применяет нативные `PCM Playback Volume`/`Line Playback Switch`, `robotd` — `plughw:aic3104`; software PCM и `ALSA_CONFIG_PATH` удалены. Настройка выполняет `alsactl store aic3104` в `/var/lib/alsa/asound.state` через ограниченный sudo. Системные `alsa-restore.service`/`alsa-state.service` сохраняют взаимоисключение и запускаются после официального `aic3104-init.service`, до robotd: максимальная инициализация не перезаписывает громкость. Стартового звукового hook нет. Старая программная громкость однократно преобразуется; звуки регенерируются только при отсутствии или смене seed/версии. Соединение асинхронно читает громкость без установки и блокировки ввода.

Калибровка предпочитает текущую сборку, затем локальные сохранённые копии; значения энкодеров обучения — данные происхождения. Без временной тестовой настройки существующая загрузка HD1910 применяет P контракта; историческая Walk имела P5/D20 и клюв P10. HOME, порядок, преобразования и официальные UART, действия, геймпад, HOME-процесс сохранены.

## Временные параметры сервоприводов v1.0.131

«Масштаб и фильтрация» становится «Расширенными параметрами», добавляя P (адрес 50/Kp), D (51/Kd), ограничение момента (48–49). Черновик 3/0/681 определён только в `defaults.servo`; обновление/редактирование его не активирует. Три поля применяются вместе с масштабом. P/D — целые 0–255, момент 0–1000. Контракты, обучение, калибровка сохранены.

Независимые `console/static/advanced-parameters.js`/CSS отображают черновые, сохранённые и применённые значения; `packaging/advanced_parameters.py` сохраняет. Проверить, снять момент, остановить robotd; сохранить глобальный масштаб в существующем TOML/копии, значения сервоприводов отдельно в `/etc/robot/feetech-ft5/servo-test-parameters.json`; перезапустить. Новых периодических SSH, службы или протокола ввода нет.

При старте `duck-control/src/hd1910_test.rs` читает JSON рядом с калибровкой. Без JSON действует исходный путь. С JSON четыре байта 48–51, little-endian лимит момента + P + D, записываются исходным bus.sync_write во все 15 сервоприводов при следующем включении момента HOME, затем подтверждаются чтением. Второго владельца UART нет. I52, ускорение 41, EEPROM, пакеты положения, выборка сохранены. Модели и официальные запросы усилений не переопределяют. Снятие момента восстанавливает прежние P/D/лимит; повторное включение применяет сохранённые тестовые значения. Оригиналы сохраняются до первой записи для восстановления частичного отказа.

UI различает ожидающее, сохранённое, подтверждённое; только `native.hd1910.temporary_gains_applied=true` подтверждает оборудование. Черновики не фактические значения. Тестовые настройки переживают перезапуск/обычное обновление; импорт модели их не меняет.

v132 разделяет stdout/stderr постоянных SSH-подпроцессов: оба пишутся в журнал в реальном времени, JSON разбирается только из stdout. Только полный ответ каталога заменяет настройки. Настоящие ошибки и повторные попытки сохраняются; операции, идентичность runtime, смена цели отменяют старые чтения, чтобы задержанный ответ не перезаписал новую службу. Ошибки чтения и отсутствие поддержки различаются. control.18, умолчания и путь регистров используются повторно.

v134 читает в каталоге только установленные контракты, манифесты, имена, наличие, объявленные хеши: без YAML, вывода параметров runtime или инференса. Импорт, привязка, запуск сохраняют проверку; фактические хеши берутся из `bus.loaded_models`. Применение чисел пропускает model-check и повторный verify_directory.

Обслуживание сохраняет SSH геймпада; существующее обнаружение inode сокета находит новую службу. Одно подтверждение использует прежний ensure только при неработающей службе. `input.status=recovering` приостанавливает действия; ready переиспользует подключённое состояние или вновь открывает web-сокет. Старые сокет, действия и владелец не переносятся. Реальные ошибки и восстановление сохраняются.

## Сырые положения и фиксированные цели v1.0.141

По запросу удалены modulo v139 и смещения оборотов v140; 15-битная знаковая обратная связь Feetech и байты провода сохранены.
