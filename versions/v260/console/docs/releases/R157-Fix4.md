# R17 v1.0.157-Fix4

固件安装日志按实际工作显示开始、成功、失败与原因。PC 显示上传字节进度；安装期间关闭旧 robotd 数据及启动状态连接，安装成功后通过完成通知恢复连接。原生程序仍是 control.36，Rust 源码、模型权重、HAT 固件与正常 50 Hz 控制工作不变。本版修改安装脚本，固件压缩包的 SHA256 会更新。

## 安装与连接流程

1. 清除旧输入，关闭旧 robotd 数据与启动状态连接。既有读线程在条件变量上等待安装完成，不定时检查 socket。独立 ToF 通道保持原流程。
2. 在 Zero 创建本次安装的随机暂存目录。目录返回无效或命令失败时显示原因，停止安装，不打印成功。
3. 上传固件。进度来自现有分块写入累计字节，不新增查询；100% 表示字节已送入 SSH 通道，界面同时说明仍等待 Zero 写入与校验。Zero 完成写入、flush、fsync 并返回字节数和 SHA256 后，本机逐一比较；不一致直接失败。
4. 解压固件。成功才运行随包安装脚本。创建、解压、清理的普通成功输出不再展示原始命令、随机路径和退出码；失败保留原始诊断。
5. 检查所有原生程序与 ONNX 推理库的 ELF 完整性、文件装载范围及 AArch64 架构，然后准备本机参数与标定。未通过完整性检查时不停止现有机器人服务。
6. 停止旧实体手柄服务，提交旧 robotd 松开请求，再让 systemd 停止旧 robotd。松开回执仅代表请求被接收；停止成功由 systemctl stop 返回证明。机器人进程停止失败直接终止安装，不继续宣称旧服务关闭成功。输入服务失败保留原因，主服务独立安装。
7. 逐文件原子替换服务文件，安装本机配置与启动命令。保留文件原子替换与模型保留的结果；串口、模式和移除旧启动配置数量改为中文说明。
8. 安装 R7 输入桥与官方 padd 配置、开机启用设置，以及实际变更的 udev 规则。只有存在旧网页虚拟手柄文件时才停用并清理，不再声称这一步已经建立 PC 的持久 SSH。现有音库无需重新初始化时不输出无动作说明；实际音频配置显示结果。
9. systemd 重载配置并启动 robotd。安装路径不再附加读取一次 busStatus，也不输出两份相同状态 JSON；systemd 启动成功与 robotd 初始化成功分别报告。
10. 安装自动更新与 golden 恢复禁用配置，重载并启动实体手柄服务。主服务不受输入启动结果影响，输入失败保留原因与准确回执。
11. 安装完成后清理本次临时文件。只接受 upgrade_installed 成功回执，退出码为零但回执缺失仍视为失败；不恢复 robotd 数据连接。JSON 保留在内部机器回执，不转印到用户日志。
12. 成功回执通知原数据读线程重新连接一次 /run/robotd.sock，订阅原始数据与 robotd 四步启动快照。第一次连接失败停止自动尝试并显示原因，用户可使用 SSH 连接按钮重连；输入恢复也只做一次，不重发安装或动作。安装失败期间数据连接继续暂停，下一次成功安装或手动 SSH 连接解除暂停。

robotd 四步启动事件仍来自既有 startupSubscribe：服务基础、硬件与有效反馈、随包模型、首个控制周期。完成后订阅会返回当前完整快照，因此不会因安装阶段暂停连接而丢失各步最终结果。
