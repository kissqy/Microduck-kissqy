# R17 中控参数来源

此页管理 R17 可调参数的默认定义、保存位置、内置模型与升级迁移。以下当前规则适用于 v1.0.155／control.34；v154 的参数与模型规则继续保留，后面的历史小节只记录当时行为。

## v1.0.154 舵机覆盖退役

中控可调的全局策略参数只有官方 `policy.action_scale`：默认 0.70，范围 0.10—1.00，步进 0.01。默认定义在 `config/r17-management.json` 的 `defaults.policy`，发行生成程序复制到中控和服务包；用户选择保存到 Zero 的 `robotd.toml` 与 `robotd.saved.toml`。联合 Walk 使用单独的 SHA 绑定执行配置，界面区分全局保存值与当前模型实际值。

高级参数只提交动作缩放，不再读取或保存 P50、D51、48 号转矩限制。`defaults.servo`、独立测试模块及其生产调用已删除；升级删除 `/etc/robot/feetech-ft5/servo-test-parameters.json` 和旧生产模块。P 来自模型合同并用于全部 15 个舵机；48／51 保留设备当前值，不显式写入，也不写零模拟恢复。上力与卸力恢复的报文规则由 [robotd 控制设计](robotd-design.md#r17-hd1910-合同-pcontrol33) 管理。此前 v131—153 的临时覆盖说明已退役，不再是安装或操作方法。

页面不以默认草稿冒充实际值。保存值与运行回读仍分开，未知时显示等待或真实错误；配置读取复用已有维护请求，不新增定时 SSH 或轮询。

## v1.0.155 已保存方向显示

全部关节反馈表增加方向列，覆盖 15 个关节，包括独立嘴巴。值来自本机已保存标定，不取训练模型、几何或默认值：+1 为“正向 +1”，−1 为“反向 −1”；编码器 counts 递增时，分别表示关节角度增加／减少。

`console/static/joint-direction.js` 从现有标定快照按关节 ID 找到唯一项，并核对名称、已标定标志及有效方向；标定通道未就绪、断开／暂停、缺失、重复 ID、名称不匹配或非法值一律显示“—”。兼容旧录制只有逐行标定元数据的形式，但不以该回退覆盖当前快照中的缺失或损坏数据。

这一列只渲染已保存状态，不写标定，不改变已有角度换算、目标、限位或原始反馈。它复用已有遥测与标定元数据，没有新增远端采集、SSH 请求或轮询。首次等待和重连代次由 [R17 连接设计](r17-connection-design.md#initial-feedback-and-reconnection-v10155) 管理；HOME 返回修正见 [robotd](robotd-design.md#r17-显式关闭策略回-homecontrol34)。

| 起坐 | `1c94934c6421ec72ed48079cea749668` | 1.00 | 原起坐运行路径 |

右踢是原始 `Mjlab-BallKick-Flat-MicroDuck` 导出，10000 轮、4096 环境，ONNX SHA256 为 `67ad09d82f4865d222a7ae06f250cf9f77f08c27e4f019ee3f7e431a764419fd`。原始 ONNX、manifest、部署合同和训练元数据逐字保留；训练检查点只留存在原始导出归档中，运行不读取、不反序列化。它复用 `kick_right` 动作槽和原命名技能，0.5 秒、命令 `[0,0,0]`、不连发、无退回阶段。实际倍率仍包含现有电压补偿，不把基础 1 误称为任何电压下输出都为 1。

`requested_action_replacements` 加入右踢 ID。配置生成比较旧安装 profile，首次迁移绑定原件并设置技能基础缩放 1；重复安装相同 profile 保留用户后来保存的有效技能参数。已有前滚翻、捡取的迁移规则继续保留：仅在对应随包模型更换时更新路径及基础缩放，不覆盖全局参数、本机标定和其他动作。

默认按键为 LB=`kick_left`、RB=`kick_right`。左踢槽为 `none`，没有左踢模型，LB 不执行动作。`retire_standalone_recovery` 删除 `stand_test` 技能并保持 Stand 槽为 `none`，仅将旧 LB=`stand_test` 改为左踢、将旧空或缺失 RB 改为右踢；其他用户自定义按键保留。独立老师 `a481d9f211f31d9476ab1a319fe362a2` 不进入本版运行载荷，源码中的旧资产只作回归夹具，既有设备目录无需强制删除。

联合 Walk 自身包含倒地恢复，不额外切换独立老师。模型 catalog 仅列出五个内置模型，移除 `manual_recovery` 及独立起身显示；“已绑定”与原生实际运行回读仍分开。中控右踢按钮复用 `robot.do`，仅在反馈新鲜、运动模式、IMU、HOME、策略与上力实际就绪时提交一次请求，不自动上力、HOME 或启用策略，不在恢复后重放失败请求。

## 联合 Walk 的独立执行配置

唯一 Walk 是 9600 轮联合模型。原始 ONNX、manifest、合同和训练记录保持原件；运行配置单独保存为 `deployment-execution.json`，当前沿用 v153 的基础 1.0、头部 0.5、腿部 0.7。原始导出中的 1／1／1 仍是训练来源。执行配置绑定完整 ONNX SHA256，不能套到其他模型；参数加载、原始动作历史和固定输出算法由 [robotd 控制设计](robotd-design.md#r17-v10154-combined-walk-execution) 统一说明。

管理描述符记录执行配置 SHA。首次迁移只补入对应配置，配置先原子替换、描述符后写；同一请求重复安装不覆盖后续有效选择。全局动作缩放继续保存，不覆盖或再叠乘联合配置。列表只读取小型元数据，不新增 ONNX 哈希、训练 YAML、推理或轮询。v146 历史的 0.9／0.5／0.7 不是本版当前执行值。

## 模型导入退役与完整包安装

v154 移除模型导入按钮、文件上传、API、CLI 及其临时验证流程。正常启动仍验证每份内置模型的合同与兼容性；不绕过加载检查。固件 ZIP 导入与随包固件安装保持。

安装继续使用完整服务包和固定目录，非模型代码与运行库通过原子替换更新；保留本机装配标定、音量、手柄幅度和已有有效设置。有效模型可按既有规则保留，损坏合同仍从完整随包目录恢复，明确退役模型及引用按管理定义迁移。旧手柄桥、padd、网页输入的配置生成与服务启动顺序沿用现有流程。

安装前校验包完整性，随包固件标签只使用校验成功的 `bundle_info().build`；尚未读取或校验失败时清除旧标签并显示未知，不再硬编码 `control.18`。运行身份来自原生回读，不能用包内版本替代。

普通重启只重启 robotd，不重新配对手柄或重写模型。robotd 系统服务 `Restart=no`，保留第一条启动错误；不自动重建配置后重试。有限 UART 启动与只读诊断机制由 [robotd 控制设计](robotd-design.md#r17-uart-启动恢复control32) 说明，SSH 与输入连接由 [R17 连接设计](r17-connection-design.md) 管理。

## 全局参数与保存位置

全局头部滤波、腿部滤波、电压补偿由官方 `robotd-params/src/lib.rs` 的 `PolicyParams` 默认及解析逻辑提供。R17 管理定义和 TOML 模板不拥有这些字段，不提供开关或修改接口。明确无滤波合同按当前模型选择目标直通，联合 Walk 则使用上述执行配置。

| 参数 | 默认来源 | 默认值 | 中控角色 |
| --- | --- | --- | --- |
| 官方动作缩放 | R17 管理定义 | 0.70 | 可调、保存、读取实际回读 |
| 头部滤波 | 官方 `PolicyParams::resolved` | 0.50 | 固定、只显示实际回读 |
| 腿部滤波 | 官方 `PolicyParams::resolved` | 0.70 | 固定、只显示实际回读 |
| 电压补偿 | 官方 `PolicyParams::default` | 开启，参考 7.4 V | 只显示实际开关及补偿倍率 |
| 嘴巴最大开度 | R17 `defaults.pad` | 100% | 保存到 `/etc/robot/feetech-ft5/pad-settings.json`，网页及真实手柄共用 |
| 手柄头部幅度 | R17 `defaults.pad` | 2.5 rad | 同上；与策略滤波无关 |
| 音量 | R17 `defaults.audio` | 50% | 原生 ALSA；`alsactl store` 保存系统声卡状态 |

升级读取旧管理定义，清理旧定义拥有但已移除的覆盖字段；原生后来明确保存的有效设置继续按普通配置合并保留。运行与重启副本同时更新，字段省略后由 robotd 解析默认。没有周期修复或额外恢复请求。

音量百分比与 ALSA 换算仅在 `packaging/voice_preferences.py` 实现。原生 `PCM Playback Volume` 与 `Line Playback Switch` 控制响度和静音，robotd 使用 `plughw:aic3104`。一次设置请求后用 `alsactl store aic3104` 保存 `/var/lib/alsa/asound.state`，开机由系统 ALSA 服务在官方声卡初始化后恢复；连接只异步读取当前音量，不设置音量，不阻塞手柄。原声音种子和版本规则保留。

本机硬件标定优先当前装配数据，再读取保存副本。模型中的训练编码器数字只记录来源，不覆盖拆装后的实际零位。

## 历史独立起身与测试参数

v131—153 曾提供舵机测试覆盖；v135—153 曾通过独立 `stand_test` 老师提供 LB 起身。这两条生产入口在 v154 已退役。历史原生起身分支及其回归夹具见 [robotd 的历史说明](robotd-design.md#r17-lb-手动起身v10145)。当时的接口、默认值和模型绑定不再描述本版运行行为。

## v1.0.141 原始位置与固定标定目标

按用户明确要求删除139的读数取模和140的目标圈数偏移。反馈只解码飞特15位符号幅值，position_raw与position_signed_raw都保留原生正负值，position_wire_raw保留报文字节。角度与模型观测直接使用 (native-zero_raw)*direction*2π/4096，不使用取模、最近圈选择或动态零位。中控接受完整原生带符号范围，负数不再显示为无效设备。

上力前仍预置新鲜采样的实际原生位置；之后HOME与策略目标仅通过既有JointCalibration.target_raw按本机零点、方向与限位换算，发送结果不加减4096。标定零点与标定目标仍为0～4095。关节工作台从带符号当前位置线性移动到用户请求的正数目标，中间报文也保留正负号；到位确认比较实际目标，不把差4096的坐标视为同一目标。散件回中也采用相同语义。

原来的HOME姿态、2秒回位、机械限位、转矩确认、P/D/48、速度、电流、41号加速度、串口时序、EEPROM、本机标定、模型和输入流程保持。坐标换算验证覆盖12号从-1回1500、22号从-1670回2276，以及重启/重新上力后目标不变。录制中22号-1670到2276相差3946计数，约346.8°；该明确要求的原始绝对坐标行为不保证最短路径，也不能据本地报文测试声称消除实机绕圈。

## v1.0.142 诊断回读的所有权与刷新

控制循环保持 50Hz。HOME 安全检查仍在原来的推理前时刻读取反馈、IMU 挂载与就绪、扭矩三态确认和关节冻结判断；轻量 FeetechControlStatus 只计算这些字段，避免为一次布尔判断复制完整诊断。冻结条件继续使用同一 joint_holding，不修改超时或连续缺帧阈值。

完整 FeetechDiagnostics 在 safety.apply 之后每轮生成一次，因此包含该轮实际应用后的转矩确认及限位计数；通信统计 observe、bus JSON 与订阅的 limp 标记使用这一轮快照。完整动态 JSON、关节反馈、逐轮通信计数和错误提示仍每 20ms 更新，不做发布降频。订阅复用时中间没有新的 safety 写入，不使用推理前状态代替应用后状态。

HD1910 最近一次寄存器检查结果由共享不可变数组保存，完整诊断仅复制引用。下一次 inspect 成功时整体替换；已有诊断快照保留原数组，新的诊断取得新数组。扭矩、冻结、增益确认、通信状态等可变字段继续实时采样。JSON 中寄存器数组的字段、内容与顺序不变。

模型的 SHA256 字符串、路径和任务身份在模型加载时生成；Controller 在建立时缓存已加载模型身份，active_model 每轮按当前活动策略取引用。热重载先创建带有新身份缓存的控制器，再按原 carry_over 继承运动状态，不复制旧身份缓存；HOME 清除活动策略时保留已加载模型列表。模型权重、张量、推理线程数、频率、动作处理和状态转换不变。

对应验证覆盖虚拟串口的新鲜、丢帧冻结、按时冻结、恢复及扭矩切换，以及寄存器重新检查时的快照隔离；真实 ONNX 验证模型热重载刷新身份并保持活动动作连续。输入服务的断连与设备监听机制由 [r17-connection-design.md](r17-connection-design.md) 管理。

## v1.0.143 诊断 JSON 与订阅快照复用

运动模式仍在 safety.apply 后按 50Hz 构造该轮完整诊断，再生成 native JSON。已经生成的 native Value 直接移动到完整报告的 native 字段，不再通过 json! 把整棵 Value 序列化并复制一次。回读采样时点、动态字段、通信统计及错误提示保持；没有把诊断移出控制线程，也没有停订阅时降低诊断刷新率。

robot.busStatus 的运动模式分支用借用结构编码已有不可变 JSON 缓存；持有的 Arc 保证缓存替换后，当前回复仍可完成序列化。下一次请求取得新缓存。JSON-RPC 结构和 ID 保持，commissioning 的 typed bus_snapshot 仍优先，缺少报告的错误响应也沿用原逻辑。借用只省掉构造 Response::ok 时的额外深复制，不复用旧帧代替新帧。

状态广播持有 Arc<proto::RobotState>，多个订阅者接收同一不可变帧时仅复制引用；每个订阅者按原有频率和字段选择生成通知。队列仍为 256 帧，落后订阅者仍走原来的 lag 处理。存在订阅者时，完整状态和骨架仍在原控制周期内生成；没有订阅者时，原来不构造状态帧的判断保持。中控最高 20Hz 的请求与原有抽样方式保持，控制循环仍为 50Hz。

生产 IPC 测试覆盖运动报告字段与缓存替换、缺报告错误、typed 报告优先级，以及多订阅者共享快照、通知内容和队列界限。遥测 SSH 转发由 [r17-connection-design.md](r17-connection-design.md) 管理。上述代码复用不能代替实机 CPU 或温度测量；v143 发布前的断开中控测试只说明原版本的连接开销。


## v1.0.144 原始快照与按请求报告

本节取代v143的逐轮完整JSON生成。50Hz控制线程仍在原有时刻读取硬件、推理和safety.apply；应用后把固定大小的原生动态诊断与所需状态放入共享最新快照。HOME推理前检查仍使用既有FeetechControlStatus，发布的limp仍取本轮应用后扭矩确认。完整JSON只在robot.busStatus等实际请求时由IPC线程组装，现有JSON结果与commissioning/startup响应保持。

通信统计observe从原来的JSON构造块独立出来：无订阅时仍按真实事务更新累计成功/失败、连续错误与最后失败信息。传输断开不清安全状态、模型状态或故障计数，不影响控制线程继续运行。HD1910寄存器检查、本机标定、加载模型身份保留共享元数据，变化后发送新定义；不按每一帧复制静态大树。

原始流有订阅者时，由独立发送任务把最新typed快照直接编码一次，多个连接共享该编码结果。没有订阅者时发送任务休眠，不编码、不读取低频系统信息。原有官方robot.subscribe仍按订阅规则生成其完整状态与骨架；R17原始流只发送状态数值，显示/导出的骨架在浏览器从同一静态模型派生。控制用的原生FK、模型推理与安全流程保持。

参数、P/D/转矩限制、标定公式、飞特多圈位置、HOME/LB、UART/HAT和全部模型文件没有为降低温度而改动。实现移除了遥测复制/处理链的重复工作，尚不能据此给出实机CPU或温度降幅。传输帧、连接生命周期、网页手柄按需启动与浏览器记录由[r17-connection-design.md](r17-connection-design.md)管理。
