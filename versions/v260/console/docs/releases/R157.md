# R17 v1.0.157：启动流程与输入通道整理

配套原生固件为 `1fa8438-feetech-ft6-control.35`。本次包含原生服务修改，安装中控后还需要通过“系统维护 → 随包固件”升级机器人固件。只替换电脑上的中控不能生效全部修改。安装时支撑机器人，升级保留本机有效标定和设置。

## 主服务四步

| 步骤 | 成功输出 | 等待或失败输出 |
| --- | --- | --- |
| 1. 读取主配置、建立 IPC、启动控制线程 | 主服务与 IPC 已启动 | 主配置解析或 IPC 建立失败记录实际错误；控制线程异常退出时进程退出，交给 systemd 恢复 |
| 2. 初始化总线、校验标定、确认卸力、读取首份有效关节和 IMU 数据 | 硬件初始化成功 | 硬件未就绪时按原有启动等待间隔继续等待，记录当前原因；IPC 仍可查询状态 |
| 3. 加载和检查模型、建立控制器 | 模型与控制器加载成功 | 记录具体模型或合同错误，保留诊断和反馈，禁止不满足条件的运动请求 |
| 4. 完成首个控制周期 | 50 Hz 控制循环已运行 | 首周期未完成不显示运行成功；运行时沿用原有总线、IMU 和运动保护 |

状态通过原生 IPC 的事件订阅发送，中控显示当前四步状态并打印变化日志。后连接的中控先获得当前状态。主配置解析发生在 IPC 建立前，错误通过已有 SSH 日志通道读取。

删除旧 UART 启动前后钩子、配置完成 ACK、按进程生成的 UART 状态文件和额外冷重开方案。飞特协议仍属于主服务的硬件 I/O 层，仍由 robotd 单独持有串口。原始遥测继续使用原有数据，中控浏览器解析；没有增加第二个串口读取者。

## 其他模块与配置

实体手柄桥接、padd、手机蓝牙和声音是独立模块，辅助模块失败报告各自状态，不作为主服务启动前置条件。显式安装流程仍负责必要配置，正常启动不再制作配置副本；修改配置的模块只在内容实际变化时备份旧内容并保存新内容。

停用自动更新及启动时自动恢复旧固件，保留中控手动安装升级。Linux 音量读取和设置沿用已有维护通道，不增加遥测中的音量读取。

## 网页手柄

网页输入通过一个持久 SSH 进程连接 robotd 原生 IPC，不再创建网页虚拟 Xbox 或经过网页 webpad 服务。按键语义沿用实体 padd；实体手柄优先。Zero 端先订阅内核输入设备事件，再读取一次现有设备，之后只在设备事件发生时更新互斥状态，中控接收状态推送，没有定时发现设备或互斥查询。

实体接入、网页关闭、SSH 断开或输入租约超时会撤销网页持续输入，不合成 Select、卸力、关机或策略切换操作。保留原有网页输入心跳和安全超时，它们只在实际使用网页控制时工作。没有新增 50 Hz 串口采集、模型推理或全局监视循环。

## 验证范围

网页输入和相关 Python 回归通过，前端回归通过；ARM 程序完成交叉编译并检查 ELF、依赖和归档校验值。具体记录见源码 `verification/changes157.json`。

原生模拟串口测试此前有四项未通过，全量历史测试中也有针对已删除 UART/webpad 方案的旧断言尚未迁移，不能称为全量测试通过。本版没有连接机器人实机，尚未验证真实手柄热插拔、Windows 原生退出、断电重启、电源冲击、承重 HOME 或温度，也不能据此保证此前偶发启动故障已经全部解决。
