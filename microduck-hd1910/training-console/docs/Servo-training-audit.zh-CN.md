# 飞特舵机、官方配置与联合训练核对

核对日期：2026-10-03。对应中控 R1.5.3，目标运行合同 0.15.1。

这次发现了实质的中控问题，也找到另一套更详细的 HD1910 辨识资料。但没有取得用户本次联合训练的运行记录与两位老师 PT，不能把某个源码问题直接认定为这次左右摇晃的原因。

## 1. 先说当前训练到底来自哪里

当前是「冻结的 Pollen 官方任务 + 陆吾飞特执行器参数 + 本机 820g 机器人适配」，不是完整照搬陆吾机器人，也不是原版 XL330 动力学。

| 内容 | 当前使用情况 |
|---|---|
| 官方任务、奖励、复位、终止、观测、PPO | 沿用 `microduck_rl@8d0db749`；全部 12 个普通脚任务逐项比较 |
| 联合训练 | 官方保护摔倒版 VelStand、行走热启动、行走/起身双教师 BC；中控绑定用户选择的本地老师 |
| 课程时间 | R1.5.2 起按 `4096×24` 样本量换算；2048 环境阈值变为 2 倍，1024 为 4 倍。对齐采样量不保证优化轨迹相同 |
| 保存、日志 | 用户要求的每 1000 轮保存；本地 TensorBoard，后台任务独立存活 |
| 执行器 | 陆吾原始 `1910_m6.json`，P=5，7.4～8.0V，最低7V，指令延迟3～6个5ms物理步 |
| 飞特复位 | 采用 fanhao375 的逐环境目标历史复位修复，基类保留官方摩擦随机化 |
| 机器人 | 官方骨架，15颗23g舵机；头部补3g、剩余补躯干，总质量820g。惯量按既有质量配方缩放，未冒充本机实测完整惯量 |
| 动作 | 训练动作系数1.0；未重新加0.7缩放；运行端应遵循导出合同 |
| 本机标定 | 保留当前导入的关节零点/方向与IMU安装关系；不会因本次资料补全回退 |

实际加载默认配置后，12个任务的静态差异均集中在：执行器、机器人构建（质量配方）、保存间隔。完整机器可读差异在 `data/official-studio-config-diff.json`。这份比较发生在绑定本地老师与课程采样量换算之前，不能当作某个正在运行任务的实时快照。

### 陆吾不只是提供了20个BAM字段

陆吾 XgoDuck 默认还有自身0.8kg几何/惯量、±24°髋俯仰Home、站立/坐姿高度、足底摩擦0.4～1.5、噪声、姿态奖励等适配。它的起身任务使用随机空中下落并冻结2秒再起身，回合8秒。当前本机沿用的是冻结官方骨架的任务，**没有照搬这些几何相关修改**。

该提交没有注册 XgoDuck 专用的新版双教师 VelStand 入口；保留的旧 MicroDuck VelStand 不能等同当前官方保护摔倒版本。不能拿陆吾其他动作的成绩当成本机新版联合训练的基准。

本机BAM文件与陆吾原文件SHA256一致：`ef2d51adfb1cc0831b9b02ca19aa9176fceecdf725148d084378d7d9a64afceb`。

### 新找到的另一条HD1910辨识路线

| 配套项 | 当前陆吾路线 | JoyandAI公开路线（固定提交22916b9d） |
|---|---|---|
| 控制器结构 | STS3215Actuator | 自定义HD1910Actuator |
| 训练选择 | M6 | M5，另有M1～M6供比较 |
| 供电 | 7.4～8.0V；下限7V | 实机/台架稳压5V；训练4.75～5.25V、下限4V |
| 固件P | 5 | 32；作者记录来自其舵机回读 |
| 指令队列 | 15～30ms | 20～35ms |
| 力矩常数 kt | 0.623761 N·m/A | 0.692 N·m/A |
| 等效电阻 R | 4.910192 Ω | 3.75 Ω |
| 参数来源细节 | 已发布辨识结果 | 72条摆锤记录，2种杆长、3种砝码、4种轨迹、3次重复；说明含48条拟合、24条验证 |

这不是「把飞特所有参数乘0.7」。原始P数值跨控制器不可直接比大小，电压与P/D转换必须配套。

该项目自己的 `characterization.json` 明确标出D强度、热降额、多颗一致性等仍待测试；同一提交的配置注释与参数说明还存在验证误差口径更正。因此这里仅增加来源和对照，没有把它切成训练默认值，也没有宣称该路线效果优于陆吾。

## 3. 哪些字段确实用了，哪些没用

| 项目 | 当前计算路径 |
|---|---|
| BAM kt、R、armature及各摩擦项 | 参与模型计算；运行时还包含电压、延迟、增益等配置 |
| BAM `error_gain_ratio` | 与P及控制器误差换算共同影响未饱和PWM响应；不是动作角度缩放 |
| BAM `max_velocity=100` | 内部目标角变化上限，不是实测舵机空载速度，也不是行走速度 |
| BAM `q_offset` | 辨识台架记录；本版bam.mjlab路径不使用，不是机器人zero_raw |
| BAM `command_delay≈0.006s` | 本版训练不消费该字段；实际由3～6个物理步队列产生延迟，不能再加6ms |
| 关节摩擦随机0.9～1.1 | 官方事件直接作用于BAM的速度无关摩擦预算；不是脚底摩擦，也不是把全部动力学乘该值 |
| 足底摩擦 | 官方默认0.7～1.3；与关节摩擦独立 |
| armature随机0.9～1.1、质心/质量惯量/观测噪声等 | 保留各官方任务对应事件，不只使用摩擦随机化 |
| XL330厂家额定、堵转、模式、寄存器与热限制 | 完整列作硬件对照，不逐个仿真全部固件寄存器；不能直接移植到飞特 |
| 硬件D/I寄存器 | 当前陆吾STS3215路径没有完整复刻该硬件PID；BAM `kd_scale` 表示反电动势项倍率，不是硬件D |
| 齿隙、热模型、多颗个体差异 | 本中控普通脚任务未启用独立齿隙关节，也没有本机实测热模型/逐颗辨识参数 |

XL330还存在JSON里没有的模型常量：控制器误差换算、PWM上限、电流限制等。R1.5.3新增构建后的实际读回，其中XL330模型有限流1.75A，当前飞特模型没有同样的电流限制；这不代表实物飞特没有保护。模型毛扭矩上界不是连续额定扭矩。

## 4. 本次修复的三个中控问题

1. **BAM中英标题和单位读错。** 原页面用数组下标访问字典，故中文说明丢失。已改为具名字段并补齐全部20项；不参与当前训练的两项明确标出。
2. **BAM覆盖文件没有真正加载。** R1.5.0～1.5.2修改了公开`json_path`，却没刷新BAM配置对象缓存的解析路径。真实复现：页面kt=0.7，执行器仍加载0.623761。现重建配置对象，实际加载与编译惯量均随编辑变化。仅影响手动覆盖BAM的情况，不能据此认定默认参数训练全错。
3. **读取联合任务配置时误隐藏BC。** 描述路径此前与评估路径一起清空`bc_cfg`，导致台账看不到17项教师参数；训练路径实际仍开启BC。现在描述保留并解释全部17项，评估与导出仍只加载学生。

已训练的旧记录如果命中已知BAM路径缓存版本，回放/续训/教师合同按当时实际加载的原参数处理，并记录说明。原PT和原运行记录不改写。新训练的BAM编辑正常生效。

## 5. 联合训练为什么值得单独查

官方本版的设计是：直立倾斜≤25°时用行走老师作动作锚点，倾斜>35°时由起身老师指导，中间由PPO学习；起身老师输入里的速度命令清零，老师各自保留原观测归一化。

新联合任务由行走老师热启动。官方会把继承的行走课程直接设为最终阶段，只对联合新增的倒地/推扰课程渐进。因此，较早行走检查点即使在简单评估下会走，也未必适应联合开局的完整指令与随机化。

官方源码记录过“起身学会了，行走却被模仿更新破坏”的失败，之后加入行走锚点、降低BC学习率并限制小批次。本机当前调用的是修正后的官方双教师版本。两位老师被选择，不等于已经证明它们在当前动作、观测归一化和当前环境分布下都能工作。

R1.5.3曲线旁直接显示：行走/起身门控采样比例、模仿损失、速度跟踪奖励、晃动惩罚。门控比例不是成功率；倒地帧太少时会跳过起身模仿。

仍需拿本次运行记录核对：实际老师哈希、热启动来源、17项BC实值、各阶段分项奖励、结束原因、课程计时和BAM读回。随后在同一评估条件下比较行走老师与联合早期/当前检查点：直立行走、趴/仰/侧躺起身、推倒后的恢复。训练现场带探索噪声与扰动，不能只用一只鸭子的即时画面判断部署表现。

官方保护项还保留原阈值，例如停转扭矩0.4N·m、速度0.5rad/s等。它们是当前官方奖励定义，不是HD1910实测合格阈值；若确需重调，应在对照评估证实问题后单项改变。

## 6. 平均奖励个位数能不能判断好坏

不能单独判定。中控`Mean reward`来自rsl-rl最近结束回合的累计奖励均值，当前缓冲100个回合；分项`Episode_Reward/*`又除以最大回合时长，不能拿两种统计数值直接相加比较。奖励还受任务定义、回合持续时间、课程阶段、惩罚和机器人动力学影响。它不是百分制，也不是并行环境的奖励总和；从1024改为4096不会直接把平均奖励乘4。

公开数字确实存在，但并没有统一及格分：

- 官方[坐站训练记录](https://github.com/pollen-robotics/microduck_rl/blob/8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec/docs/sitstand_policy.md)记载，课程加难时平均奖励从140降到125、131降到116，然后在阶段内恢复。它是SitStand，不是本机联合任务。
- 官方[联合任务源码记录](https://github.com/pollen-robotics/microduck_rl/blob/8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec/src/mjlab_microduck/tasks/microduck_velstand_env_cfg.py)的发布基准run `6op8a8u8`，特定仿真推倒测试（三个种子）恢复成功率88～95%，恢复时间中位2.7秒；不是“平均奖励88～95”。这里未取得可直接比对的最终mean reward，不能编造一个官方分数。
- 社区[Datawhale的256环境复现](https://github.com/datawhalechina/dive-into-embodied-ai/blob/master/docs/practices/amd/microduck-rl/index.md)公布500轮mean reward 5.3664（峰值5.5925）；它同时报告请求前行0.15m/s时实际仅约0.0052m/s，说明保持直立也可能得到若干奖励。累计1500轮后mean reward升到59.0012（峰值62.2754），最终检查点在同一短时评估下实际前行约0.0454m/s，仍未达到目标；抽样最好的反而是较早的model_750。分数上涨和最后一轮都不等于最佳步态。该实验不是本机飞特联合训练，4秒回放也不是长期实机验收。

对于本次“奖励下降且左右摇晃”，应查速度跟踪、回合提前结束、恢复成功率与老师动作偏差；不能只用“课程变难所以正常”解释掉现象。

## 7. 参数页面与验证范围

现有“机器人与舵机参数 → 执行器”内展示19项训练配置、10项控制模型读回、20项BAM、28项厂家规格、XL330和HD1910各3个电压性能点、XL330厂家壳体重心/惯量，以及XL330当前控制表110项（含间接地址/数据）。厂家旧固件间接地址差异和文档内范围不一致均保留备注。完整字段在`data/servo_references.json`。

ROBOTIS来源：[XL330-M288手册](https://docs.robotis.com/docs/dxl/model_reference/x_series/xl_series/xl330-m288/)、[美国商店](https://robotis.us/products/dynamixel-xl330-m288-t)、[惯量资料](https://www.robotis.com/service/download.php?no=2136)。厂家壳体惯量需要转换坐标系，不能替代BAM的转子附加惯量。未公布或本机未测的值不填成猜测值。

飞特来源：[HD-1910-C001厂家规格书，A/0，2026-09-07，JoyandAI公开存档](https://github.com/JoyandAI/OpenMicroDuck/blob/main/hardware_spec/servo/HD-1910-C001%E4%B8%B2%E5%9E%8B%E8%A7%84%E6%A0%BC%E4%B9%A6-20260907.pdf)。电气性能列出4.8/6/7.4V三组扭矩、空载速度、电流及额定负载；工厂默认模式/保护不是本机当前寄存器回读。规格书质量21±2g，本机仍保留用户实测23g，不自动改总质量820g。

本次修复不改变默认BAM、供电/P值、奖励或固件；没有连接ZERO，也没有停止用户WSL训练。实际执行的验证和未覆盖范围见`Verification.md`。
