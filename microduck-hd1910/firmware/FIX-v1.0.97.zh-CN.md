R17 v1.0.97 / 官方 0.15.1 升级修复与界面更新

本版仍延续 R17 v1.0.95 硬件接口和原中控。未采用另一个窗口的中控代码或舵机通信协议；未修改或刷写 HAT 固件。
实际服务标识：1fa8438-feetech-ft6-control.3；官方基线：0.15.1 / 1fa84386f07884e27866411bc1ba166977bced95。

一、这次升级失败的原因与修复
1. v1.0.96 的 UART 助手标识停留在 control.1，实际服务是 control.2。助手一直等旧版本的 configuring_uart 报告，无法向实际服务确认设置完成，两端在 8 秒后超时。本版共用唯一的安装/UART 版本定义，新增 robotd deployment-info 实际二进制身份查询。安装前要求助手、包清单及实际二进制完全匹配，不匹配时在停止旧服务前拒绝升级。
2. 用户日志仍出现 /opt/microduck-0151 的 custom_policy_guard，检查的走路模型为 0b8f0447…，并非本次 5c019c3d… 联合模型。旧清理只识别 R17 ExecStart，未识别仅添加 ExecStartPre 的其他安装目录。本版清理 robotd 的这类启动/停止钩子，保留用户身份、环境和资源限制，并在 /var/lib/robot/feetech-ft5/r5/retired-startup 留私有原始副本。随后检查 systemd 合并后的实际主命令、启动前、启动后及停止钩子；仍有冲突则明确拒绝启动。
3. UART 设置继续按 R17 的顺序：唯一服务先打开串口，助手设置并读回 FIFO/IRQ，确认后才允许总线采集。未移除握手或放宽安全门槛。安装后进一步核验总线就绪及扭矩 OFF；运动模式还必须核验控制器实际模型全 SHA256 和全局参数。
4. 声音软件音量元数据未创建时，明确沿用现有官方声音设置。这条原日志不是 UART 失败原因，不因缺少 voice-device.json 阻断服务。

三、手柄与中文参数说明
三列同高：普通桌面从 620 增加到 1120 像素；大屏 1180，窄屏堆叠且各 1140。手柄增加外壳纹理、摇杆和按键的明暗层次。参数区及按键说明采用中文；手柄键帽保留实体键名。
• Start：首次回 HOME；再次启用策略；再按关闭策略回 HOME。
• 行走模式：左杆前后走 / 左右侧移；右杆左右转向。松开摇杆仅回中，走路模型继续做零速度保持。
• Y：头部模式 / 再按返回行走。左杆头俯仰与转向，右杆颈俯仰与头侧倾；该模式速度归零。
• B：身体姿态模式 / 再按返回行走。左杆上下调高度，右杆俯仰与侧倾；该模式速度归零。具体可响应范围由训练合同决定。
• 方向键下：原 10000 轮起坐，坐下 / 站起切换。
• LT / RT：官方长叫 / 短叫并控制嘴巴，松开归零。
• Select：短按后松开卸力；按住 2 秒坐下、卸力、关闭 Zero。
• A、X、LB、RB 没有配套独立模型；上/右方向键本机不支持；左方向、L3、R3 和中央键官方未绑定。这些键在网页明确灰显。
• 真实手柄接入会销毁网页虚拟设备，暂停网页动作输入。中文说明和新外观未修改 official padd 或 R7 手柄桥。

参数区区分：
• 全局动作缩放：首次默认 0.9，行走、零速度保持及联合模型起身共用。
• 起坐基础倍率：固定 1.0，但继续应用全局滤波及官方电压补偿。
• 头部低通：首次默认 0.5，即本帧目标 50% + 上帧滤波目标 50%。
• 腿部低通：首次默认 0.7，即本帧目标 70% + 上帧滤波目标 30%。
• α 越小平滑越强；1 为直通。嘴巴由扳机控制。
• 官方电压补偿：显示实际开关、参考电压及补偿系数；当前实际动作倍率 = 对应基础倍率 × 官方电压系数。策略未运行时显示“未推理”，不伪造已生效数值。
• 仍保留模型/缩放同行及重启记忆。相同联合模型的再次升级保留已保存选择；新首次配置采用 0.9 / 0.5 / 0.7。训练合同不再强制将运行滤波改为 1。

四、模型与标定不变
只安装：联合行走起身 18000 轮，SHA256 5c019c3d3d2c490947f21974f394750671b0ec7b7a2d1e36734e82c8a3c9225b；原起坐 10000 轮，SHA256 1c94934c6421ec72ed48079cea74966868a7a59f7d732e0207d0f7bdaeed3c50。
优先保留当前装配标定，再使用本机保存副本；不写入训练时的编码器零位。没有有效标定时保持标定模式、运动禁用。其他模型无官方备用回退。

五、如何重新安装
1. 关闭旧中控，完整解压 Microduck-Console-R17-v1.0.97.zip 到新目录，运行 start.cmd 并连接 Zero。
2. 在“09 固件与电源”选择“随包固件”。首次需要 sudo 时在原“机器人服务模式”卡片中填密码。
3. 支撑机身，保持 Zero 供电，点击“升级所选固件”，看安装日志与实际回读。即使当前 robotd 启动失败，仍可由 SSH 升级恢复。
4. 完成后实际运行版本应为 control.3。确认实时关节与 IMU，再手动回 HOME、使用 Start 启用策略；安装不会自动运动。
无需自己修改 systemd 或重新标定，也无需先安装 v1.0.96。
