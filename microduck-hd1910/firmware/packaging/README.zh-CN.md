# Microduck R17 V167 / control.43 随包固件

当前固件构建为 `1fa8438-feetech-ft6-control.43`，配套中控 `1.0.167` 和官方系统 `0.15.1`。robotd 为本版 ARM64 编译程序，padd 保留配套原版程序；robotctl、mediad、输入桥及安装流程使用配套包内配置。

通过中控“系统维护 → 随包固件”安装。服务需要完成四步启动；执行运动须切到运动模式，完成 HOME 并启用策略。完整按键操作见中控根目录的 `README.zh-CN.md`。

## 标定与舵机参数

随包标定来自用户确认的 `duck-10e4` 装配数据，来源记录为 `robot-calibration-source.json`。15 个关节方向为 −1，ID 30 零位 2526、ID 31 零位 2228、ID 33 零位 1599，并包含 IMU 标定。

安装优先保留有效本机标定和已保存参数；需要恢复装配标定时使用随包配置。运行标定路径为 `/etc/robot/feetech-ft5/hd1910-calibration.toml`，服务配置为同目录的 `robotd.toml`。

舵机 P 按模型合同应用，当前随包合同为 P=5；写入与卸力恢复仅涉及地址 50 的一个字节。显式上力时地址 51 写入单字节 D=0，地址 48 写入小端两字节 1000（E8 03）。卸力恢复本次上力前保存的 P，D 与限值保持；地址 41、52 和 EEPROM 不写入。控制循环为 50 Hz。

## 服务

robotd 使用原生 IPC 控制机器人，padd 接收实体手柄；启动、连接及模型加载不自动请求运动。标定模式用于反馈采集，运动模式加载策略。模型切换完成后，从 HOME 启用策略使用。

mediad 视频会话按需唤醒，最后一个使用者退出后休眠。系统配置停用自动覆盖本包固件的更新及 golden 恢复路径。

## 完整性与验证

`BUILD.json` 声明实际构建版本，`ELF-CHECK.json` 记录原生程序，`install-files.json` 与 `SHA256SUMS` 定义随包文件及哈希。安装执行上传字节数、SHA256 和 AArch64 ELF 校验。

当前范围 235 项 Rust 测试通过，六个动作和四个滑轮模型 ARM64/QEMU 加载与首次推理通过，成品导入及逐文件校验通过。完整测试日志随源码提供；Zero 实机滑轮运动尚未验证。

滑轮运行系数由各模型原始合同解析并随当前网络应用。起身模型原始合同的 slot 与 required_skill_settings 均为空，声明 manual_skill 零命令路由；本包通过既有技能通道为实体 L3 提供 5 秒手动测试窗口，执行前在 padd 核对滑轮模式、运行状态及最新 IMU 倒地判断；不增加自动起身槽。5 秒是本地测试配置，原始训练合同及权重保持原样。训练归档名为 10000，manifest 的实际检查点为 11000，以后者为准。
