# Microduck R17 v1.0.147 — 3D 标定参照修复

## 安装

关闭旧中控，完整解压 `Microduck-Console-R17-v1.0.147.zip`，Windows 运行 `start.cmd`，macOS 运行 `start.command`。页面左下角应显示中控版本 `1.0.147`。

已经使用 R146 / `1fa8438-feetech-ft6-control.29` 固件的机器人，本次只需更新电脑上的中控。此包沿用原固件和模型，不需要为本次 3D 修复再刷固件。连接、标定保存与手柄控制沿用原流程。

## 审核结论

对照固定训练模型 `8d0db74916a4f833d1d9b95d6a1d7f4d13b9d5ec`、R146 运行模型与产品原 Three.js 代码，14 个可动关节的转轴、正负方向和编号映射一致，没有发现多颗关节被反号。检查覆盖全零/HOME两种基姿、15输入槽的0和正负10度，共90组、每组64个视觉零件。34号嘴部在模型中没有独立转轴，不可用这张3D图判断开合方向。

确认的界面问题是：原图依赖已保存标定；无完整反馈时显示HOME，缺少独立的零位/正向示范；目标叠加可显示旧运动目标；IMU过期或未确认时的文字与实际冻结倾斜不一致；原相机“正面”指固定场景方向。

## 本版修改

- 加入“实测、零位0°、HOME站姿、0→+10°、0→−10°”五个显示按钮。参考按钮只改变屏幕模型，不发控制或标定命令。
- 零位为14个可动关节全部0°；正负示范从全零位开始，只改变选中关节，其他关节随父链正常运动。动画1秒完成后停在正/负10°。
- 参考姿态直接使用模型定义，不读取本机direction、zero_raw、反馈角度、IMU或里程计，因此可独立核对标定方向。HOME与零位分别显示，11号HOME为+5°、21号为−5°。
- 标出机器人自身左侧20–24与右侧10–14，标签随机身和观察视角投影；正面/背面/左侧/右侧以机器人当前朝向定位相机。
- 目标线框只在运动模式、目标与实际反馈均有效时显示，标定模式及数据过期时隐藏；独立参考不叠加目标。
- 实测倾斜状态与渲染使用同一个判断，明确提示IMU过期、安装未确认或沿用旧值。
- 固定的34号嘴部缺少标定或反馈时，不再阻塞其余14个关节的显示。真正可动关节缺反馈时，明确标出缺失ID；从未收到有效姿态时显示有明确标签的零位示意。
- 标定表单的方向改为“编码器递增时：关节角度增加(+1)/减少(−1)”，避免把屏幕左右当作正负号。

## 用新视图核对一颗关节

1. 在关节工作台选择舵机。3D上方会显示该关节ID、模型零位与HOME角度。
2. 点“零位0°”，看它的模型零位；点“0→+10°”，看模型的正方向。参考按钮会把相机切回机器人正面。
3. 在标定模式、扭矩OFF时，让实物沿同一物理方向小幅转动，观察工作台的原始counts。counts增加选+1；counts减少选−1。
4. 手动摆到已知物理角度后，在“已知角度”填实际摆出的角度再保存。左右髋侧摆真正摆正时都是0°；如果摆的是HOME姿态，11号+5°、21号−5°。
5. 点“实测”返回反馈图，核对实物动作和画面。参考按钮不会自动填入或保存标定值。

左右始终按鸭子自身。面对鸭子看时，鸭子左侧在屏幕右边。34号嘴部没有可用的3D开合示范，正负示范按钮会禁用；用实物与数值核对。

## 修改方向对已训练模型的影响

修改标定方向不改变ONNX权重，但会改变编码器到模型关节角的换算，以及模型角度到舵机目标的换算。把错误方向修正到与训练模型一致，这项修正本身不需要重训。已经按实物确认正确的32号方向应保留。若改变了训练模型的坐标轴或机械范围，则需要另行核对，不能与单纯修正实机标定混为一谈。
