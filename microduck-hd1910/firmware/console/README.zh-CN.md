# Microduck R17 V167 / control.43 使用说明

当前中控版本为 `1.0.167`，随包机器人固件为 `1fa8438-feetech-ft6-control.43`，配套官方系统为 `0.15.1`。实体手柄使用原生 padd → robotd 通道，可控制行走和滑轮模型；四个滑轮 ONNX 随固件安装。

开源地址：[Microduck-kissqy](https://github.com/kissqy/Microduck-kissqy)。网页顶部和 Windows 启动窗口均提供入口。

## 启动与安装

1. 完整解压 `Microduck-Console-R17-V167.zip`。Windows 运行 `start.cmd`，macOS 运行 `start.command`；Linux 可执行 `python3 console.py --dashboard --feetech --open`。
2. 在网页连接 Zero 的 SSH，核对中控 `1.0.167` 和机器人实际运行 `control.43`。Zero 已安装 `control.43` 时只需更换电脑上的中控目录；首次安装可通过“系统维护 → 随包固件”安装。
3. 等待 robotd 启动 1/4～4/4 全部成功，再确认实时反馈与实体手柄连接。连接成功本身不触发运动。
4. 如服务显示 `commissioning`，点击“切到运动模式”，等待四步启动完成。标定模式不加载运动策略。

## 实体手柄滑轮操作

开始前装好滑轮，松开摇杆并扶稳机器人。首次按 Start 执行 HOME，待回位完成，再长按 ↑ 3 秒切到滑轮模式。等待模型切换完成后再按 Start 启用策略，随后使用摇杆或 A。

| 操作 | 当前行为 |
| --- | --- |
| ↑ 长按 3 秒 | 行走／滑轮模式切换；进入滑轮时 A 默认为蹲下 |
| ← 长按 2 秒 | 滑轮模式下切换 A 的蹲下／原地转动作；要求静止 HOME、无正在执行的动作 |
| A | 执行当前滑轮动作；行走模式下执行地面捡取 |
| 左摇杆前后 | 对称滑行；滑轮模式不使用横向平移 |
| 右摇杆左右 | 调整目标航向，robotd 使用 IMU 当前航向计算模型所需的航向误差 |
| Start | 首次 HOME；之后切换策略启用状态，关闭策略时回到 HOME |

要切换 A 的动作，先松开摇杆、等当前动作结束，按 Start 关闭策略并等机器人回到 HOME，再长按 ← 2 秒。切换完成后按 Start 启用策略，再按 A 执行。请求被拒绝时查看日志中的原因，修正条件后重新操作。

按键须保持满指定时间；每次长按只发出一次切换请求，再次切换需要先松开。滑轮模式及其动作通过实体手柄操作，网页不提供专用滑轮切换按钮。实体手柄连接时网页输入自动禁用。

## 模型显示与执行参数

手柄下方左列为模型与高级参数，右列为中文按键说明。模型状态来自同一次配置读取；起身模型显示实体 L3 手动测试入口及条件，网页 L3 只作提示，不产生输入。

四个滑轮卡片标题统一为“滑轮对称滑 / Swizzle”“滑轮蹲下 / Crouch”“滑轮原地转 / Spin”“滑轮倒地起身 / Stand up”；训练轮数及安装状态显示在标题下方。

| 滑轮模型 | 基础缩放 | 头部滤波 | 腿部滤波 | 当前入口 |
| --- | --- | --- | --- | --- |
| 对称滑行 | 1.0 | 1.0 | 1.0 | 滑轮摇杆 |
| 蹲下 | 0.8 | 0.5 | 0.7 | 滑轮 A，周期 5 秒、结束相位 0.7 |
| 原地转 | 1.0 | 1.0 | 1.0 | 滑轮 A，周期 4 秒、结束相位 0.7 |
| 倒地起身 | 1.0 | 1.0 | 1.0 | 实体 L3：滑轮模式、运动已启用、IMU 倒地；5 秒手动测试 |

robotd 在加载各模型时读取原始合同的 `required_policy_settings`，实际推理按当前网络应用缩放与滤波；动作结束后恢复滑行模型自己的参数。蹲下的部署滤波与原训练未加 EMA 的历史分别保留，训练合同和权重不改写。电压补偿与增益继续读取原有配置。

滑轮起身包的实际检查点为 11000，文件名中的 10000 不作为模型元数据。原始合同声明 `manual_skill`、零命令，未声明 Stand 槽或执行时长。当前通过既有 `[[policy.skill]]` 配置设置 5 秒手动测试窗口，此时间是测试配置，不是训练合同参数。实体 L3（左摇杆按下）执行前读取实际模式及新鲜 IMU；仅滑轮模式、策略已启用、已完成 HOME、无其他动作且 IMU 确认倒地时接受。直立、行走、HOME、卸力或 IMU 过期时拒绝并记录原因。每次按下只请求一次，按住及手柄重连不重发；Start 可取消。窗口结束交回滑行模型。LB 保留左脚踢球，网页 L3 只显示说明。

当前没有独立的 LB 起身测试。行走的保持与恢复由联合 Walk 模型承担。本机已保存的有效自定义按键按现有配置使用。

## 标定与设置

安装保留 Zero 上已存在的有效本机标定和已保存参数。需要恢复随包装配标定时，使用包内用户确认的配置：15 个关节方向为 −1，颈部 ID 30 零位 2526、ID 31 零位 2228、头部 ID 33 零位 1599，IMU 标定随包恢复。

这份随包标定来自用户提供的 `duck-10e4` 装配数据；全新 Zero 的镜像若没有有效本机标定，安装日志中的“恢复装配标定”指使用这份随包数据。更换机器人后，应按该机器实际装配检查标定。

实时反馈中的方向列读取本机已保存标定；无有效数据时显示“—”。高级参数保留动作缩放；模型合同提供舵机 P，其他配置以本机有效设置和当前合同为准。

## 摄像头与连接

mediad 常驻，视频按需唤醒：点击摄像头连接开始采集，最后一个视频使用者退出后休眠，多页面可同时使用。仅启动系统或打开网页不会持续采集视频。

首次连接未收到完整反馈时显示等待状态。真实 SSH、服务或启动错误在日志中给出原因；可使用“导出启动诊断”保存只读诊断。手柄连接修复按页面提示使用 A+HOME 模式并完成配对。

## 退出

关闭浏览器标签后，中控脚本仍可能运行。更换或删除解压目录前，在启动终端按 Ctrl+C 并等待退出。Windows 的地址与 DPAPI 密码保存在 AppData；SSH 共用当前中控的凭据流程。

## 验证范围

robotd／padd 已完成真实 ARM64 编译；当前控制核心、IPC、padd 和滑轮范围共 235 项测试通过。六个动作和四个滑轮 ONNX 由新 ARM64 robotd 在 QEMU 中加载与首次推理通过，成品清单哈希和中控固件导入校验通过。

Zero 实机滑轮运动尚未在本次编译环境中验证。上述结果覆盖明确列出的范围，不代表全工程测试全部通过；原始构建与测试记录保存在 `verification/v163/`。
