## 2. 设计目标与原则

1. **停止永远比启动容易**：停下按钮最大、常驻、红色，且在拇指自然落点（2×2 的左下）；卸力必须长按 1.5 s（长按本身就是确认，不再叠一层弹框）。
2. **一眼看懂机器人现在是什么状态**：`policy`、`limp/fallen`、电量、环频、限幅原因都在顶栏一行内。
3. **不假装**：被 `robotd` 限幅时显示"为什么不走"，而不是让摇杆看起来在动。
4. **单手可完成 90% 操作**：左手摇杆，右手四个动作；不需要在页面间跳转。
5. **离线不失控**：离线只读、不缓存指令、重连必须重新产生输入。
6. **误触代价可控**：主界面没有"关机"，没有"恢复出厂"，没有直接发力矩的入口。

## 3. 信息架构

```text
PWA
├── 主界面（唯一驾驶页）
│   ├── 顶栏：手机式状态图标（连接 Wi-Fi / 策略 / 电量 / 控制环 / 电机温度 / 主控温度 / 告警数）
│   ├── 警示条：手柄服务运行、低电量、限幅原因
│   ├── 摇杆区：浮动摇杆（vx / vyaw），窄屏 2×2 按钮在上方、宽屏按钮在下
│   ├── 动作区：站立 / 接管·交还 / 停下 / 卸力(长按)，窄屏 2×2、宽屏一排四个
│   ├── 底：速度档 / 倾角仪 / 维护入口（只放驾驶相关）
│   └── 弹层：toast
├── 状态详情（点顶栏进入）
│   ├── 连接 / 策略 / 控制环 / 电源 / 温度（电机 + 主控）/ 输入源
│   ├── 顶部告警摘要（有几项、分别是什么）
│   └── 输入源可跳到警告详情；不提供设备级动作
├── 警告详情（从黄/红条“详情 ▸”进入）
│   ├── 左：当前提示为什么出现（输入源 / 限幅 / 电量 / 倒地 / 电机温度 / 主控温度 / 控制环）
│   ├── 左：给出证据与建议（请求 vs 实际、原因、命令、阈值）
│   ├── 右：最近消息列表（时间、级别、标题、摘要；点一条看历史详情）
│   └── 只做解释与轻量动作，不做设备级维护
├── 维护面板（底部抽屉）
│   ├── 重启舵机（二次确认）
│   ├── 输入源状态 + “查看详情”跳警告详情
│   ├── 版本 / 环频 / 温度
│   └── 排障入口（静态文案）
├── 策略条（主界面，警示条下方一排按钮）
│   ├── 收起：一排策略 chip，点一下直接切；放不下横向滑动
│   ├── 展开（▾）：全名 / 槽位 / 状态徽标（在用·未配置），点一项直接切
│   └── 只列 `robot_mode != "roller"` 的包；不做 Hub 搜索/下载
├── 只读态（覆盖层）
└── 离线态（覆盖层 + 重试）
```

**没有的东西**（v1 明确不做）：摄像头页、头部控制、声音、地图、设置页、账号、固件升级、关机、轮滑策略、从 Hub 搜/下策略。

区域尺寸（可用高度 896，加起来刚好一屏）：

| 区块 | 高度 | 说明 |
| --- | --- | --- |
| 顶栏 | 52（折两行时约 88） | 宽 414 放不下一行，第二行放主控温度与告警数 |
| 警示条 | 36 | 无警示时 `display:none`，内容区自动上移 |

| 摇杆区 | 剩余全给（约 560） | 底座居中，直径 248；旋钮 104 |
| 动作区 | 2×84 + 10 gap = 178 | **底部 2×2 满宽**，单个约 190×84 |
| 底栏 | 48 | 速度档 / 倾角气泡 / 维护入口 |

要点：

- **动作按钮在底部，不在右侧**。竖屏宽 414，右侧竖排只能给到 190 宽却要挤掉摇杆的横向空间；改成 2×2 后每个按钮从 220×64 变成 190×84，更方、更好按，且「停下」正好落在拇指自然落点。
- 摇杆区提示文案是「按住拖动 · 松手即停」，**贴在摇杆区顶部居中**，因为左下角是速度读数。摇杆在整块区域内任意位置按下都能接管（不是只在左半屏）。
- 密度分档：可用高度 ≤700（手机浏览器带地址栏）时按钮压到 70、摇杆 176；宽度 ≤380 时再收底栏与摇杆。≤520 的极矮窗口只做兜底，不属于支持范围。

### 5.1.1 宽视口：按钮改一排四个

手机竖屏是主场景，但电脑/平板/横窗口也会打开这个页面。宽度一上去，2×2 会被拉成两条 800 px 的大块，很不协调（真机评审时用户第一眼就指出来了）。所以布局按**宽度**分档，两档之间不连续过渡：

| 可用宽度 | 内容列宽 | 动作按钮 | 单个尺寸 |
| --- | --- | --- | --- |
| ≤ 480（手机竖屏） | 满宽 | **2×2** | 约 190×84 |
| 481 – 619 | 480 居中 | 2×2 | 约 230×84 |
| ≥ 620（电脑 / 平板 / 横窗口） | 720 居中 | **一排四个（1×4）** | 约 166×64，图标 34，主标题 16，副标题保留 |

```text
宽视口（≥620，内容列 720 居中）
┌──────────────────────────────────────────────────────────────┐
│ …                    （顶栏 / 警示条 / 摇杆 同上）            │
├──────────────┬──────────────┬──────────────┬─────────────────┤
│ ▲ 站立       │ ⇅ 交还       │ ■ 停下       │ ⫻ 卸力          │ 64
│   回 HOME    │   行走策略    │   仍站立      │   长按 1.5s     │
├──────────────┴──────────────┴──────────────┴─────────────────┤
│ 速度 [0.1][0.2][0.3] m/s   ◉ 倾角 8.5°              ⚙ 维护  │ 48
└──────────────────────────────────────────────────────────────┘
```

规则：

- 只有**宽度**决定排布，**不看方向、不看高度**。上一版按"窗口够高才套手机壳"来兜底，结果窗口一矮就漏成整屏 2×2，正是这次的问题来源。
- 一排四个时按钮高度压到 64，图标 34，圆角与色条造型不变；「停下」仍是唯一的红色实心图标。
- 页宽上限 720，两侧留背景色，不再让按钮横跨整个显示器。

### 5.2 顶栏：手机式状态栏

| 组 | 图标 | 值 | 状态规则 |
| --- | --- | --- | --- |
| 连接 | Wi-Fi | 无文字 | 绿=驾驶者，蓝=只读，灰=离线 |
| 策略 | 鸭头 | `行走 / 待命 / HOME / 卸力` | walk 绿、home 黄、limp 红、其余灰 |
| 电量 | 电池轮廓 + 填充 | `61%` | <25% 黄；<15% 或 <7.0 V 红（见 §5.4） |
| 控制环 | 脉冲 | `50` + `Hz` | <48 Hz 黄；<45 Hz 红 |
| 电机温度 | 温度计 + `电机` | `30°` | ≥50°C 黄；≥60°C 红 |
| 主控温度 | 芯片 + `主控` | `48°` | ≥70°C 黄；≥85°C 红 |
| 告警数 | `⚠` + 数字 | `1` | 有告警才出现；含红色告警时整体变红 |
| 右侧 | `›` | — | 提示整条可点 |
| 最右 | 全屏图标 | — | 独立按钮，调用 `requestFullscreen()` |

- **整条状态栏是一个按钮**（除全屏），点任意位置打开"状态详情"。
- 两个温度必须分开显示，且带 `电机` / `主控` 小标签：只给两个数字无法一眼区分。
- 告警状态直接落在顶栏：电量、控制环、电机温度、主控温度各自变黄/变红；`⚠ N` 汇总当前告警数。
- 顶栏不放 IP、电压、missed、版本、`原型` 标签，这些全部进详情页。
- 状态栏高 56，可点区域高 44；图标 + 小标签 + 数字的组合保证"一眼知道是什么"。
- 电池数据缺失时显示 `—`，不显示 0%（`robot.health` 的 battery 可能为 `None`）。
- 顶栏不放菜单/设置，避免驾驶中误触。

### 5.3 警示条规则（最多一条，按优先级）

按优先级从高到低，同一条只显示最高优先级：

| 优先级 | 条件 | 条幅 | 颜色 |
| --- | --- | --- | --- |
| 0 | 离线 / 只读 | 覆盖层，不用条幅 | — |
| 1 | `fallen=true` | 已检测到倒地；仍可站立/卸力 | 红 |
| 2 | 电量进入危险（<15% 或 <7.0 V） | 电量低：`12% · 7.05 V` | 红 |
| 3 | 电机温度危险（≥60°C） | 电机温度偏高：`65°C` | 红 |
| 4 | 主控温度危险（≥85°C） | 主控温度偏高：`92°C` | 红 |
| 5 | `padd` 在运行 | 手柄服务 (padd) 在运行，会覆盖手机指令 | 黄 |
| 6 | `limited_by` | 未执行：指令超时 / 关节限位 / 数值非法 | 黄 |
| 7 | 电量预警（<25% 或 <7.3 V） | 电量偏低：`24% · 7.28 V` | 黄 |
| 8 | 电机温度预警（≥50°C） | 电机温度偏高：`52°C` | 黄 |
| 9 | 主控温度预警（≥70°C） | 主控温度偏高：`74°C` | 黄 |
| 10 | 控制环偏低（<48 Hz） | 控制环频率偏低：`46.8 Hz` | 黄/红 |

**点"详情"打开"警告详情"，只解释当前这条提示；维护面板从底栏"维护"进入，两者不共用页面。**

**`deadman` 的显示规则**：机器人静止时 `robot.state.move.limited_by` 也会常年是 `["deadman"]`，直接显示会变成噪音。页面只在"摇杆有非零请求"或"最近 500 ms 内有过输入"时提示"未执行：指令超时"；松手 500 ms 后自动收起。

### 5.4 告警分级与阈值（UI 层）

数据来自 `robot.health`（1 Hz）：`battery {volts,percent}`、`motors {max_c}`、`cpu_temp_c`、`loop.hz`。阈值是 **UI 提示阈值**，不是固件保护值；实测后可以只改前端常量。

| 指标 | 正常 | 预警（黄） | 危险（红） | 顶栏表现 |
| --- | --- | --- | --- | --- |
| 电量 % | ≥25% | <25% | <15% | 电池图标与百分比变黄/红 |
| 电池电压 | ≥7.3 V | <7.3 V | <7.0 V | 同上；% 与电压任一触发即生效 |
| 电机最高温 | <50°C | ≥50°C | ≥60°C | 温度计 + `电机 30°` 变黄/红 |
| 主控温度 | <70°C | ≥70°C | ≥85°C | 芯片 + `主控 48°` 变黄/红 |
| 控制环 | ≥48 Hz | <48 Hz | <45 Hz | 脉冲 + `50 Hz` 变黄/红 |
| 输入源 / 限位 / 倒地 | 无 | padd、限幅 | 倒地 | 按 §5.3 走条幅，单独计入 `⚠` 总数 |

- 顶栏 `⚠ N` 的 `N` = 当前同时成立的告警项数（电量、电机温度、主控温度、控制环、输入源、限幅、倒地各算一项）。
- 有任意一项为红色，`⚠ N` 整体变红；只有黄色时保持鸭黄。
- 温度、频率、电量在状态详情页用同一套阈值着色，避免"顶栏红了、详情页还是灰的"。
- 告警恢复后颜色立即恢复，但"最近消息"里保留历史记录（§6.6.1）。

## 6. 组件规格

### 6.1 浮动摇杆

- **出现**：在摇杆区（不含顶栏、警示条、动作区和底栏）任意位置 `pointerdown`，底座中心落在按下点；底座直径 248 dp，旋钮 104 dp（小屏压到 176/78、160/70）。
- **映射**：
  - `dy` 向上为正 → `vx = (dy / 80) * speed`，范围 `-0.6..1.0 × speed`（后退限速 60%）。
  - `dx` 向右为正 → `vyaw = -(dx / 80) * yawMax`（右转是负，符合 `robot.move.vyaw` 正=左转）。
  - 总位移先夹到半径 80；`|v| < 0.12` 视为 0（死区）。
  - 输出按 **20 Hz** 节流发送；值变化 < 0.005 时不发，心跳 100 ms 必发一次。
- **视觉**：底座两圈同心圆 + 十字刻度；旋钮黄色，偏移时带 `--duck-soft` 光晕；超出死区时底座描边变黄。
- **松手**：`pointerup / pointercancel / lostpointercapture / blur` 一律归零，并在 16 ms 内发 `drive(0)`；底座淡出 200 ms。
- **反馈**：摇杆下方一行小字显示 `vx +0.18 m/s · vyaw -0.40 rad/s`；被限幅时变黄并追加 `（已限幅）`。
- **禁用**：只读/离线/已卸力时，底座变灰、不响应。

### 6.2 动作按钮（底部 2×2）

| 按钮 | 图标 | 默认态 | 按下 | 禁用条件 | 说明 |

| 站立 | 向上箭头 + 横线 | 冷蓝图标底座/色条/状态灯 | 黄边 + 10 ms 震动 | 离线/只读（卸力后仍可用它恢复） | 发送 `robot.init`；执行中显示"站立中…" 2 s |
| 接管 / 交还 | 双向箭头 | `held` 时中性灰，显示"接管／让策略驱动"；`walk` 时绿色，显示"交还／策略待命" | 同上 | 离线/只读 | `robot.enable {on:true/false}`；副标题刻意不提"策略"，避免和策略条混为一谈 |

### 6.2.2 状态与按钮的关系

- `policy=walk`：交还按钮变绿边、绿图标、绿状态灯，副标签"行走策略"。
- `policy=held/home`：交还按钮回到中性灰，主标签变"接管"。
- `limp`：卸力按钮禁用变灰；站立按钮保持可用（用于恢复）。
- 只读/离线：四个按钮全部 `disabled`，状态灯熄灭，不改变尺寸。

**长按卸力**：
- `pointerdown` 开始 1500 ms 计时，按钮底部出现进度条（0→100%）。
- 进度 <100% 时 `pointerup`：取消，进度回落，短震动一下。
- 100%：震动 40 ms，弹出确认层（见 6.7）；确认后才发 `robot.relax`。
- 长按期间不阻止页面其他区域，但摇杆自动归零。

### 6.3 速度档

- 三段：`0.10 / 0.20 / 0.30 m/s`，默认 **0.20**；yaw 随档位 `0.4 / 0.6 / 0.8 rad/s`。
- 外观：底栏左侧分段控件，选中项黄底黑字；未选中透明。
- 切换立即生效；摇杆正在推时，把当前输出按新上限夹一次并立即发送。
- 记忆到 `localStorage`，下次打开沿用；离线也可切换（只影响本地）。

1. 速度档。
2. 倾角仪：28 dp 圆，内部气泡按 `gravity` 偏移；>25° 变黄，`fallen` 变红。

左栏是当前提示的解释与动作，右栏是最近消息列表；短屏（<760 px）上下堆叠。

| 提示类型 | kicker | 标题 | 证据区 | 动作 |
| --- | --- | --- | --- | --- |
| `padd` 输入源 | 输入源 · 手柄 | 手柄服务正在运行 | 状态、已连接设备、停止命令 | 复制停止命令 / 知道了 |

#### 最近消息列表

- 位置：右栏标题"最近消息" + 条数；列表可滚动，最多保留 10 条（v1 内存态，刷新即清空）。
- 行结构：级别圆点（绿=完成、黄=预警、红=危险）→ `HH:MM` → 标题 + 一行摘要 → `›`。
- 当前这条若还没写进历史，会临时插在列表顶部（`当前`），保证"当前"也能在列表里看到并高亮。
- 点任意一行：左栏切换到该条历史详情，顶部出现 `返回当前`，动作区只保留"知道了"。
- 点 `返回当前`：回到本次打开的告警详情；如果没有当前告警，则只关闭历史视图。
- 历史视图不提供"去站立/复制命令"等上下文动作，避免在旧状态下误操作。
- 新事件来源：站立 / 接管 / 交还 / 停下 / 卸力 / 舵机重启 / 掉线 / 接管请求 / 告警触发。
- 只读和离线不弹告警详情；但事件仍写入列表，重连后能看到刚发生过什么。

规则：
- 打开前先归零（与卸力确认层一致，弹层出现先停）。
- 同一时刻只显示一条当前提示，优先级见 §5.3。
- 只读/离线时不触发（覆盖层优先）。
- 详情里不放"重启舵机/校准/关机"；需要时从底栏"维护"进入。
- 点遮罩、`Escape`、`知道了` 都关闭；关闭后不恢复旧摇杆值。

### 6.7 卸力：长按即生效（无二次确认）

```text
     ┌────────────────────┐
     │  ⫻   卸 力         │   按住 1.5 s，按钮底部一条琥珀进度条
     │      长按 1.5s      │   填满即生效；中途松手则取消
     └────────────────────┘
```

- **只有一次长按**：满 1.5 s 直接发 `robot.relax`，不再弹确认层。长按本身就是防误触；真机上多一次弹框等于要多点一次，急的时候反而更危险。
- 生效后：主界面 `policy=limp`、摇杆禁用、按钮变灰，toast「已卸力 · 机器人会瘫倒」，事件列表记一条 warn。
- 卸力后恢复：点「站立」（`robot.init`）。倒地时站立与卸力都保持可用。
- **「重启舵机」仍保留二次确认** —— 它同样是"点完机器人立刻倒"的动作，且没有长按这一层兜底。

### 6.7.1 危险动作的分级

| 动作 | 防误触 | 理由 |
| --- | --- | --- |
| 停下 | 无 | 越容易越好；代价是停下而已 |
| 卸力 | 长按 1.5 s | 高频但不可逆（要重新站立），长按足够 |
| 重启舵机 | 二次确认 | 低频、会先切力矩、可能丢标定状态 |

### 6.8 Toast

- 位置：**顶部居中，距顶栏 12 dp**。绝不能放底部 —— 竖屏下底栏上方就是「停下」，浮层盖住急停是安全问题。深色面板 + 左侧色条（绿/黄/红）。
- 时长：成功 2 s，警告 3 s，错误 5 s；同时最多 2 条，新的顶掉旧的。
- 不阻塞操作；不用于需要确认的事情。

### 6.9 倾角仪

- 输入：`robot.state.safety.gravity`（trunk 系，直立约 `[0,0,-1]`）。
- 气泡位置：`x = gravity[1] * 12`，`y = -gravity[0] * 12`（限幅 12 dp）。
- 颜色：<15° 绿，15–25° 黄，>25° 或 `fallen` 红。
- 无 IMU 数据时显示空心圆 + `—`。

### 6.11 策略条（主界面一排按钮，点一下直接切）

第一版把策略放在维护抽屉里，用户反馈"藏得太深、不好找不好操作"。改成主界面上一排按钮：**看一眼就知道在跑什么，点一下就跑一次，不用进任何页面。**

#### 位置与两态

在警示条和摇杆之间，独占一条 46 dp：

└────────────────────────────────────────────┘

┌────────────────────────────────────────────┐

- **收起态**就是一排 chip：宽度放不下时**横向滑动**（右侧渐隐提示可滑），不换行、不折行，永远只占一条。
- **当前策略**用鸭黄实心 chip 表示，其余为描边 chip；`未配置`（缺 `policy.onnx`）的 chip 是虚线 + 删除线，不可点。
- **▾ 展开**成浮层（覆盖摇杆，不改变布局高度），每行给全名 + `槽位 · 槽位中文名` + 状态徽标 + 底部一句风险说明。
- 收起：再点 `▾`、点浮层外任意位置、或点过任一 chip 后自动收起。

#### 底层到底怎么切（源码结论）

先说清楚一件事，因为它决定界面对不对：**"切换策略"在 robotd 里是两件不同的事**。

| 层 | 接口 | 行为 | 会不会自己变回去 |
| --- | --- | --- | --- |
| **槽位内容** | `robot.loadPolicy {slot, path}` | 写 `policy.<slot>` 进 `robotd.toml`，换掉这个槽位加载的 `.onnx` | **不会**。持久，重启还在，只有 `policy reset` 撤 |
| **技能执行** | `robot.do {skill}`（手柄 A/X/LB/RB 同理） | 跑一次这个技能，跑完落回行走 | **会**。窗口到期自动回 walk |

技能执行的优先级链（`robotd/src/control.rs` step 里）：

```text
skill  >  ground pick  >  sit / rise  >  stand-by-magnitude  >  walk
```

- 技能有 `duration`：前滚翻 **1.0 s**、左脚踢 / 右脚踢 **0.5 s**、抬头捡取（`ground_pick_period=4.0`）运行窗口 **2.8 s**。
- 到期且没有 chain，`self.active = None` → **下一个 tick 就跑 walk 了**。所以是"执行完就回行走"，不是"停在那"。
- `sit_toggle` 是**锁存**：坐下之后由 `sit/rise` 那一段保持，直到再点一次站起（`Sit::Rising` 完成回 `Sit::Up`）。
- 每个 tick 实际在跑什么，`robot.state.policy` 会直接给：`walk` / `roulade` / `kick_left` / `held` / `limp_fall`。

所以"点一下就执行一次并保留在切换后的策略"这个说法，**只有坐下/站起成立**；前滚翻、踢球、拾取都是跑完自动回行走。界面按后者做，才不会显示一个和机器人实际状态不符的高亮。

**实现用的是第二层（`robot.do`），不是第一层。** 策略条不是"换模型"，是"跑一次"：槽位里装哪个 `.onnx` 由板上部署决定，页面不碰 `robot.loadPolicy`（它写配置且持久，副作用还会让 robotd 重写整份 `robotd.toml`）。

#### 交互：点一次执行一次，跑完回行走

| chip | 发送 | 之后 chip 停在哪 |
| --- | --- | --- |
| 行走 | —（常态，不发指令） | 一直是它 |
| 坐下/站起 | `robot.do {skill:"sit_toggle"}` | **停在这里**（锁存），再点一次站起 |
| 拾取 | `robot.do {skill:"ground_pick"}` | 2.8 s 后自动回「行走」 |
| 左脚踢 / 右脚踢 | `robot.do {skill:"kick_left"/"kick_right"}` | 0.5 s 后自动回「行走」 |
| 前滚翻 | `robot.do {skill:"roulade"}` | 1.0 s 后自动回「行走」 |

- 每个 chip 都能反复点，包括当前那个（重复触发同一次技能）。
- toast 只有一句：**「已切换至XX策略」**；自动回到行走**不弹提示**，靠 chip 高亮自己回去表示。
- 点击瞬间把摇杆请求归零（`drive(0)`）。
- **实现时 chip 高亮直接跟 `robot.state.policy` 走** —— 不用前端计时器。`state.policy == "walk"` 就高亮行走，等于某个技能名就高亮那个，`held` 则整条不高亮。

**只有「行走」时方向盘（摇杆）能驱动运动**：

| `state.policy` | 摇杆 |
| --- | --- |
| `walk` | 可用 |
| 任意技能名（roulade / kick_left / …） | **禁用**，摇杆区压暗 |
| `held` | 禁用（没策略在驱动） |

#### 和「接管／交还」是什么关系

这是两件不同的事，容易混：

| 控件 | 管什么 | 发送 | 状态表现 |
| --- | --- | --- | --- |
| **策略条** | **跑哪个技能**（一次一跑，跑完回行走） | `robot.do {skill}` | chip 高亮跟 `robot.state.policy` 走 |
| **接管／交还** 按钮 | 让不让策略**驱动**机器人（开 / 关） | `robot.enable {on:true/false}` | 顶栏 `行走` / `待命` |

- 交还（`enable off`）之后机器人 `policy=held`，只是**保持姿态**，不跑策略 —— 这时候点技能 chip 不会有效果（`robot.do` 会被固件按"没有策略在驱动"拒掉或立刻落回 held）。
- 接管按钮的副标题是 **「让策略驱动」/「策略待命」**，措辞上不出现"策略"以外的词，避免和策略条混淆。
- 策略条**不锁死**：它只是把「能不能点出效果」交给摇杆门禁去表达（见下）。原因是技能可以反复点，锁上反而让人以为"不能再来一次"。

#### 门禁：只有「行走」时方向盘可用

用户明确要求：**只有行走策略时方向盘才能驱动方向，其他策略都可以反复点、点完即执行一次**。

| `robot.state.policy` | 摇杆 | 动作 chip |
| --- | --- | --- |
| `walk` | **可用** | 可点 |
| 任意技能名（`roulade` / `kick_left` / `ground_pick` / `sit_toggle` …） | **禁用**，摇杆区压暗 | 可点（重复点 = 再来一次） |
| `homing` | 禁用 | 可点 |
| `held`（已交还，策略没在驱动） | 禁用 | **不可点** + toast「先点『接管』让策略驱动」 |
| 卸力（`limp`） | 禁用 | **不可点** |
| 只读（另一台在驾驶）/ 离线 / `robotd` 不可达 | 禁用 | 置灰 |

门禁实现为 `canAct() && !limp && policy !== 'held'`，落在 `app.js` 的 `policyGateOpen()`；
摇杆门禁是更严的 `canDrive()`（额外要求 `policy === 'walk'`）。

这条门禁和**固件自己的语义一致**：非 `walk` 时别的网络正在驱动，此时发 `robot.move` 本来就不会被采纳。
界面只是把"发了也没用"提前说清楚，不是 UI 自己发明的规矩。

#### 只显示双足

`deployment-contract.json.robot_mode == "roller"` 的包一律不进 chip 列表；`robot_mode` 为 `feet` 或缺失才算双足。轮滑那 4 个包还在 `/opt/robot/feetech-ft5-r5/roller/` 里，将来做轮滑版时按 `robot.mode` 分组显示即可。

#### 数据与接口

| 字段 | 来源 |
| --- | --- |
| chip 文案（短名） | 桥侧静态表 `POLICY_SLOTS`，按槽位：`walk` 行走、`sitstand` 坐下/站起、`ground_pick` 拾取、`kick_left` 左脚踢、`kick_right` 右脚踢、`roulade` 前滚翻 |
| 全名 / 轮数 | `models/<id>/model-info.json` 的 `name`（如「前滚翻 10000 轮 · 无缩放滤波」） |
| 槽位、当前 path、错误 | `robot.policies` |
| 执行 | `robot.do {skill}` |

桥侧新增两条消息：

| 消息 | 方向 | 说明 |
| --- | --- | --- |
| `policies` | 页面 → 桥 | 读 `robot.policies` + 扫包元数据，3 s 缓存。**放在角色检查之前**，只读会话也能读，否则第二台设备的策略条永远是空的 |
| `policyDo {skill}` | 页面 → 桥 | 转发 `robot.do`，回 ack（带 `reason`）+ 刷新后的 `policies` |

槽位是否可点由 `robot.policies.slots[].path` 决定：有文件才 `ready`，`kick_right` 缺 `policy.onnx` 就显示为未配置。桥以 `duck`（在 `robot` 组）直连 `/run/robotd.sock`，**不需要 sudo**。

#### 禁用与异常

| 情况 | 表现 |
| --- | --- |
| 离线 / 只读（另一台在驾驶） | 整条置灰不可点，chip 保持上一帧的样子 |
| `robotd` 不可达 | 整条置灰 + toast「robotd 未连接」 |
| 机器人卸力（`limp`） | chip 不可点（`robot.do` 会被固件拒，硬发只会在日志里留一堆错误） |
| 已交还（`policy=held`） | chip 不可点，toast「先点『接管』让策略驱动」 |
| 机器人倒地 | chip 仍可点（`fell` 不影响 `robot.do` 的受理），但拒绝时的 `reason` 原样显示 |
| 槽位没文件（`kick_right`） | chip 虚线 + 删除线，不可点 |

#### 来源与许可

板上这 6 个双足策略是 **kissqy 自训权重**（`Microduck-kissqy/microduck-hd1910/docs/MODEL-PROVENANCE.md` 的发布 ID 与 `models/` 目录逐一对上），官方策略对这套自定义 R17/HD1910 栈用不了 —— 所以 chip 上不出现「官方」字样。**不做 Hub 搜索/下载**；将来自己训练的包放进 `models/<sha256>/`（含 `policy.onnx`、`manifest.json`、`deployment-contract.json`）重启 robotd 后自动出现在这一排。

#### 已知限制

- **接管实测过不去，原因是工装不是代码**：`enable` 要求 14 个关节全在 HOME ±5°（`home_start.rs` 的 `MAX_JOINT_ERROR_DEG = 5.0`，编译期常量，无配置项），而 0 位支架把关节锁在 0°、HOME 有 3 个关节非 0（`left_hip_roll −5°`、`right_hip_pitch +5°`、`right_hip_yaw −5°`），实测 MAX 误差 **9.4°**。要过这一门，必须拿掉支架让机器人自己站，或把支架角度改成 HOME 位姿。
- **`init` 不看倾角**：`init` 是开环斜坡（`HOME_RAMP`），`held` 且倾斜时点它会直接翻倒（实测两次）。正确顺序是 `relax → init → 趁 homing 结束立刻 enable`。**这是页面需要提示用户的地方，目前还没做**（见下条）。
- `robot.loadPolicy` 会让 robotd 整份重写 `/etc/robot/feetech-ft5/robotd.toml`，实测会丢掉没被触碰的槽位 key。当前实现**不再调用它**（策略条走 `robot.do`），所以这一坑暂时绕开了；将来真做"换模型"功能时要复查 7 个 key、缺的补回并备份。
- chip 用的是短名，全名在展开浮层里；这是为了一屏塞下 5–6 个 chip 的取舍。

#### 提出但未实现：接管自动重试

上一轮真机联调暴露的真问题：**人点不到 HOME 那一下**。

`init` 完成后有一段窗口满足 `enable` 的 5 道门（回 HOME 完成、反馈新鲜、IMU 就绪、已上力、关节到位、机身直立），
但窗口很短，手动点「接管」经常落在窗口外或者被人手扶着的姿态破坏掉。

拟的方案（**未实现**）：桥侧收到 `enable` 后以 20 Hz 重发最多 2 秒，直到被接受或被拒绝。

| 要点 | 说明 |
| --- | --- |
| 只在 `enable on` 时重试 | `enable off` 重发没有意义 |
| 上限 2 s | 超过就不是"窗口没对上"，是条件真的不满足，继续重发只会刷日志 |
| 每次重发的 `reason` 要留在最后一帧 | 拒绝原因会随姿态变化（先是"尚未回 HOME"，之后可能是"倾斜超过 10°"），最后一次才是该显示给用户的那句 |
| 抢在 `init` 之后自动触发 | 用户点一次「站立」，桥自己把 `init` + 重试 `enable` 串起来，不用人插手 |

这一条要不要做、以及是否让 `init` 也走同一条自动串（风险是 `init` 在倾斜状态会翻倒，见上），需要评审确认。

## 7. 交互与状态机

### 7.1 页面状态

```text
BOOT
 ├─ 读取 SW 缓存壳
 ├─ 尝试 WS（3 s 超时）
 │   ├─ 失败 → OFFLINE
 │   └─ 成功 → HELLO
 │             ├─ 拒绝/超时 → OFFLINE（显示原因）
 │             ├─ 已有驾驶者 → READONLY
 │             └─ 无驾驶者 → DRIVER
DRIVER ──松手/断线/切后台/锁屏──→ DRIVER（速度 0）
DRIVER ──长按"卸力"──→ RELAX_HOLD ──满 1.5 s──→ LIMP（无二次确认；未满松手回 DRIVER）
DRIVER ──点"站立"──→ STANDING（2 s）──→ DRIVER（policy=held）
DRIVER ──点"接管/交还"──→ DRIVER（policy 切换）
DRIVER ──点"详情"──→ ALERT（先归零，只解释当前提示）
ALERT ──点"最近消息"某条──→ ALERT_HISTORY（左栏换成该条历史，只留"知道了"）
ALERT_HISTORY ──返回当前──→ ALERT
ALERT ──知道了/点遮罩/Esc──→ DRIVER（不恢复旧摇杆值）
ALERT ──"去站立"──→ STANDING（仅 fallen 详情）
DRIVER ──点顶栏──→ STATUS（只读，可点输入源进 ALERT）
STATUS ──×/关闭/遮罩/Esc──→ DRIVER
READONLY ──请求接管──→ DRIVER（原驾驶者收到被接管提示）
OFFLINE ──重试成功──→ HELLO
LIMP ──点"站立"──→ STANDING
```

> `ALERT`、`ALERT_HISTORY`、`STATUS`、`MAINT` 都是覆盖层，不改变底层页面状态；`MAINT` 仅从底栏进入。

### 7.2 状态 × 可用操作

| 状态 | 摇杆 | 站立 | 接管/交还 | 停下 | 卸力 | 维护 |
| --- | --- | --- | --- | --- | --- | --- |
| DRIVER | 可 | 可 | 可 | 可 | 可 | 可 |
| READONLY | 禁 | 禁 | 禁 | 禁 | 禁 | 只读 |
| OFFLINE | 禁 | 禁 | 禁 | 禁 | 禁 | 只读 |
| STANDING | 禁 | 执行中 | 禁 | 禁 | 禁 | 禁 |
| RELAX_HOLD | 自动归零 | 禁 | 禁 | 可取消 | 进行中 | 禁 |
| LIMP | 禁 | 可 | 禁 | 可（无意义） | 禁 | 可 |

### 7.3 五条停止路径（必须全部成立）

| # | 触发 | 前端动作 | 服务端动作 | 预期 |
| --- | --- | --- | --- | --- |
| S1 | 松手 | 立即发 `drive(0)` | 250 ms 看门狗 | ≤250 ms 归零 |
| S2 | 切后台/熄屏 | `visibilitychange=hidden` → `sendBeacon("/stop")` + `drive(0)` | 收到后 `robot.stop` | ≤500 ms 归零 |
| S3 | 关页面 | `pagehide` → `sendBeacon("/stop")` | 同上 | ≤500 ms 归零 |
| S4 | 断 Wi-Fi | 无（页面走离线态） | 250 ms 看门狗 → 归零；500 ms `robotd` deadman | ≤500 ms 归零 |
| S5 | 桥崩溃 | 无 | `robotd` 500 ms deadman | ≤500 ms 归零 |

### 7.4 连接与重连

- 首次连接：输入 6 位配对码 → `hello` → `welcome`。
- 断线：立即进入"重连中"（顶部灰点），指数退避 `1 / 2 / 4 / 8 / 15 s`；页面不弹模态框。
- 重连成功：必须重新 `hello` + `welcome` 才恢复驾驶；**不补发断线前的摇杆值**。
- 连续 5 次失败：显示离线覆盖层 + "重试 / 排障"。
- 配对失败 5 次/分钟：服务端锁定 60 s，页面显示倒计时。

### 7.5 接管

- 第二台设备连上：`busy {who}` → READONLY 覆盖层，摇杆与动作按钮全部禁用，维护只读。
- "请求接管"：服务端给原驾驶者发 `preempt`，原驾驶者立即归零并转只读；新驾驶者 `hello` 重连后成为 DRIVER。
- 原驾驶者页面 toast："已被另一台设备接管"。

## 8. 关键流程时序

### 8.1 站立 → 接管 → 驾驶 → 停下

```text
用户            页面                     桥                        robotd
 │ 点站立        │                        │                          │
 │──────────────>│ cmd init               │                          │
 │               │───────────────────────>│ robot.init (request)     │
 │               │                        │─────────────────────────>│
 │               │                        │<──── {accepted:true} ────│
 │               │<──── ack init ─────────│                          │
 │               │ 按钮"站立中…" 2 s       │                          │
 │ 点接管        │                        │ robot.enable {on:true}   │
 │──────────────>│───────────────────────>│─────────────────────────>│
 │               │<──── ack enable ───────│<──── {accepted:true} ────│
 │ 推摇杆        │ drive 20 Hz            │                          │
 │──────────────>│───────────────────────>│ robot.move (notification)│
 │               │                        │─────────────────────────>│ 50 Hz 策略
 │ 松手          │ drive(0) 立即          │                          │
 │──────────────>│───────────────────────>│ robot.move 0             │
 │               │                        │ + robot.stop             │
 │ 点停下        │ cmd stop               │                          │
 │──────────────>│───────────────────────>│ robot.stop (request)     │
```

### 8.2 卸力

```text
pointerdown 卸力 → 进度 0→100%（1.5 s）
  ├─ 提前松手 → 取消，进度回落
  └─ 满 → 确认层 → 再长按 1.5 s
        └─ 发 cmd relax {confirm:"RELAX"}
              → robot.relax
              → policy=limp, 摇杆禁用
              → toast "已卸力 · 机器人会瘫倒"
```

### 8.3 离线打开

```text
浏览器启动（飞行模式）
  → SW 返回缓存 index.html/app.js/style.css
  → 读 localStorage 上次状态（只读展示，时间戳）
  → WS 3 s 超时 → OFFLINE 覆盖层
  → 点"重试" → 成功后 hello → 恢复
```

## 9. 功能点 → 实现映射

### 9.1 前端 → 桥（WebSocket JSON lines）

| 功能 | 触发 | 消息 | 频率/时机 |
| --- | --- | --- | --- |
| 配对 | 首次输入 6 位码 | `{"t":"hello","token":"......","name":"Mate 40 Pro"}` | 一次 |
| 驾驶 | 摇杆 | `{"t":"drive","vx":0.18,"vyaw":-0.4}` | 20 Hz + 100 ms 心跳 |
| 站立 | 按钮 | `{"t":"cmd","id":1,"name":"init"}` | 一次 |
| 接管/交还 | 按钮 | `{"t":"cmd","id":2,"name":"enable","on":true}` | 一次 |
| 停下 | 按钮/停路径 | `{"t":"cmd","id":3,"name":"stop"}` + `drive(0)` | 一次 |
| 卸力 | 双重长按确认 | `{"t":"cmd","id":4,"name":"relax","confirm":"RELAX"}` | 一次 |
| 重启舵机 | 维护二次确认 | `{"t":"cmd","id":5,"name":"rebootMotors"}` | 一次 |
| 保活 | 定时 | `{"t":"ping"}` | 1 Hz |

> 状态详情、警告详情和维护面板都是**本地 UI**，不新增 WS 消息；维护里的"重启舵机"仍走 `cmd rebootMotors`。

### 9.2 桥 → `robotd`

| WS 消息 | robotd 方法 | 备注 |
| --- | --- | --- |
| `drive` | `robot.move` **notification**（无 `id`） | 桥先夹 `vx∈[-0.25,0.35]`、`vyaw∈[-0.8,0.8]`，再转发 |
| `init` | `robot.init` request | 2 s 斜坡；会倒，需手扶/吊架 |
| `enable` | `robot.enable {on}` request | `accepted:false` 时把 `reason` 原样回给页面 |
| `stop` | `robot.stop` request | 只归零速度，不卸力 |
| `relax` | `robot.relax` request | 低层会切力矩 |
| `rebootMotors` | `robot.rebootMotors {ids:[]}` request | 先切力矩再重启 |
| 状态 | `robot.subscribe {hz:20}` | 桥只取需要的字段，裁成 ~200 B |
| 电量/温度 | `robot.health`（1 Hz） | `battery {volts,percent}`、`motors {max_c,mean_c,hottest}`、`cpu_temp_c`、`loop` |

### 9.3 桥 → 页面状态字段

```jsonc
{"t":"state","ts":1732000000.123,
 "mv":[0.18,0,-0.4],          // requested
 "ap":[0.15,0,-0.32],         // applied
 "lim":["deadman"],           // limited_by
 "pol":"walk","limp":false,"fall":false,
 "hz":49.9,"tilt":8.5,
 "bat":[7.55,61],"temp":30,"cpu":48}
```

页面把 `lim` 映射为中文（§13）；`bat`/`temp` 缺失时显示 `—`，不要显示 0。

## 14. 安全设计（UI 层）

1. 主界面无"关机"、无"恢复默认"、无"改校准"。**物理停止是 HUB 上的总电源开关**；App 不提供关机，避免把文件系统断电写坏。
2. 停下按钮常驻、最大、红色；任何弹层出现时先归零。
3. 卸力双重确认：长按 1.5 s + 确认层再长按 1.5 s。
4. 重启舵机二次点击确认（3 s 窗口）。
5. 摇杆松手/取消/失焦/页面隐藏一律归零。
6. 只读/离线时所有动作按钮 `disabled`，不只是视觉变灰。
7. 重连后不恢复旧摇杆值；必须重新触摸。
8. 速度档上限硬编码在桥与页面两侧，页面被改也超不过桥的夹取。
9. 不把"已发送"当"已执行"；以 `robot.state.move.applied` 为准。

## 15. 可访问性与误触防护

- 所有按钮 `role="button"`、`aria-label`、可见焦点环（键盘评审）。
- 颜色不是唯一信息：状态点配文字，限幅条配图标。
- 字体放大 1.15× 不截断；按钮最小高度 56 dp。
- 摇杆区与底部按钮区之间留 10 dp 空白，避免拇指跨区误触；摇杆松手才归零，手指滑出摇杆区也归零。
- 底部手势条区域不放动作按钮（留 `env(safe-area-inset-bottom)`）。
- 页面级禁用下拉刷新与双击缩放；只做竖屏，不再处理旋转。
- 驾驶中不弹模态框（除卸力确认，且弹前已归零）。

### 18.2 页面 ↔ 桥：最终协议

页面 → 桥：

| 消息 | 说明 |
| --- | --- |
| `{"t":"hello","token":"…","name":"Mate 40 Pro"}` | 首次配对；配对成功后页面记住 token |
| `{"t":"drive","vx":0.15,"vyaw":-0.3}` | 20 Hz + 60 ms 心跳；桥夹到 `vx∈[-0.25,0.35]`、`vyaw∈[-0.8,0.8]` |
| `{"t":"cmd","id":N,"name":"init"}` | 站立（`robot.init`） |
| `{"t":"cmd","id":N,"name":"enable","on":true}` | 接管/交还（`robot.enable`） |
| `{"t":"cmd","id":N,"name":"stop"}` | 停下（`robot.stop`） |
| `{"t":"cmd","id":N,"name":"relax","confirm":"RELAX"}` | 卸力（`robot.relax`） |
| `{"t":"cmd","id":N,"name":"rebootMotors"}` | 重启舵机（`robot.rebootMotors {ids:[]}`） |
| `{"t":"cmd","id":N,"name":"padd","action":"stop"}` | 停掉手柄服务（`sudo -n systemctl stop padd`） |
| `{"t":"takeover"}` | 抢回驾驶权 |
| `{"t":"ping"}` | 1 Hz 心跳，桥 5 s 收不到就判会话死亡 |

桥 → 页面：

| 消息 | 说明 |
| --- | --- |
| `{"t":"hello","ok":true,"role":"driver","clamp":{…},"paddCanStop":true}` | 角色与能力 |
| `{"t":"hello","ok":false,"reason":"need_token"\|"bad_token"\|"locked"}` | 配对失败；`need_token` 表示"还没输过"，不扣次数 |
| `{"t":"state",…}` | 20 Hz，裁剪后 ~300 B（见 §18.3） |
| `{"t":"ack","id":N,"ok":true,"reason":null}` | 指令结果；`reason` 原样转发 robotd 的拒绝原因 |
| `{"t":"session","role":"readonly","reason":"已被另一台设备接管","driver":"iPad"}` | 角色变化 |

### 18.3 `state` 字段（实际）

```jsonc
{"t":"state","ts":1732000000.123,"ok":true,
 "mv":[0.15,0,-0.32],      // robotd 收到的 requested，用于"请求 vs 实际"
 "ap":[0.15,0,-0.32],      // applied
 "lim":["deadman"],"pol":"walk","limp":false,"fall":false,
 "hz":49.9,"missed":12,"tilt":1.1,
 "bat":[7.55,61],"temp":30.5,"cpu":48,
 "padd":false,"paddCanStop":true,"robotd":"0.15.1"}
```

- 原始帧 ≈4 KB（`frames`/`skeleton`/`joints`），桥只留这十几个字段。
- `bat`/`temp`/`cpu` 来自 1 Hz 的 `robot.health`；缺失时是 `null`，页面显示 `—`，**不显示 0**。
- `robotd` 版本不在 `robot.health` 里，桥读 `/opt/robot/daemon/current/BUILD.json` 的 `official_version`。
- 页面本地另有"摇杆意图"：读数与"请求"进度条用本机意图（更跟手），
  告警详情里的"请求 vs 实际"用 `mv`/`ap`（robotd 的真值）。

### 18.4 与设计稿的差异（都是实现时才暴露的）

| 项 | 设计稿 | 实现的改动 | 原因 |
| --- | --- | --- | --- |
| padd 处理 | 只能"复制停止命令" | 能停时主按钮是"停止手柄服务"（`sudo -n systemctl stop padd`），不能停才退回复制 | 手机上没有终端，复制出来也没处粘；停 padd 比驾驶本身更无害 |
| 首次连接 | 直接输配对码 | 页面先发空 token，桥回 `need_token`，**不占 5 次机会** | 第一次打开就显示"配对码不对，还可尝试 4 次"是恐吓 |
| Service Worker | 静态资源 `stale-while-revalidate` | 全部改**网络优先 + 缓存兜底** | 局域网里网络永远比缓存新；SWR 会让刚部署的页面第一次加载还是旧 JS |
| 预览缓存 | `cache.addAll` | 逐文件 `cache.add` | `addAll` 是全有全无，一个文件失败整份壳为空，症状是"离线打不开"且没有日志 |
| 主界面骨架 | 四行 grid | `flex column` + `#main{flex:1}` | 警示条 `display:none` 时不再占格，grid 会把 `1fr` 让给后面的底栏，界面缩成一条 |
| 告警 chip | 仅红色告警才出现 | 任何告警都出现，红色告警时变红 | 黄条已经在说"有事"，chip 显示"几件"更一致 |

### 18.5 停止路径（与安全设计一致，均为实现态）

### 18.6 第二轮：只做竖屏（真机手感反馈后的定稿）

真机通关第一轮后按用户意见改了四处，**横屏从设计稿到代码全部删除**：

| 设计稿原文 | 实现态 | 为什么 |
| --- | --- | --- |
| §5.1 横屏线框 900×430 基准 | **只做竖屏**：摇杆在上、按钮 2×2 在下、速度/倾角/维护在底栏；顶栏折两行 | 横屏要拧着拿。竖屏下单按钮从 220×64 变成 190×84，更好按，「停下」正好在拇指落点 |
| §5.1 `请横屏使用` 覆盖层 | 删除 | 竖屏是唯一布局，不需要拦截 |
| §7 卸力：长按 1.5 s → 弹框二次确认 | 长按 1.5 s **直接卸力**，只出 toast + 事件条 | 长按本身就是防误触；再弹一次框真机上一急反而更危险。「重启舵机」仍保留二次确认 |
| §8 配对码层（首次输入 6 位码） | 整层删除，服务端默认不校验 | 局域网内临时用，配对码从哪来本身就是问题；正式发版前重新设计鉴权（要恢复加 `--auth`） |

跟着改的细节：

- 摇杆提示「按住左半屏拖动」→「按住拖动」，竖屏时移到摇杆区顶部居中（左下角是速度读数）。
- 摇杆底座 200 → 248、旋钮 88 → 104（896 高度下空间够，别让盘面淹掉）。
- **Toast 从底部移到顶部**：竖屏下底栏上方就是「停下」，浮层盖住急停是安全问题。
- 维护抽屉的行：宽度 ≤460 时数值/按钮落到下一行右对齐，否则「关闭」会插在两行说明中间。
- `manifest.webmanifest` 的 `orientation` 改为 `portrait`（旧值 `landscape`）；全屏不再 `orientation.lock`。
- 宽视口（≥620）内容收成 520 单列，桌面评审时不把按钮拉成长条。

三种视口（414×896 / 360×640 / 900×430 桌面横条）都截图核对过，见部署文档 §9.4、§10。

### 18.7 还没验证的部分

- 真机联调已在 2026-11-19 做过（站立/接管/摇杆/卸力/五条停止路径/看门狗/只读/离线恢复），结果表见 [duckphone-deployment.zh-CN.md](../robot/duckphone-deployment.zh-CN.md) §9.1；**未做**的是「重启舵机」和连续 30 min 浸泡。

## 20. v2：空闲声音 + 头部动作

> 2026-11-26 · 已确认：I1 抬头，I2 左右看；后续再升级随机动作库。

### 20.1 用户看到什么

空闲触发时，声音与头部动作同时开始，头部读数/画面会跟着动，然后回到中位：

| 触发 | 声音 | 动作 | 时长 |
| --- | --- | --- | --- |
| I1 第一次空闲 | `coo` | 抬头看一眼（pitch -0.30） | 1.2 s |
| I2 之后空闲 | `inquire` | 抬头 + 左右看（pitch -0.18，yaw ±0.30） | 1.6 s |

- 不新增按钮，不新增设置入口；只在设置抽屉里放一个「空闲头部动作」开关。
- 动作期间摇杆/头部输入、接管、关闭动态声音、P0 告警都会立刻取消动作，用户输入优先。
- 动作结束回中；之后正常头部控制不受影响。
- 只在有驾驶者、在线、非只读、非 limp/fallen、倾斜 <30°、policy 为 walk/held 时执行。
- 摇杆/键盘头部幅度同时从 ±0.5 rad 提升到 ±0.8 rad，动作更明显；robotd 仍按关节限位处理。

### 20.2 原型

`design/prototype.html` 是静态假数据，不模拟真机头部动作；评审看 §20.1 的时序即可。
真机验收时看头部读数从 0 → 抬头/左右 → 0，并确认摇杆一碰就停。

### 20.3 后续升级

随机动作库：抬头、左看、右看、点头、歪头等，每个动作带时长/幅度；
规则层只传 I1/I2，动作层随机挑一个。v2 不做，等这一版验收后再加。
