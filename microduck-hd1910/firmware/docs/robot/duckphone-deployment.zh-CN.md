## 1. 它是什么

手机浏览器打开 `http://<板子IP>:8001/`，就能：站立、接管/交还、摇杆驾驶、停下、长按卸力、重启舵机，看电量/双温度/控制环/告警。

竖屏、横屏都支持，竖屏是默认使用姿势（单手拇指够得到摇杆和四个按钮）。

板子上只多一个 Python 进程（标准库），页面是离线可打开的 PWA。**不改 robotd 配置，不动机器人源码。**

```text
手机浏览器 ──HTTP/WS :8001──> duckphone ──unix socket──> robotd ──UART──> 舵机
```

## 2. 安装

### 2.1 从电脑推上去

```bash
cd microduck-hd1910/firmware/duckphone
./install.sh duck@192.168.110.240
```

脚本做四件事：同步到 `/opt/duckphone`、装 `duckphone.service`、`enable` + `restart`、打印访问地址。

### 2.2 直接拷到板子上

```bash
scp -r microduck-hd1910/firmware/duckphone duck@192.168.110.240:/tmp/
ssh duck@192.168.110.240
cd /tmp/duckphone && ./install.sh        # 不带参数 = 本机安装
```

### 2.3 手动跑（不装服务，排障用）

```bash
cd /opt/duckphone
python3 server.py --static ./static -v
```

看到这段就说明好了：

```text
duckphone 已启动：http://192.168.110.240:8001/
```

## 3. 第一次使用

1. 手机连**同一个 Wi-Fi**（路由器不能开 AP 隔离）。
2. 浏览器打开 `http://192.168.110.240:8001/`。
3. 直接就能用 —— 局域网内默认**不需要配对码**（见 §9.4 第 3 条）。
4. 竖屏即用；横屏也可以，两种方向都会自动重排。点右上角全屏可去掉浏览器地址栏。
5. 点「站立」→ 等 2 秒 → 点「接管」→ 摇杆可用。

> **姿态前提**：站立前请扶住机器人或挂吊架。`robot.init` 会真的给关节上力并回 HOME。

| # | 检查 | 怎么做 | 期望 |

| 6 | 姿态 | 底栏倾角 | 站立后接近 0° |

## 5. 操作与语义

| 按钮 | robotd 调用 | 语义 |
| --- | --- | --- |
| 站立 | `robot.init` | 给关节上力，2 秒斜坡回 HOME。**会动** |
| 接管 / 交还 | `robot.enable {on}` | 接管 = 让策略开始走；交还 = 回 HOME 待命 |
| 摇杆 | `robot.move`（20 Hz） | 松手立即归零；桥夹到 `vx∈[-0.25,0.35]`、`vyaw∈[-0.8,0.8]` |
| 停下 | `robot.stop` | 只归零速度，**不卸力**，机器人仍站着 |
| 卸力（长按 1.5 s ×2） | `robot.relax` | 切断力矩，**会瘫倒** |
| 重启舵机（维护，点两次） | `robot.rebootMotors {ids:[]}` | 先切力矩再重启，用于过载锁死 |
| 停止手柄服务（告警详情） | `sudo -n systemctl stop padd` | 停掉之后手柄不能再用，直到手动 start |

摇杆方向：向上 = 前进，向下 = 后退（限速 60%），左右 = 转向。

## 7. 排障速查

| 症状 | 先看 | 处理 |
| --- | --- | --- |
| 页面打不开 | `systemctl status duckphone` | `journalctl -u duckphone -n 50` |
| 页面能开但一直转 | `curl <IP>:8001/healthz` | 返回 `robotd-unreachable` → 查 `robotd` |
| 提示"需要配对码"（只有开了 `--auth` 才会出现） | `/etc/duckphone/token` | 5 次错锁 60 s，等倒计时 |
| 连上但不动 | 顶部黄条 | 停掉 padd；确认已「接管」 |
| 摇杆动一下又停 | 「未执行」详情 | `deadman` = 指令超时，检查 Wi-Fi 抖动 |
| 状态全 `—` | 状态详情「输入源」 | `robot.health` 失败时不显示 0，属正常降级 |
| 机器人自己走 | 立刻按物理电源 / 「停下」 | 检查是否有第二台设备接管（只读页会显示） |

## 8. 回滚

```bash
sudo systemctl disable --now duckphone
```

机器人行为完全回到装之前（`robotd`、`padd`、校准都没被改动）。
`/opt/duckphone` 和 `/etc/duckphone/token` 可以直接删。

### 9.3 现场环境问题（与代码无关）

- `robotd` 原以 `--commissioning` 启动，且标定文件 `motion_enabled = false`（最后一次标定撤掉了运动授权）。用 `/opt/robot/feetech-ft5-r5/calibration-config.py enable` 恢复；原 drop-in 备份为 `zzz-r17-0151.conf.bak-commissioning-*`。
- ~~`padd` 每次开机都会自己回来，测试驾驶前需再停一次。~~
  **2026-11-26 已修正**：手柄不可用，`padd` 与 `gamesir-xboxd` 已 `systemctl disable --now`，
  不再开机自启（`is-active/inactive`、`is-enabled/disabled`），duckphone 状态里 `padd=false`。
  需要恢复时执行 `sudo systemctl enable --now gamesir-xboxd padd`。
- 主控温度开机即 79–82°C（阈值 70/85），散热值得单独排查。
- 板子无 RTC：开机后时间会跳变（18:xx → 次日 08:xx），日志时间戳不连续。
- 吊架让机身前后倾 12–16°，超过 walk 策略的 10° 直立门。**有效做法：点「站立」回到 HOME，在斜坡刚结束时立刻点「接管」**（此时倾角 4.9°）；进入 walk 后策略会把机身稳回 4–6°，之后不再被门拒绝。
- 板子在 08:41、08:43 连续重启两次（`journalctl --list-boots` 里 11-18 也有多次 3 秒的短 boot）。电压 78%/7.86 V、总线无错，重启原因未确认，**继续走之前需要先排除供电**。
- 一次 Wi-Fi 抖动：往返延迟 3 ms → 40 ms，随后板子失联约 10 s。桥看门狗和 `robotd` deadman 都在，机器人不会因此持续输出速度。
- **电池卡扣在摔倒时会脱落**（今天两次）。每次脱落都等于断电重启，板子回来要 20 s、`robotd` 要重新加载策略。**继续做地面测试前必须先解决电池固定问题**，否则每次失败都以重启收场，拿不到连续数据。
- 走姿本身不稳：`held` 会稳定停在约 12.5° 前倾；进入 `walk` 后短暂稳住（3–6°），但一旦前倾累积到 30–40° 就会摔倒。这与项目计划 §0 的结论一致（走姿不稳是独立问题，手机遥控不负责修复它）。

### 9.4 按真机手感的第二轮改造

用户手动跑过一遍后提的 4 条，逐条落地：

| # | 意见 | 改法 |
| --- | --- | --- |
| 1 | 强制横屏不方便，竖屏布局也要能用 | `#app` 改 flex 纵向，顶栏允许折行不再裁切；竖屏布局：摇杆在上（占满剩余高度）、四个动作按钮 2×2 在下、速度/倾角/维护收进底部。摇杆提示移到顶部居中，不再压住左下角的速度读数 |
| 2 | 卸力太啰嗦，长按后还弹框 | 删掉二次确认层，长按 1.5 s 直接发 `relax`，结果只用 toast + 事件列表。**「重启舵机」保留二次确认**（它同样会让机器人立刻倒） |
| 3 | 配对码界面先去掉 | 删掉 `#pair` 层与相关逻辑；服务端默认**不开鉴权**（要开加 `--auth`，此时仍支持 `?token=xxxxxx` 免输入）。正式发版前要重新设计配对来源 |
| 4 | 这个服务是独立进程还是塞进现有进程 | **独立进程**：`/etc/systemd/system/duckphone.service`，`User=duck`、`WantedBy=multi-user.target`、已 `enable`。实测 PID 1021，与 `robotd`（992）互不隶属，PPID 都是 1。桥只通过 `ws://127.0.0.1:8111` 说 JSON-RPC，不链接 `robotd` 代码，任何一方重启都不影响对方 |

### 9.5 第三轮：横屏彻底下线（竖屏定稿）

用户要求「原来的更新掉，横屏的都不要了」，所以这一轮把横屏从设计稿到代码一起删干净，原型也重做了一版：

| 项 | 改动 |
| --- | --- |
| `manifest.webmanifest` | `orientation` 由 `any` 改为 **`portrait`**，安装后系统不会再把页面转成横屏 |
| `static/style.css` | 删掉 `@media (orientation:landscape)` 两条和整套「横屏两列」基线；竖屏布局变成**唯一**布局（不再是媒体查询里的特例）。`screen.orientation.lock('landscape')` 一并去掉。密度分档改为按高度 700/520 与宽度 380 分，不再看方向 |
| 摇杆 | 底座 200→248、旋钮 88→104（896 高度下空间够）；`#stickBase` 的复位坐标从 `38%/52%` 改 `50%/50%` |
| Toast | **从底部移到顶部**：竖屏下底栏上方就是「停下」，浮层盖住急停是安全问题 |
| 维护抽屉 | 宽度 ≤460 时行内换行，数值/按钮落到下一行右对齐。原来「关闭」会插在两行说明中间，留下一个孤零零的「跑。」 |
| 宽视口 | ≥620 宽时内容收成 520 单列并居中，避免桌面评审时按钮被拉成长条；≤520 高再收一档兜底 |
| 原型 | `design/prototype.html` 重做成竖屏（删「请横屏使用」遮罩、卸力弹框、横屏密度块），宽屏自动套 414×896 手机壳，右侧加一排「原型状态直达」按钮；`install.sh` 会把它拷到板上，手机上直接访问 `/design/prototype.html` 评审 |

### 9.6 策略通道调查（策略条实现前的摸底）

摸 `robotd` 的 RPC 时得到的结论，写在这里免得下次再挖一遍：

| 项 | 结论 |
| --- | --- |
| 列策略 | `robot.policies`（unix socket `/run/robotd.sock`）→ `{mode, homed, sitting, skills[], slots:[{slot,path,origin,overridden,error}]}`；与 `robotctl policy list --json` 一致 |
| 切策略 | `robot.loadPolicy {slot, path}`，`path:"none"` 关掉该槽位；失败返回 `{accepted:false, reason}`（会指出缺文件/形状不符） |
| 权限 | 桥以 `duck` 跑、在 `robot` 组，socket `root:robot 660` → **不需要 sudo** |
| 模式 | `robot.mode` → `walk`；`robot.setMode` 的合法值是 `walk|roller|roller_crouch|roller_spin`（从报错信息里得到） |
| 双足/轮滑 | 每个包 `deployment-contract.json.robot_mode` = `feet` / `roller`；板上 6 个双足包中 `sitstand` 未写该字段 |
| 板上策略来源 | 6 个双足包都是 **kissqy 自训权重**，ID 与 `microduck-hd1910/docs/MODEL-PROVENANCE.md` 逐一对上；官方策略对这套自定义栈用不了 |

**已知问题（本次实测发现）**：调 `robot.loadPolicy` 会让 robotd 把内存参数**整份重写**回 `/etc/robot/feetech-ft5/robotd.toml`，实测把没被触碰的 6 个槽位 key 全丢了（1879 → 1391 字节，`robotd.previous.toml` 同版本一并被覆盖）。

- 影响：**运行态不变**，且丢掉的 6 个 key 与内置 profile（`management_profile.PROFILE['builtin_models']`）指向同一批文件，所以重启后行为也一致 —— 属于"文件不忠实"而不是功能故障。
- 待办：实现策略切换时，切换成功后复查 7 个槽位 key 是否齐、缺的用 `sudo` 补回并备份（`duck` 有全量 `NOPASSWD sudo`）。

#### 没通过的部分：接管

| 观察 | 结论 |
| --- | --- |
| 点「接管」被拒 | `MAX_JOINT_ERROR_DEG = 5.0`（`home_start.rs` 编译期常量）要求 14 个关节全在 HOME ±5°，实测 **MAX 9.4°** |
| 为什么会差 9.4° | **0 位支架锁住的姿态和 HOME 位姿不是同一个**。HOME 里有 3 个关节非 0：`left_hip_roll −5°`、`right_hip_pitch +5°`、`right_hip_yaw −5°`；支架把它们按在 0°，于是 `left_hip_roll` 差 +9.4°、`right_hip_pitch` 差 −6.5° |

这是**工装问题，不是代码问题**。固件这一门没有任何配置项，容差写死在 `home_start.rs`。
要继续做接管测试，必须拿掉 0 位支架让机器人自己站着，或者把支架角度按上表改成 HOME 位姿。

#### 摔了两次：`init` 在 `held` 倾斜状态下会翻倒

这一轮最贵的教训。`init` 的处理分支是：

- `Bringup::Limp` → `set_torque(true)` + `Homing{from: 当前姿态}`
- `Bringup::Ready` → `reset_for_home()` + `Homing{from: 当前姿态}`

**两条都是开环斜坡（`HOME_RAMP`）**，从当前姿态硬走到 HOME，不看倾角、不看关节是否被外力按住。
所以在 `held` 且机身倾斜时点 `init`，它照走不误 —— 实测两次翻倒（61°、78°）。

正确顺序：

```
relax  →  init  →  趁 homing 结束那一下立刻 enable
```

`enable` 才有那 5 道拒绝门（回 HOME 完成、反馈新鲜、IMU 就绪、已上力、关节到位、机身直立），
`init` 一道都没有。

#### `padd` failed：断电把舵机总线拉坏了

| --- | --- | --- |
| `padd` 起不来，`status=78/CONFIG` | 之前电池卡扣脱落导致多次断电，`padd` 启动体检第 3 步（舵机总线）超时，`systemd` 把它标成 failed 并且不再重试 | `sudo systemctl reset-failed padd && sudo systemctl start padd` |

当前实测丢帧 **0%**。看这个数要看增量，不要看绝对值。
